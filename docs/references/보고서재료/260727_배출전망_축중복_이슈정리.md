# 이슈 정리 — 배출전망(05)의 "BAU가 두 벌" 문제 (2026-07-27)

> 표본 대사(사람 원문 검증) 중 발견한 구조적 문제의 기록.
> 보고서·발표 자료에 쓸 수 있게 쉬운 말로 정리한다.

## 한 줄 요약

지자체 문서에는 "2030년 배출 전망(BAU)"이 **여러 벌** 실리는데(옛 계획의
전망, 현행 계획의 전망, 집계 범위가 다른 전망), 우리 05 시트에는 이걸
구분하는 칸이 없어서 **서로 다른 진짜 값들이 같은 자리를 두고 충돌**한다.
이것은 추출 오류가 아니라 **시트 설계(계약)의 문제**다.

## 실제 예시 — 경기도 "농축산 부문 2030년 BAU"

표본 검증에서 두 백엔드가 이렇게 서로 다른 값을 냈다:

| | 값 | 알고 보니 |
|---|---|---|
| 백엔드 A (flash-lite) | 91.4 천톤 | 오답 — 표의 옆 칸(감축잠재량)을 잘못 집음 |
| 백엔드 B (luna) | 3,235,952 톤 (≈3,236 천톤) | **정답** — p.94 [표 2-32] 관리권한 전망(VKT 기준)의 실제 값 |
| 그런데 원문 p.99에는 | 1,156.8 천톤 | **이것도 정답** — 단, "기존 계획"이 썼던 BAU (제3장 회고 자료) |

즉 같은 "농축산 2030 BAU"라는 질문에 원문이 **1,156.8과 3,236 두 개의
답**을 갖고 있다. 2,800배 차이가 나는 두 값이 모두 원문에 실재하는
정답이다 — 다른 계획(기존/현행), 다른 집계 축(지역전체/관리권한)의
값이기 때문이다.

어느 쪽이 "현행 계획의 공식 BAU"인지는 검산으로 확인된다:

```
p.94 전망(2030 합계)        83,243 천톤
− p.134 목표배출량(2030)     46,581 천톤
= 36,662 천톤  ← p.134 [표 4-4] 목표감축량과 정확히 일치
```

현행 계획은 p.94의 전망을 기준선으로 놓고 감축목표를 계산하고 있다.
따라서 **현행 계획의 공식 BAU = p.94 관리권한 전망**이고, p.99는 옛
계획을 소개하는 회고 자료다.

## 가이드라인은 뭐라고 하나

환경부 가이드라인(`carbon_guideline.md`)의 답은 명확하다:

1. **추출 대상**: 요구사항 표 D행 — 배출 전망은 "**관리권한 인벤토리
   대상** BAU/배출전망, 전망방법론"이라고 정의한다. 즉 05 시트가 담아야
   할 본류는 **관리권한 축의 전망**(위 예시의 p.94)이다.
2. **감축목표도 같은 축**: §2.2 — "기본계획의 감축목표는 지역 전체
   인벤토리를 그대로 쓰는 것이 아니라 … **관리권한 인벤토리**를
   기준으로 설정한다." 전망과 목표가 같은 축에서 이어지는 구조다.
3. **시나리오는 3가지**: §2.5 — 아무 조치가 없을 때의 전망이 BAU이고,
   경로는 ①조치 없음(BAU) ②조치 ③추가조치 셋으로 표준화한다.
   (파이프라인의 시나리오 코드 BAU/정책반영/추가조치가 이것이다.)

**그런데 가이드라인의 05 컬럼 목록에는 축을 구분하는 칸이 없다**
(시나리오·전망방법·부문·세부부문·연도·값·단위·가정뿐). 가이드라인은
"관리권한 축 하나만 있다"고 전제하고 시트를 설계했기 때문이다. 비교:
06_감축목표에는 `목표범위`(관리권한/지역전체) 칸이 있어서 같은 문제를
구분할 수 있는데, 05에는 그에 해당하는 칸이 없다.

## 그래서 무슨 일이 생기나

실제 지자체 문서(경기 실측)에는 전망이 최소 세 벌 실린다:

1. 기존 계획의 BAU (제3장 회고 — p.99 [표 3-2])
2. 현행 계획의 관리권한 전망 (p.94 [표 2-32], VKT 기준) ← 가이드라인의 본류
3. 지역전체 총배출량 전망 (별도 절)

파이프라인은 "원문에 있는 것을 빠뜨리지 않는다"는 원칙대로 셋 다
추출한다. 그러면 축 구분 칸이 없으므로 **셋이 같은 키(부문·연도·
시나리오)로 잡혀서 충돌**한다 — 채점·교차검증에서 "값불일치"로 보이지만
실제로는 둘 다 원문값인 경우가 생긴다.

## 지금은 어떻게 다루고 있나

- **표본 검증 판정 규칙**: 각 값을 그 값이 적어낸 출처페이지로 추적해
  "원문의 어떤 표와 일치하는가"만 판정한다. 다른 축의 원문값을 정확히
  읽었으면 오답이 아니라 정답(비고에 축 명시)으로 기록한다.
- **시나리오 표기 통일**: "BAU 대비 31.2% 감축" 같은 자유 문구를
  BAU/정책반영/추가조치 3코드로 정규화했다(원문 문구는 별도 칸에 보존).
- **계약 결정은 발주 확인 요청**: 축 구분을 어떻게 할지는 개발자가
  임의로 정하면 안 되는 정책 결정이라, 발주 문의서 3번(06 인벤토리 축)에
  05 사례를 추가해 확인을 요청해 둔 상태다(`docs/audit/발주문의_초안_20260717.md`).

## 선택지 (발주 회신에 따라)

| 안 | 내용 | 장단점 |
|---|---|---|
| (a) 축 칸 추가 | 05에 `전망범위`(관리권한/지역전체/기존계획) 컬럼 신설 | 정보 무손실, 충돌 해소. 단 가이드라인 계약 확장 필요 |
| (b) 본류만 한정 | 가이드라인 문면대로 관리권한 전망만 05에 담고 나머지는 제외/별도 표기 | 계약 그대로. 단 문서에 실재하는 다른 전망 정보가 빠짐 |
| (c) 현행 유지 | 다 추출하되 충돌은 검증리포트로 표시 | 변경 없음. 충돌 소음 지속 |

가이드라인 문면 기준의 최소 해석은 (b), 정보 보존 관점의 권고는 (a)다.

## 보고서에 쓸 때 핵심 문장 (요약)

> 지자체 문서에는 동일 부문·연도의 배출 전망이 계획 축(기존/현행)과
> 집계 축(지역전체/관리권한)에 따라 복수로 실리는데, 가이드라인의 05
> 시트 계약은 관리권한 축 하나만을 전제해 축 구분 필드가 없다. 표본
> 원문 검증에서 "값 불일치"로 보였던 사례의 상당수는 추출 오류가 아니라
> 서로 다른 축의 원문값이 같은 키에 겹친 것으로 확인되었으며(예: 경기
> 농축산 2030 BAU 1,156.8천톤[기존계획] vs 3,236천톤[현행 관리권한]),
> 이는 시트 계약에 축 구분을 추가하거나 추출 범위를 관리권한 축으로
> 한정하는 정책 결정이 필요한 사안이다.
