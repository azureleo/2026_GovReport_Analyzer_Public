# 저장 응답 고정·감축목표 정리·실패 배치 복구

## 적용 범위

`OrganizerAgent`의 감축목표 정리는 이전의 지자체·목표수준·부문·목표연도만으로
첫 행을 선택하던 방식을 제거했습니다. 목표범위·기준연도·단위도 구분하며,
동일 업무 값만 합치고 근거 ID·객체 ID·페이지·계보를 모읍니다.
범위 공란을 다른 행에서 추정하지 않으며, 같은 식별자의 값 충돌은 두 행과 검토 사유를 남깁니다.
일반 `main.py` 실행에도 이 정리 규칙이 적용됩니다.

`scripts/recover_saved_extractions.py`는 이미 완료된 실행을 부분 보완하는 별도 실행기입니다.
전체 모델 재실행이나 원본 RunState의 지문 검사 완화가 아닙니다.

- 기존 Excel의 모든 셀을 불변 기준으로 사용합니다. 성공 텍스트와 Vision은 재호출하지 않습니다.
- 저장 원장의 감축목표 행을 실제 Organizer로 다시 정리합니다.
- 원문 숫자가 확인되고 기존 본문에 없는 사실만 새 행으로 추가합니다.
  기존 행과 동일 식별자에서 다른 값이 있으면 보류하며, 기존 값을 덮어쓰지 않습니다.
- 감축목표의 일부 숫자만 원문 대조에 실패하면 해당 필드를 비우고 나머지 확인된 값을 보존합니다.
  원래 행·미확인 필드·보류 사유는 복구 JSON에 유지합니다.
- 실패 배치의 시트·페이지·입력 텍스트·보조 지침·스키마 지침·지역·출처를 원래 배치 ID로 재검증합니다.
  일치하지 않으면 재호출하지 않습니다. 첫 버전은 시트별 텍스트 배치 원장을 지원합니다.
- 모델/provider는 기준 실행 매니페스트에서 읽습니다. 실호출은 Codex 기준 실행만 지원하며,
  모델·추론 강도·프롬프트·실제 `.env`를 수정하거나 다른 모델로 대체하지 않습니다.
  기존 CLI의 추론 기본값을 사용하며 과거에 기록하지 않은 CLI 전역 설정의 동일성은 보증하지 않습니다.
- 실패 배치당 한 번만 시도하고 원응답을 파싱 전에 저장합니다.
  완료 응답은 반복 실행에서 재사용하며, 중단·실패 호출은 자동 재시도하지 않습니다.
- 실제 Organizer·의미 검증(자동 재분류 OFF)·원문 숫자 대조·ExcelAgent를 통과합니다.
  물량도 정성 계획도 없는 `-` 행은 복구 성공 행으로 추가하지 않습니다.
- 저장 후 기존 셀 보존과 신규 업무 셀 일치를 실제 Excel 재개방으로 검사합니다.

이 실행기는 당시 전체 원시 데이터(특히 정리 전 Vision 업무 행)가 없는 과거 실행을
완전히 재구성하지 않습니다. 현재 남아 있는 저장 응답과 불변 Excel을 이용하는 증분 복구입니다.
기존 검증리포트·내부 원장은 당시 이력으로 보존하며, 해결된 배치와 현재 보류는
`*_recovery.json` 및 `pipeline_audit.context.saved_recovery`에서 구분합니다.

## PowerShell 실행

현재 이 브랜치를 사용하는 프로젝트 폴더에서 실행합니다. 기준 Excel과 같은 위치의
`_run_manifest.json`, `_pipeline_audit.json` 및 원장 `ledger.jsonl`, 원본 PDF가 필요합니다.

```powershell
$baseline = ".\output\기준실행.xlsx"
$repairDir = ".\output\저장응답복구_$(Get-Date -Format 'yyyyMMdd_HHmmss_ffffff')"

# 1. 기본: 저장 응답 정리만. 모델 호출 없음.
py scripts/recover_saved_extractions.py "$baseline" --output-dir "$repairDir"

# 2. 같은 기준/같은 폴더에서 실패 배치만 최대 1회 호출.
py scripts/recover_saved_extractions.py "$baseline" --output-dir "$repairDir" `
  --recover-failed --max-calls 1 --timeout 300 `
  --codex-command "$env:APPDATA\npm\codex.cmd"
```

같은 두 번째 명령을 반복해도 저장된 복구 응답이 있으면 재호출하지 않습니다.
매번 불변 기준에서 새 Excel을 만들기 때문에 추가 행이 누적 중복되지 않습니다.
더 많은 미시도 실패 배치는 `--max-calls`를 명시적으로 늘려 진행할 수 있습니다.
상한은 해당 실행의 새 호출 수이며, 이미 시도한 배치를 재시도하는 옵션은 아닙니다.

원본 파일을 이동했다면 `--pdf`·`--state-dir`로 경로를 지정할 수 있습니다.
보조 지침이 바뀌었다면 당시의 지침 dict JSON을 `--extraction-prompts`로 제공해야 하며,
기준 지문이 다르면 호출하지 않습니다. `--output-dir`에는 별도 전용 폴더를 지정하세요.

## 결과와 해석

| 파일 | 내용 |
|---|---|
| `plan.json` | 불변 입력 해시·성공/실패 배치·기준 모델·정책 |
| `state.json` | 시도/응답 저장 상태와 해시. 중단 호출의 자동 재호출 방지 |
| `배치ID_response.json` | 요청 지문과 원응답 문자열 |
| `recovered_001.xlsx` 등 | 기준 셀을 보존한 새 Excel |
| `recovered_001_recovery.json` | 원행·필드 보류·중복·충돌·신규 셀 검증 결과 |
| `recovered_001_pipeline_audit.json` | 기준 내부 원장 이력과 현재 복구 결과 |

종료 코드 `0`은 복구 범위의 처리·저장 검증 완료, `2`는 저장됐지만 미시도/실패/보류가 남음,
`1`은 입력·지문·저장 등의 오류입니다. 행 수 증가나 숫자 문자열의 원문 존재는 전체 정확도를 뜻하지 않습니다.
모델 판독 성공·본문 추가·실제 셀 저장을 구분하며 공식 골든 채점은 이 실행기에서 수행하지 않습니다.

검증 예:

```powershell
py -m pytest tests/test_saved_extraction_recovery.py -q
```

외부 모델 경계만 fixture로 바꾸고 실제 데이터 전달·정리·의미 검증·원문 대조·Excel 저장을 검사합니다.
실제 모델 실측과 fixture 연결 검증은 따로 기록해야 합니다.
