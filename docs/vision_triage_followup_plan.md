## 범위와 현재 상태

2026-09-19: 우선순위 1(판단 근거 부족과 명확한 비데이터 구분)을 구현했다.
우선순위 2(제한적 판독)와 3(평가 지표 보완)도 구현했다. 제한적 판독은 기본 비활성이며 아래 환경변수로 명시적으로 켠다.

## 우선순위 1: 구현한 분류 계약

| 조건 | action | final_status | 자동 모델 호출 |
| --- | --- | --- | --- |
| 기존 강한 데이터 신호가 있는 시각 객체 | `ocr_required` | 판독 전 `needs_review` | 기존 정책 유지 |
| 강한 신호가 없고 객체 자체 캡션이 좁은 비데이터 라벨에 일치 | `skip_non_data` | `not_relevant` | 없음 |
| 캡션 없음, 근거 부족, 주변의 부정적 문맥만 존재 | `review_required` | `needs_review` | 없음 |
| 공백뿐인 네이티브 텍스트 | `review_required` | `needs_review` | 없음 |
| 비어 있지 않은 네이티브 텍스트 | `native_keep` | `extracted` | 기존 정책 유지 |
| 전체 페이지 렌더 전송 프록시 | `transport_only` | `not_relevant` | 별도 데이터 객체로 호출하지 않음 |

- 명시적 비데이터 라벨은 번호를 제거한 전체 캡션이 `위원회 사진`, `행사 사진`, `기관 로고` 등 제한된 표현에 일치하는 경우만 인정한다.
- 주변 문장의 `사진`, `모집`, `참고 사례`만으로 이미지를 비데이터로 확정하지 않는다.
- 데이터 신호는 비데이터 캡션보다 우선한다. 강한 신호의 판정 기준 자체는 이번에 넓히지 않았다.
- 보류의 `status`는 `deferred_classification`, 판독 시도는 0회다. `ocr_required`로 자동 승격하지 않는다.
- 기존 객체 ID, 근거 ID, 좌표, 캡션과 이유를 보존한다. 원문객체인벤토리에서는 기존 `review` 경로를 사용한다.
- 로그와 실행 매니페스트의 `vision_render_stats`에 보류 객체·보류 시각 객체·빈 텍스트·명시적 비데이터 건수를 기록한다. 여기의 건수는 호출 횟수가 아니다.

우선순위 1만 적용하면 테스트 PDF의 숫자가 Excel에 채워지지는 않는다. 기존처럼 조용히 제외하지 않고, 아직 판독되지 않은 객체라는 사실을 남기는 단계다. 추가 판독을 켜야 우선순위 2 경로가 실행된다.
기존 결과·체크포인트를 소급해 고치지 않는다. 새 검증은 새 상태 디렉터리에서 실행한다.

## 우선순위 2: 근거 부족 객체의 제한적 판독

### 구현 순서

1. `utils/vision_review.py`의 별도 승격 함수로 최초 분류와 승격 이유를 각각 기록한다. `utils/selective_ocr.py`의 직렬화에도 이를 보존한다.
2. 페이지의 실제 네이티브 텍스트 양과 이미지 점유 면적을 조합해 스캔형 페이지를 찾는다. 페이지 머리말·캡션이 조금 있는 경우도 포함한다. 파일명·서울 전용 페이지 번호는 사용하지 않는다.
3. 먼저 큰 페이지 이미지와 구조화된 표·도식 후보를 선택한다. 크기만으로 데이터라고 확정하지 않는다. 정성 체계도와 단위 없는 조직 정보도 후보에서 배제하지 않는다.
4. 페이지 내 중복 이미지·전송 프록시는 물리 객체 ID로 통합해 같은 그림을 반복 호출하지 않는다. 전체 페이지와 부분 그림을 동시에 보낼 필요가 있는 경우는 명시적 정책으로 분리한다.
5. `agents/image_agent.py`의 기존 호출 경로에 승격된 객체만 연결한다. 기존 `ocr_required` 객체에는 추가 분류 호출을 붙이지 않는다.

### 비용 보호와 설정

다음 설정을 `config.py`에서 지원한다. `.env` 파일은 수정하지 않았다.

- `VISION_REVIEW_ENABLED`: 기본 0. 1로 켠 실험만 제한적 판독을 추가한다.
- `VISION_REVIEW_MAX_OBJECTS`: 기본 16개. 전체 파이프라인 재시도에서도 예산을 공유한다.
- `VISION_REVIEW_MAX_PER_PAGE`: 기본 1개. 다중 패널은 한 대표 입력을 우선한다.
- 승격 객체 재시도/재귀 분할: 최초 실험은 추가 재시도 0, 재귀 분할 0으로 별도 제한. 기존 일반 후보 정책은 유지한다.
- `VISION_REVIEW_MAX_CALLS`: 기본 16회. 단일 이미지/단일 루트 배치이며, 캐시 재사용도 예약 1회로 보수적으로 계산한다. 실제 외부 호출 수는 별도 LLM 계측을 확인한다.
- `VISION_REVIEW_MAX_SECONDS`: 기본 600초. 추가 판독 경로의 누적 소요 시간 예산이다. 전체 PDF 파이프라인의 종료 시간 제한이 아니다.
- `VISION_REVIEW_CALL_TIMEOUT`: 기본 120초. 남은 총 예산과 기존 CLI 타임아웃 중 가장 작은 제한을 적용한다. 프로세스 종료 정리 시간이 소폭 추가될 수 있으며 그 시간도 사용량에 기록한다.
- 예산의 0은 무제한이 아니라 추가 판독 금지다. 상한 도달 시 남은 객체는 `needs_review`/예산 보류로 남긴다.
- 추가 판독은 순차 실행하며 JSON 재요청·quota 대기·capacity 모델 전환·음성 재검증도 금지한다. 기존 일반 후보의 정책은 변경하지 않는다.
- 현재 엄격한 단일 호출/시간 제한은 `codex`·`claude` CLI에 지원한다. 이 추가 판독 경로에 API 백엔드를 지정하면 호출하지 않고 검토 대상으로 남긴다. 일반 API 판독 경로는 유지한다.
- `vision_review_budget.json`에 예약을 먼저 저장한다. 중단된 예약은 재개 시 타임아웃 전체를 사용한 것으로 보수적으로 계산하며, 같은 객체는 자동 재판독하지 않는다. 성공 체크포인트와 부분 성공 행은 보존한다.
- `--retry-vision-evidence` 등 강제 복구 옵션도 추가 판독 예산을 우회하지 못한다. 다시 판독하려면 명시적으로 새 실험을 만든다.
- 예산 사용량, 입력 이미지 해시와 복구 정책을 기록한다. 모델/백엔드는 기존 실행 매니페스트에 기록한다. CLI 기본 추론 강도는 자동 계측하지 않으므로 비교 전에 별도로 동일하게 고정·기록해야 한다. 시간 지연·실패도 비용에 포함한다.

### 호출 전 사전 점검

- 모델 호출 없이 분류·승격 후보·제외 사유·페이지·객체 ID·이미지 해시·예상 루트 배치를 출력한다.
- 이번 11쪽 파일은 11개 대표 시각 입력의 포함 여부를 확인한다. 빈 텍스트 11개는 추가 이미지 호출을 만들지 않는다.
- 후보 0개인데 검토 대상이 남았으면 경고하거나 비교 실행을 중단한다.
- 두 모델에 같은 후보 목록을 사용한다. 모델별 `RUN_STATE_DIR`를 분리하며 Vision 모델/백엔드/예산 정책을 실행 지문에 포함한다.
- `VISION_EXPECTED_CANDIDATE_SHA256`를 지정하면 실제 ImageAgent 후보 해시가 다를 때 Vision 호출 전에 중단한다. 텍스트 추출보다 먼저 검사하는 옵션은 아니므로 반드시 사전 점검부터 실행한다.

### 완료 기준

- 이미지형 11쪽에서 대표 이미지를 빠짐없이 선택하며, 명시적 행사 사진·로고는 기존 제외를 유지한다.
- 서울 원본 175쪽과 같은 캡션만 추출되는 체계도는 보류에서 제한적 판독 후보로 승격된다.
- 예산 초과·타임아웃·재개·부분 성공 시 상한과 보류 상태를 보존한다.
- 외부 모델을 쓰지 않는 모의 통합 테스트 후 1~2쪽 실호출, 마지막에 11쪽 A/B 순서로 진행한다.

## 우선순위 3: 제외·보류·빈 분모를 구분한 평가

### 구현 대상

- `utils/source_verifier.py`: 데이터 추출 대상, 내용 미확정 검토 대상, 명시적 비데이터, 전송 프록시를 구분한다.
- `agents/supervisor.py` 및 `main.py`: 파일 저장 성공과 추출/평가 성공을 분리한다. 상태별 종료 코드 정책을 기존 배치 실행기와 함께 검토한다.
- 기존 Excel 인벤토리/검증리포트, 실행 매니페스트와 관련 평가·보고 스크립트를 함께 점검한다.

### 지표 원칙

- 객체 커버리지와 추출 배치 성공률의 분모 0은 `null` 및 평가 불가 사유로 기록한다. 숫자를 기대하던 감독관 로그와 보고 코드도 수정했다.
- 확정된 데이터 대상의 커버리지, 판독 시도율, 보류율, 명시적 비데이터 제외율을 각각 제공한다.
- 보류를 정답 데이터로 단정해 재현율에 섞지 않는다. 확정 비데이터로 간주해 숨기지도 않는다.
- 빈 텍스트/0개 배치/0개 업무 행에 성공 점수를 부여하지 않는다. 계산 방식 변경은 평가 버전과 함께 기록한다.
- 기존 인벤토리의 `review` 행은 유지하되, 이제 확정 데이터 객체 커버리지 분모에서는 분리한다. 데이터 신호가 확실한 미판독 객체는 여전히 추출 분모에 포함한다.
- 평가 버전은 `quality-v2/source-inventory-v2`다. 구버전 점수와 직접 비교해 정확도 개선/하락으로 해석하지 않는다.
- 셀 정확도·행 정밀도는 독립적으로 확인한 정답 표본이 있어야 산출한다. 자동 완전성 점수를 정확도로 부르지 않는다.

### 완료 기준

- 전부 보류, 전부 명시적 비데이터, 데이터/보류 혼합, 정상 추출, 렌더 실패, 모델 실패의 지표를 각각 검증한다.
- 파일이 생성됐어도 실질 추출이 0이면 성공으로 오인되지 않는다.
- 동일 입력의 수정 전후 결과에서 분류와 분모 변화를 분리해 설명할 수 있다.
- 확정 비데이터 표본과 독립적인 신규 데이터 표본을 포함해 누락 감소와 추가 호출 비용을 함께 평가한다.

## 종료 상태 및 저장 파일

- 종료 코드 0: 운영상 완료. 셀 정확도/행 정밀도 보장을 뜻하지 않는다.
- 종료 코드 1: 실행 오류 또는 중단.
- 종료 코드 2: 실질 업무 행 없음. `--evaluate` 평가 계약 오류도 기존처럼 2이므로 메시지와 결과 파일을 함께 확인한다.
- 종료 코드 3: 파일 저장됨·검토 필요(보류/미복구 배치/품질 기준 미달). 파일 생성 실패가 아니다.
- `<결과명>_run_outcome.json`: 파일 저장과 추출 상태를 분리한다. run-state를 끈 실행에도 생성한다.
- `<결과명>_vision_preflight.json`: 시도별 후보·해시와 제한적 판독 예산 기록.
- 기존 실행 매니페스트: 새 평가 지표와 `review_budget`, `batch_status`, `status`, `exit_code`를 포함한다.
- 기존 텍스트 A/B·가이드라인 A/B 실행기는 코드 3과 대응하는 저장 결과가 확인되면 비교를 계속하되 검토 상태로 보고한다. 코드 2는 중단한다.

- 빈 분모, 전부 보류, 명시적 비데이터, 혼합 대상, 저장 성공과 검토 상태의 구분을 검증했다. 이 결과는 판독 정확도나 모델 간 속도 비교 결과가 아니다.

프로젝트 폴더의 VSCode PowerShell에서 실행한다. 후보 목록 생성만 하며 Excel을 추출하지 않는다.

```powershell
$env:VISION_REVIEW_ENABLED = "1"
$env:OCR_BACKEND = "vlm"
$env:SELECTIVE_OCR_ENABLED = "1"
$stamp = Get-Date -Format "yyyyMMdd_HHmmss_ffffff"
$preflight = ".\output\vision_preflight_$stamp.json"
py scripts/preflight_vision.py ".\테스트파일_2.pdf" --output "$preflight"
if ($LASTEXITCODE -eq 0) {
    $plan = Get-Content -LiteralPath $preflight -Raw -Encoding UTF8 | ConvertFrom-Json
    $env:VISION_EXPECTED_CANDIDATE_SHA256 = $plan.candidate_sha256
    Write-Host "일반 입력: $($plan.regular_inputs), 추가 판독: $($plan.review_inputs)"
    Write-Host "예상 루트 배치: $($plan.expected_root_batches)"
} else {
    Write-Warning "사전 점검 실패 또는 후보 없음: 모델 비교를 시작하지 마세요."
}
```

`--enable-review`도 지원하지만 그 옵션은 사전 점검 프로세스에만 적용된다. 실제 `main.py` 실행까지 켜려면 위 환경변수가 필요하다.
예산을 바꿨다면 사전 점검도 다시 실행한다. 다른 PDF로 넘어갈 때는 `Remove-Item Env:VISION_EXPECTED_CANDIDATE_SHA256 -ErrorAction SilentlyContinue`로 이전 해시를 제거하고 새로 생성한다.

다음 순서: 1~2쪽 실호출 → 같은 후보의 11쪽 Luna/Astra 비교 → 전체 PDF. 이번 구현 검증에서는 실호출하지 않았다.
두 모델의 후보 해시뿐 아니라 실제 판독 시도 수·보류 수가 같은지도 확인해야 한다. 600초 제한 때문에 한 모델만 일부 객체를 판독했다면 전체 표본의 속도/정확도 우열로 결론 내리지 않는다.
완전한 11개 입력 비교가 필요하면 두 실행 모두 같은 더 큰 총 예산을 사전에 선택한다. 모델·추론 강도·캐시·일반 후보 복구 정책도 별도로 동일하게 통제한다.

모델별 실행은 새 출력 이름과 별도 `RUN_STATE_DIR`를 사용한다. 이전 실험의 예산을 초기화하려면 새 실험 디렉터리를 만들고 `EXTRACTION_RESUME=0`으로 실행한다. 단순 `--resume`으로 예산이 초기화되지는 않는다.

현재 구현분의 빠른 검증 명령:

```powershell
py -m pytest tests/test_vision_review_budget.py tests/test_triage_uncertainty.py tests/test_selective_ocr_pipeline.py tests/test_source_verifier.py -q -p no:cacheprovider
```

이 명령은 모델을 호출하지 않는다. `-p no:cacheprovider`는 OneDrive 경로의 pytest 캐시 쓰기 경고를 피하기 위한 옵션이다.
