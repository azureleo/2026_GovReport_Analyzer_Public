# Vision 목차 선별 구현 및 텍스트 최적화 후속 계획

2026-09-20 최초 작업은 목차 판정 기록과 Vision 호출 전 제외였다.
같은 날 후속 작업에서 텍스트 입력 감사·보수적 최적화·묶음 부분 복구와 분리 A/B를 구현했다.
현재 동작과 검증 한계·명령은 `docs/text_optimization.md`를 참고한다.
아래 3~4절은 최초 계획을 보존한 것이다. 강한 키워드 일괄 제거와 빈도만 이용한 본문 배정 축소는 활성화하지 않았다.

## 1. 구현한 동작

- `utils/vision_toc.py`: 페이지의 목차 근거와 객체별 판정을 생성한다.
- `agents/image_agent.py`: 객체 선별 직후, 제한적 판독 후보 승격·렌더·배치 등록 전에 적용한다. 기존 렌더 경로에도 안전 검사를 적용한다.
- `utils/selective_ocr.py`: 객체 결정과 메타데이터에 `toc` 근거를 보존한다.
- `utils/run_state.py`: 정책 버전/모드를 실행 fingerprint에 포함한다. 다른 정책의 체크포인트를 같은 실행으로 재사용하지 않는다.
- `scripts/preflight_vision.py`: `--toc-mode`로 기록 모드와 제외 모드를 모델 호출 없이 점검한다.
- 감독관은 기존 `*_vision_preflight.json`의 `attempts[].toc_audit`에 상세 근거를 저장하고 실행 기록에 목차 카운터를 남긴다. 재시도별 카운터 합계는 고유 객체 수가 아니므로 고유 수는 각 preflight에서 확인한다.

### 판정과 안전 경계

1. 표/그림 번호·제목·참조 쪽번호가 반복되는 구조를 확인한다. 제목만 있거나 숫자만 있는 항목은 근거가 부족하다.
2. 명시 목차 제목이 있으면 서로 다른 항목 3개 이상, 제목 없는 연속 목록은 8개 이상의 독립 항목이 필요하다. 이 기준과 제외 객체를 모두 기록한다.
3. 목차와 실제 데이터가 섞인 페이지는 `mixed_toc`로 기록한다. 확인된 목록 캡션 프록시만 제외한다.
4. 실제 표 셀을 가진 객체, 알 수 없는 삽입 이미지, 목록 밖의 동일 캡션, 통합된 객체의 미확인 별칭은 제외하지 않는다. 통합 별칭의 원본 모두가 목차임을 확인해야 제외할 수 있다.
5. 전체 페이지 렌더 제외는 목차 텍스트 비율이 높고, 네이티브 표·삽입 이미지·목록 외 캡션이 없는 확인된 목차 페이지에 한정한다. 혼합 페이지는 보존한다.
6. 확정된 목차 항목은 `skip_non_data`, `not_relevant`, 시도 0회로 기록한다. 판단 보류나 성공적으로 판독한 데이터로 집계하지 않는다.
7. 목차 원문, 참조 쪽번호, 좌표, 객체 ID와 판정 전 동작을 남긴다. 인쇄 쪽번호를 물리 PDF 페이지 번호로 임의 변환하지 않는다.
8. 스캔 목차·불충분한 단서·새로운 목록 형식은 기존 경로에 남을 수 있다. 이 기능은 목차 전부를 반드시 제거하는 분류기가 아니다.

### 설정

`VISION_TOC_MODE`:

| 값 | 동작 |
|---|---|
| `exclude` | 기본값. 판정을 기록하고 확인된 목차를 Vision 호출 전에 제외 |
| `audit` | 같은 판정을 기록하지만 기존 호출 후보는 유지 |
| `off` | 목차 판정과 제외 모두 끄기 |

`.env`는 수정하지 않았다. 해당 키가 없으면 기본 `exclude`가 적용된다.
이미 열린 Python 프로세스에는 소급 적용되지 않는다. 모드를 잘못 입력하면 조용히 제외하지 않고 설정 오류로 중단한다.

### 사전 점검 명령어

프로젝트 폴더의 PowerShell에서 실행한다. 실제 LLM 호출은 없지만 로컬 PDF 파싱·렌더링은 수행한다.

```powershell
$stamp = Get-Date -Format "yyyyMMdd_HHmmss_ffffff"

py scripts/preflight_vision.py ".\서울특별시_탄소중립계획.pdf" `
  --toc-mode audit `
  --output ".\output\vision_toc_audit_$stamp.json"

if ($LASTEXITCODE -ne 0) { throw "기록 모드 사전 점검 결과를 먼저 확인하세요." }

py scripts/preflight_vision.py ".\서울특별시_탄소중립계획.pdf" `
  --toc-mode exclude `
  --output ".\output\vision_toc_exclude_$stamp.json"
```

`--toc-mode`는 이 사전 점검 프로세스에만 적용한다. `main.py`에서 모드를 명시하려면 같은 터미널에서 `$env:VISION_TOC_MODE = "exclude"`를 사용한다. 기존에 지정한 `VISION_EXPECTED_CANDIDATE_SHA256`가 있다면 변경된 후보에 대해 새 preflight로 검증한 해시를 사용해야 한다. 정책 변경 후 이전 해시의 안전 검사를 우회하지 않는다.

## 2. 이번 작업의 한계

- 목차의 네이티브 텍스트와 HTML 표는 수정하지 않는다. 따라서 **텍스트 추출에서 생성된 목차 유래 업무 행은 이번 변경만으로 사라진다고 보장하지 않는다.**
- 저장 응답을 후단에 재연결하는 것만으로 새 호출 선별의 실제 속도·모델 정확도를 평가할 수 없다. 사전 점검은 후보 보존 검증이지 최종 셀 정확도 검증이 아니다.
- 제외 입력 수, 제외 객체 수, 루트 배치 수, 복구를 포함한 실제 호출 수는 서로 다르다.
- 이전 결과와 원본 PDF·.env·골든셋은 변경하지 않는다. 실제 장시간 전체 모델 실행은 이번 구현 검증에 포함하지 않는다.

## 3. 최초 후속 계획 A: 텍스트 입력 및 배정 최적화

### A1. 호출 계획과 실효성 계측

`agents/extractor_agent.py`의 배정 및 작업 큐에 시트, 페이지, 객체 ID, 선택 근거, 입력 문자 수, 반환/최종 채택 행 수, 지연, 분할 계보를 기록한다. 빈 응답은 누락 가능성도 있으므로 자동 제외의 정답으로 사용하지 않는다.

### A2. 배정 변경은 기록 전용으로 먼저 비교

- 목차/머리말과 장·절/실제 표 헤더의 신호를 구분한다.
- 확실한 목차 항목은 본문 탐색 인덱스로 보존하고 측정값 후보와 분리한다.
- 페이지가 여러 시트에 해당하면 복수 배정을 유지한다.
- 연속 표, 각주, 단위, 지역·기간의 문맥을 보호한다.
- 페이지 수 상한, 앞 N쪽 제외, 라우팅 점수 일괄 인상은 사용하지 않는다.
- `ROUTE_DROP_UBIQUITOUS_STRONG`은 당장 켜지 않는다. 기존 코드에도 메타 필드 손실 위험이 기록돼 있다.

기존 `scripts/verify_routing_coverage.py`를 확장하여 이번 후보 정책과 현행 정책을 명시적으로 비교한다. 현재 검증기의 weak-keyword 비교만 통과했다고 새로운 정책이 검증됐다고 보지 않는다.

### A3. 중복 표현 축소

본문 문자열과 HTML 표에 동일 표가 중복된 경우 객체/좌표 근거로 중복 표현만 제거한다. 원문은 별도로 보존한다. 표 헤더, 캡션, 각주, 명시 단위, 시트별 필드 정의, 추론 금지 규칙은 유지한다. `BATCH_SIZE`나 문자 상한을 무조건 높이지 않는다.

### A4. 통과 기준

골든 원문 앵커의 시트별 후보 보존율, 기존에 올바른 행을 만든 페이지 보존, 제외된 비골든 표본의 사람 검토를 함께 수행한다. 사전 점검을 통과하면 문서 메타/실적/연간 예산/다년 합계/배출 전망/본문 그림을 포함한 소규모 고정 표본으로 실호출한다. 알려진 정답의 손실은 총점 상승과 별개로 검토한다.

## 4. 최초 후속 계획 B: 텍스트 묶음 호출 별도 A/B

기존 `scripts/run_text_optimization_ab.py`와 `EXTRACTION_SHEET_CLUSTERING`을 활용하되, A 단계 변경이 확정된 뒤 묶음 여부만 바꾼다.

- A군: 같은 배정·입력을 시트별로 호출.
- B군: 같은 배정·입력에서 의미가 가까운 시트만 2~3개 묶음.
- 그룹 전체의 페이지 합집합에 항상 모든 시트를 요청하지 않고, 해당 배치에 실제 필요한 시트를 검토해 요청한다.
- 성공한 시트 결과는 보존하고 실패한 시트만 제한적으로 복구한다. 시트 누락 응답을 빈 배열 성공으로 처리하지 않는다.
- 입력 PDF/해시, 코드, 모델·추론 강도, 동시성, 제한 시간, 후단 규칙과 채점 계약을 고정한다. 양쪽 모두 캐시·resume을 끄고 별도 실행 원장을 사용한다.
- Vision은 양쪽 모두 비활성화하여 텍스트만 평가하거나, 동일한 저장 Vision 결과를 동일한 후단으로 연결한다. 다른 Vision 응답을 섞지 않는다.
- 입력 최적화와 묶음 호출을 동시에 바꾸는 첫 실험은 하지 않는다.
- 최종 평가: 동일 골든 분모의 셀 정확도·행 정밀도·행 재현율, 기존 정답 손실, 중복/충돌, 실패 시트, 타임아웃·복구 포함 실제 호출 수와 벽시계 시간을 비교한다. 품질 점수나 문자 수를 정확도/토큰 수로 오인하지 않는다.

과거 묶음 실험의 약 21% 텍스트 시간 단축은 참고 이력이다. 현재 변경에 대한 재검증 없이 그대로 기대 성능으로 제시하지 않는다. 두 계획이 검증된 후에만 전체 캐시 없는 실행 1회를 진행하고, 전체 실행시간 절반 목표 달성 여부를 측정한다.
