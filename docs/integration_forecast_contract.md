## 키와 불확실성

05의 동일 행 판단은 지자체명·전망범위·시나리오·부문·세부부문·연도·단위와 값을 함께 고려한다.
다른 시나리오·세부부문·단위·범위는 같은 값이어도 분리한다.
수치 또는 공개 필드의 충돌은 행을 각각 유지하고 `_merge_conflict`에 남긴다.
출처페이지와 근거ID는 동일 사실의 경우 합집합으로 병합한다.
추출 계보와 엔진 집합도 합집합으로 유지하며, 병합 후 Excel의 `출처계보` JSON을 다시 직렬화한다.
구 산출물에 직렬화된 계보만 남아 있는 경우도 읽어 함께 보존한다.

빈 전망범위는 전체 후보를 먼저 구성한 뒤 정확히 하나의 범위·행에만 대응할 때 흡수한다.
지역전체와 관리권한 모두 후보이면 빈 행을 유지하고 `_forecast_scope_review`를 기록한다.
같은 키·수치라도 주요가정·전망방법 등 공개 필드가 충돌하면 빈 범위를 흡수하지 않는다.
`관리권한 외/제외/없음`, `비관리권한`은 관리권한 범위로 정규화하지 않는다.
입력 순서별 모든 순열 검증에서 결과가 같다. 구 체크포인트의 필드 누락은 빈 범위로 처리한다.
지자체명·고정 페이지 번호는 범위를 판정하는 근거로 사용하지 않는다.

축 원값은 `_axis_original`에, 처리·근거는 `_axis_validation`에 남긴다.
축이 지워진 행은 그 사실만으로 전망행이 되지 않는다. 잘못된 원래 축이 있으면 자동 이동을 보류한다.
직접/간접/흡수의 원문 헤더·세부부문 토큰만 보완 근거로 사용하며 건물 등의 부문명만으로 추정하지 않는다.

의미 이동은 객체의 근거ID가 있으면 해당 객체 문맥을 먼저 사용한다.
유효한 축, 계획시작 전 과거행, 목표·실적 표시, 미확정 시나리오는 원래 시트에 남긴다.
명시 BAU·정책반영·추가조치 전망일 때 이동하며, 이동이 성립한 뒤 03→지역전체, 04→관리권한을 적용한다.
후처리 후 `_key_blank_stats`를 다시 집계한다.

## 산출물과 복구

`validation_report`에는 축 enum 위반, 보완 근거, 범위 미확정, 병합 충돌이 남는다.
root의 `_pipeline_audit.json`에는 행 주석·키 공란 통계·격리 원장과 OCR 원장이 포함된다.
`write_quarantine_ledger`는 독립 호출 시 `<stem>_격리원장.json`을 생성한다.
Organizer는 기존 validation/visual_inventory 및 OCR 메타데이터를 정제 후에도 유지한다.

`RunState`는 V9 API를 유지하되 추출 원천 우선순위만으로 값이 다른 행을 삭제하지 않는다.
엔터티 키에도 범위·시나리오·세부부문·단위를 포함한다.
실행 fingerprint에는 전체 execution_info를 포함하므로 root가 전달한 OCR 파일 해시 변경도 다른 실행이 된다.
같은 행 재병합 및 체크포인트 재개는 중복 행을 생성하지 않는다.

## 채점

구 골든→신 출력, 신 골든→구 출력, 양쪽 범위 존재, 범위 충돌을 각각 검사했다.
05 매칭은 양쪽에 명시된 범위·시나리오·세부부문·단위 충돌을 완화 매칭에서도 거부한다.
명시 범위의 정확 매칭을 먼저 처리하고, 한쪽 범위가 비어 있으면 양방향으로 후보가 유일할 때만 호환 매칭한다.
빈 범위가 여러 범위에 대응하면 임의의 후보를 소비하지 않는다.
같은 기본 키에 명시 범위 충돌이 남아 있으면 빈 범위 후보로 그 충돌을 우회해 매칭하지 않는다.
두 scorer는 골든 파일 SHA256과 채점 계약 버전을 보고한다.
서로 다른 골든 버전의 점수는 직접 성능 향상 근거로 비교할 수 없다.
서울 V9 전망범위 골든 및 기존 골든 파일은 복사·수정·확정하지 않았다.
