# 2차 예산 행의 계획구분·부문 연결

2026-10-26, `codex/second-pass-reading-merge`에 적용했습니다. 기존 1차 파이프라인의 모델·추론 강도·`.env`·금액 판독 프롬프트는 변경하지 않습니다. 분류 보완은 2차 실행기의 신규 예산 행에 적용합니다. 기존 Excel의 업무 셀은 유지하고 새 파일을 저장합니다.

## 분류 근거와 범위

`utils/second_pass_context.py`의 `ContextResolver`가 저장된 객체와 기준 Excel을 읽습니다.

- 실제 본문의 계획 절 제목 → 사업 관리번호 머리글 → 해당 사업의 부문 머리글 → 원문 예산표 위치를 연결합니다. 코드 접두사를 부문명으로 변환하거나 사업명 키워드로 분류하지 않습니다.
- 다음 사업·상위 사업군·새 절을 만나면 앞선 사업의 연결 범위를 끊습니다. 사업 머리글에서 8쪽을 초과한 연속 연결은 보류합니다. 다른 사업의 분류, 참고사례 및 목차로의 전파를 차단합니다.
- native/pymupdf 계열 및 출처 엔진이 없는 과거 객체의 명시 머리글을 사용합니다. 모델/VLM/OCR이 만든 머리글을 독립 원문 근거로 승격하지 않습니다. 일반 문장이 혼입될 수 있는 `section`·`nearby_text` 문자열은 분류 근거로 사용하지 않습니다.
- 기준 `11_재정투자계획`·`08_감축사업목록`의 값은 지자체와 출처 페이지/객체 근거가 맞고, 사업명 또는 명시 관리번호가 대응할 때만 연결합니다. 사업명은 공백·줄바꿈을 정리하지만 괄호를 임의로 제거하거나 유사도로 연결하지 않습니다. 별칭은 원문 객체에 명시된 목록만 허용합니다.
- 값이 하나로 일치하면 빈 열을 채웁니다. 서로 다른 유효 분류는 필드별로 보류합니다. 이미 확보한 값은 유지하며 새 충돌을 `preserved_with_conflict`로 기록합니다.
- 분류 목록에 없는 문자열(예: 사업명+시비가 잘못 들어간 부문)은 검토 근거에 원문을 보존하고 분류값으로 채택하지 않습니다. `전환`과 `에너지 생산`, `건물`과 `시민협력`을 임의 동의어로 합치지 않습니다. `탄소 흡수`→`흡수원`처럼 지원하는 표기 대응은 원문과 함께 기록합니다.

근거에는 원문 객체/근거 ID·페이지·좌표·관리번호·사업 경계·원래 값·기준 시트 행이 포함됩니다. 후보별 `context_resolution`, 기존 `출처계보`, 별도 `_context_resolution.json`, 검증리포트에 판정과 보류 사유를 남깁니다. 실제 저장한 두 분류 셀도 재조회해 검증합니다.

## 코드 변경 뒤 기존 응답 재사용

일반 `--resume`은 구현 지문이 달라지면 계속 차단합니다. 과거 응답을 재평가할 때는 **새 출력 폴더와 `--reuse-run`**을 명시합니다.

이 경로는 원본 계획 지문, 입력 파일 해시, 표·대상 ID·좌표, 모델 계약, 실제 프롬프트 해시, 응답/이미지 해시를 검증합니다. 모두 맞는 저장 응답만 새 후단으로 전달하며 모델을 호출하지 않습니다. 원래 실행 폴더와 그 하위에는 저장하지 않습니다. 재평가 결과 폴더는 실제 호출 재개 상태로 전환하지 않습니다. 미시도·실패 응답도 자동 호출하지 않습니다.

```powershell
Set-Location -LiteralPath "C:\Users\정현택\.codex\worktrees\second-pass-reading-merge\졸업프로젝트"
$project = "C:\Users\정현택\OneDrive\바탕 화면\과제\4-1\졸업프로젝트"
$runTag = Get-Date -Format "yyyyMMdd_HHmmss_ffffff"

py -B scripts/run_second_pass.py `
  --targets "$project\output\서울_2차대상준비_20261024_225408_165448_confirmed_targets.json" `
  --input "$project\서울특별시_탄소중립계획.pdf" `
  --reuse-run ".\output\서울_2차판독_제한_20261025_105757_134746" `
  --output-dir ".\output\서울_2차분류보완_$runTag"
```

`.env` 수정이나 Codex CLI 경로 지정은 필요하지 않습니다. 재평가에서는 호출·시간 예산을 사용하지 않습니다. 이미 이번 작업에서 실행한 결과가 있으므로 위 명령은 재현용입니다.

## 검증과 출력

외부 모델 경계만 대체한 fixture 통합과 기존 main/OCR/원문 대조 회귀를 합해 **269 passed**입니다. 샌드박스 임시 폴더 권한 오류가 발생한 첫 실행을 정리하고, 작업 폴더 내 임시 경로에서 전체 검증을 완료했습니다.

```powershell
New-Item -ItemType Directory -Path .test_tmp -Force | Out-Null

```

주요 파일: `utils/second_pass_context.py`(명시 근거 연결), `utils/second_pass.py`(후단·실제 셀 검증·응답 재평가), `scripts/run_second_pass.py`(CLI), 두 `test_second_pass*.py` 테스트 파일입니다. 새 Excel 옆 `_context_resolution.json`과 `_pipeline_audit.json`에 근거와 사유를 저장합니다. `context_summary`는 두 열이 채워진 수와 충돌 없는 수를 구분합니다.
