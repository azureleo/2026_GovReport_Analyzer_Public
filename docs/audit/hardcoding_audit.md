# 하드코딩·샘플링 감사 기록

이번 감사의 목적은 HWP 가이드라인과 지자체 문서 전체를 근거로 추출해야 하는데, 코드에 내장된 상한값·고정 연도·고정 프롬프트 때문에 누락이 발생할 수 있는 지점을 식별하고 제거/완화하는 것이다.

## 확인된 문제와 조치

| 영역 | 문제 | 조치 |
| --- | --- | --- |
| 이미지 분석 | `MAX_IMAGES=50` 기본값 때문에 triage 통과 이미지 중 상위 일부만 Vision 분석했다. | 기본값을 `None`으로 변경해 triage 통과 후보를 전수 분석한다. 빠른 테스트 때만 `--max-images N` 또는 `MAX_IMAGES=N`으로 명시 제한한다. |
| 이미지 fallback | Vision이 모든 이미지를 `해당없음`으로 판단하면 최초 일부 페이지만 fallback 후보로 남겼다. | fallback 상한을 기본 무제한으로 바꾸고, Vision 미판독 페이지마다 주변 텍스트/표에서 직접 보이는 수치를 검토 후보로 남긴다. |
| 문서 라우팅 | 시트별 `DOCUMENT_ROUTE_MAX_PAGES_*` 기본 상한 때문에 관련 페이지가 뒤에 있으면 LLM 입력에서 빠질 수 있었다. | 기본 상한을 제거했다. 필요한 경우에만 환경변수로 제한한다. |
| 전체 문서 스캔 | 키워드 기반 라우팅·프리필터가 가이드라인/문서 표현 차이를 놓칠 수 있다. | `--full-scan`/`FULL_DOCUMENT_SCAN=1`을 추가해 모든 페이지·모든 배치를 에이전트에 전달할 수 있게 했다. |
| 2035 목표 | `감축목표(2035)`를 특정 서울 문서의 2033 근거로 보강하는 코드가 고정 패턴에 가까웠다. | `감축목표(YYYY)` 항목마다 원문에서 해당 연도 근거를 찾고, 없으면 원문 내 가장 가까운 목표연도를 동적으로 찾아 “별도 목표 없음”으로 기록하도록 일반화했다. |
| 빈칸 보완 | `GAP_FILL_MAX_TARGETS`와 focused anchor 상한이 기본값으로 걸려 있어 누락 행 전체 보완을 막을 수 있었다. | 기본 상한을 제거하고 명시 환경변수가 있을 때만 제한한다. |
| 가이드라인 반영 | 기본 스키마/프롬프트는 필요하지만, 이것만으로 추출 규칙이 고정될 수 있었다. | HWP에서 시트별 관련 문맥을 뽑고, Codex 로컬 에이전트가 실행 규칙(`agent_guideline_spec`)을 재구성해 추출 프롬프트에 추가한다. |

## 남아 있는 의도적 고정 요소

- Excel 시트명과 기본 컬럼은 산출물 호환성을 위해 유지한다.
- 기본 부문명/배출유형/전략유형 표준화 목록은 서로 다른 문서의 표현을 같은 엑셀 스키마로 정규화하기 위한 fallback이다.
- `--full-scan`과 이미지 전수 분석은 실제 실행 시간이 매우 길 수 있다. 빠른 개발 검증 때만 명시적으로 상한을 둔다.
