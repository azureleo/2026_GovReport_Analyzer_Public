   p139~140(47,341), p185(28,660·37.8%·23,225·49.6%), p201~202 표 5-5 사업명 등.

## 발견된 결함 (v5 명세서에 반영)

   과제번호와 본계획(p201~, 제6장) 관리번호가 같은 형식·다른 사업. 기본 추출본이
   양쪽을 섞었고, Codex도 구계획 목록(p149)을 기준으로 오탐(양방향 충돌 지적).
   08/10 값충돌의 최대 원인. → v5 WP7 (장 경계 맵 + 계획구분 태깅 + 관리번호
   레지스트리 검증)
2. **후보↔병합 dedup 키 불일치**: 누락후보 686건 중 283건이 '기본본중복'으로 차단
   (자기모순). accept+high 보류 173건 중 156건이 이 사유. → v5 WP3-C-1
3. **'반영' 로그와 시트 불일치**: 반영 251건 중 6건이 최종 시트 부재(06_감축목표

   항목명 변형. → v5 WP3-C-2, WP6-4
4. **관리부문 "에너지"→"전환" 오변환 실증**: p109 에너지 합계가 04 시트에

5. **00_문서메타 중복 3행**(기준연도·목표연도 상충 병존). → v5 WP6-5

## 판정: 이 파일만으로 "v3 검증 완료"라고 할 수 있는가 — **아니오 (부분 검증)**

- **성립하는 것**: v3 기본 추출의 리콜·정합 문제가 크다는 진단(방향성·규모),
  폐루프 병합 인프라의 동작 확인, 위 결함 목록.
- **성립하지 않는 것**:
  1. **사람 판정 0건** — 검수상태 전부 '미검수'. LLM(Codex)이 LLM(v3)을 검수한
     결과이며, 표본 대조(n≈10)는 통과했지만 Codex 자신도 오탐(구계획 기준 충돌
     지적)을 냈으므로 798건 전체의 정밀도는 미확정.
  2. **커버리지 5/16 시트** — 01·02·05·07·09·12~16 시트는 폐루프 검수가 없음.
  3. **라우팅 샤프닝 검증이 아님** — `ROUTE_DROP_UBIQUITOUS_STRONG` A/B와 무관.
     샤프닝 go/no-go 판단 근거로 사용 불가(별도 트랙 그대로 유지).

## 남은 검증 절차 (권장)

1. **층화 표본 사람 판정 (~60건)**: 반영 20 / accept+high 보류(기본본중복) 15 /
   값충돌 15 / needs_human 5 / reject 5. 각 행의 근거페이지를 PDF에서 확인해
   17시트 `검수상태`를 채운다. 목적: Codex 검수 정밀도 추정(오탐률). 특히
   기본본중복 차단 156건이 진짜 중복인지(v5 WP3-C-1 근거 강화).
2. **값충돌 92건 우선 소진**: 이 유형이 최종 데이터 품질에 직결(잘못된 값이 시트에
   남아 있다는 주장). 구계획/본계획 구분 기준으로 재분류하면 상당수가 자동 해소될
   것으로 예상.
3. **타 문서 1건 재현**(강원 또는 경기): 서울 특이 사항(이중 넘버링)이 일반 패턴인지
   확인 — WP7 휴리스틱 패턴 설계에 반영.
4. 라우팅 샤프닝 A/B는 종전 계획대로 별도 진행(v3 라우팅 코드는 v4와 동일하므로
   라우팅 수준 결과는 이전 가능, 종단 확인은 새 브랜치에서 `run_ab_validation.py`).
