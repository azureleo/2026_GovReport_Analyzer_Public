# docs 분류 규칙 (2026-08-28 제정)

문서는 **"누가 보는가"** 로 나눈다. 새 문서를 만들 때 이 규칙대로 배치한다.

## references/보고서재료/ — 사용자(사람) 열람용

보고서·발표를 쓰기 위해 사용자가 직접 읽는 문서만 둔다: 발견 사례 정리(사례노트), 구조적 문제(이슈) 정리, 벤치마크 요약 등.

- **파일명**: `YYMMDD_주제.md` — 작성일을 앞머리에 붙여 시간순 정렬되게 한다. 제목은 짧고 보자마자 알 수 있게(세부 키워드는 본문에).
- **문체**: 쉬운 말로, 보고서에 바로 인용할 수 있는 수준으로 다듬는다. "보고서에 쓸 때 핵심 문장" 요약 절을 붙이면 좋다.

## audit/ — AI 작업용: 실측·검증·운영 기록

마일스톤 실측(M*·v* 실측, 중간점검), 감사 기록, 상세 판정 원자료(표본채점 상세 등), 발주 문의 초안, 대사 작업 가이드 등 파이프라인 운영 문서.

## specs/ — AI 작업용: 구현 명세서·지시서

명세(Claude) → 구현(Opus) → 검증(Claude) 사이클의 지시 문서.

## references/ — 원본 자료·사람 열람 문서

환경부 가이드라인 원본(hwp), 발췌 이미지(`assets/`), 제출한 보고서(`reports/` — 중간·월간 보고서, 경과보고 — **git 미추적, 로컬 보관**), 그리고 위의 `보고서재료/`.

---

**판단이 애매하면**: "사용자가 보고서를 쓸 때 다시 열어볼 문서인가?" — 그렇다면 `references/보고서재료/`, 아니면 AI 측 폴더. 그래도 애매하면 사용자에게 물어본다.
