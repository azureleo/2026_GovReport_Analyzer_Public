# 고정 시각 표본 데이터셋 생성 및 무캐시 실험 절차

## 1. 목적

전체 515페이지를 매번 무캐시로 실행하면 비용과 시간이 커서 작은 변경의 효과를 빠르게 확인하기 어렵습니다. 고정 표본은 다음 질문에 답하기 위한 개발용 벤치마크입니다.

- 기존에 유실된 시각 객체가 수정 후 실제로 반환되는가
- 정상적으로 읽히던 객체가 회귀하지 않는가
- 장식, 사진 같은 음성 객체를 데이터로 잘못 기록하지 않는가
- 응답 누락과 수치 미판독을 성공으로 잘못 집계하지 않는가
- 개별 재시도 같은 복구 정책이 같은 입력에서 유의미한 개선을 만드는가

고정 표본은 전체 문서 정확도를 대신하지 않습니다. 표본에서 개선을 확인한 뒤에만 전체 무캐시 실행으로 외적 타당성을 확인합니다.

## 2. 핵심 원칙

### 원본 PDF를 기준 자료로 유지

페이지를 잘라 새 PDF를 만들면 페이지 번호, 앞뒤 문맥, 객체 좌표가 달라질 수 있습니다. 따라서 원본 PDF를 정답 기준으로 유지하고, 코드가 고정된 페이지 목록만 결정론적으로 렌더링합니다.

### 객체 ID를 표본 단위로 사용

페이지가 아니라 `요소ID`가 실험 단위입니다. 같은 페이지에 그래프가 두 개 있으면 이미지 파일은 공유하더라도 서로 다른 두 표본으로 평가합니다.

### 선택과 렌더링을 모델에 맡기지 않음

표본 선택, 페이지 렌더링, 해시 계산, 응답 누락 판정, 지표 계산은 모두 Python 코드가 수행합니다. VLM은 선택된 이미지 판독에만 사용합니다.

### 캐시 정확도 실험과 캐시 성능 실험을 분리

- 정확도 실험: `--cache-mode off`
- 캐시 성능 실험: 동일 결과를 확인한 뒤 별도 `--cache-mode on`

캐시 실행 결과는 재현성과 속도 검증에는 유효하지만 새 모델 응답의 정확도 표본으로 사용하지 않습니다.

## 3. 표본 구성

기본 선택 정책은 세 집단을 합칩니다.

1. **failure**: 최근 감사 결과가 `vision_유실`인 객체 전부
2. **positive_control**: `기록됨` 상태의 기대 추출 객체를 문서 앞·중간·뒤와 객체 유형별로 분산 선택
3. **negative_control**: 사람 인벤토리에서 `기대추출=N`인 객체를 같은 방식으로 분산 선택

난수는 사용하지 않습니다. 동일한 원본, 인벤토리, 감사 결과와 옵션이면 선택 ID와 데이터셋 지문이 같습니다.

현재 서울 개발 표본은 다음과 같습니다.

| 구분 | 객체 수 |
|---|---:|
| 과거 `vision_유실` | 7 |
| 양성 대조군 | 12 |
| 음성 대조군 | 5 |
| 합계 | 24 |
| 고유 페이지 | 23 |

## 4. 생성 산출물

`build` 명령은 다음 파일을 만듭니다.

| 파일 | 역할 |
|---|---|
| `manifest.json` | 원본 SHA256, 선택 정책, 렌더 조건, 데이터셋 지문 |
| `objects.jsonl` | 객체 ID, 페이지, 유형, 제목, 역할, 기대 상태, 이미지 해시 |
| `images/page_NNNN.png` | 원본 PDF에서 고정 DPI로 렌더한 페이지 이미지 |
| `inventory_snapshot.xlsx` | 표본 생성에 사용한 사람 인벤토리 스냅샷 |
| `audit_snapshot.json` | 실패 상태를 선택할 때 사용한 감사 결과 스냅샷 |
| `annotations_template.jsonl` | 사람 값 정답 입력 템플릿 |

원본 PDF 자체는 복사하지 않습니다. 대신 SHA256을 고정하며 실행 전 해시를 다시 확인합니다.

## 5. 데이터셋 생성

현재 작업 폴더에는 서울 원본이 `출력 결과 모음집` 아래 있으므로 다음처럼 실행합니다.

```powershell
py scripts/fixed_visual_sample.py build `
  "출력 결과 모음집\서울특별시_탄소중립계획.pdf" `
  --inventory "data\golden\서울_시각요소_인벤토리_v1.xlsx" `
  --audit "output\evaluation_20260801_233926\visual\visual_inventory_audit_20260802_083515.json" `
  --dataset-id "seoul-visual-fixed-v1" `
  --output-dir "output\fixed_visual_samples\seoul-visual-fixed-v1" `
  --positive-controls 12 `
  --negative-controls 5 `
  --dpi 144
```

생성 후 반드시 검증합니다.

```powershell
py scripts/fixed_visual_sample.py validate `
  "output\fixed_visual_samples\seoul-visual-fixed-v1\manifest.json"
```

검증은 원본 PDF, 객체 목록, 인벤토리 스냅샷, 감사 스냅샷, 모든 렌더 이미지의 SHA256을 확인합니다.

이미 실험을 시작한 데이터셋은 `--force`로 덮어쓰지 않습니다. 입력이나 선택 정책을 바꾸려면 `seoul-visual-fixed-v2`처럼 새 ID와 새 폴더를 만듭니다.

## 6. 사람 값 정답 확정

자동 지표만으로는 객체가 반환됐는지와 수치가 존재하는지는 확인할 수 있지만, 수치 자체가 맞는지는 판정할 수 없습니다. 값 정확도를 계산하려면 `annotations_template.jsonl`을 복사해 `annotations_confirmed.jsonl`을 만들고 다음 필드를 채웁니다.

```json
{
  "sample_id": "E019",
  "review_status": "confirmed",
  "expected_status": "extracted",
  "expected_title": "[그림 2-16] 공원 종류별 공원수",
  "expected_unit": "개",
  "expected_visual_rows": [
    {"항목": "어린이공원", "값": 1257, "단위": "개"}
  ],
  "notes": "원본 p71 직접 확인"
}
```

권장 확정 절차는 다음과 같습니다.

1. 검토자 1이 원본 PDF와 렌더 이미지를 대조해 값을 입력합니다.
2. 검토자 2가 숫자, 단위, 계열명, 연도를 독립 확인합니다.
3. 의견이 다른 셀만 원본을 다시 보고 합의합니다.
4. 확정 후 파일 해시를 기록하고 기존 버전을 수정하지 않습니다.

값 비교는 수치에 0.5% 상대 허용오차를 적용하고 문자열은 공백과 대소문자를 정규화합니다.

## 7. 소규모 무캐시 기준선 실행

현재 동작을 측정하는 기준선은 누락 개별 재시도를 끈 상태로 실행합니다.

```powershell
py scripts/fixed_visual_sample.py run `
  "output\fixed_visual_samples\seoul-visual-fixed-v1\manifest.json" `
  --provider codex `
  --model "gpt-5.6-luna" `
  --batch-size 4 `
  --cache-mode off `
  --retry-missing none `
  --output-dir "output\fixed_visual_samples\runs\baseline"
```

사람 정답이 확정됐다면 다음 옵션을 추가합니다.

```powershell
  --annotations "output\fixed_visual_samples\seoul-visual-fixed-v1\annotations_confirmed.jsonl"
```

Gemini API를 비교할 때는 표본과 나머지 조건을 그대로 두고 공급자와 모델만 바꿉니다.

```powershell

  "output\fixed_visual_samples\seoul-visual-fixed-v1\manifest.json" `
  --provider gemini `
  --model "gemini-2.5-pro" `
  --batch-size 4 `

  --retry-missing none `
  --output-dir "output\fixed_visual_samples\runs\gemini_pro_baseline"
```

## 8. 적응형 재시도 A/B 실험

개선안은 표본, 모델, 배치 크기, 프롬프트를 유지하고 누락 복구만 켭니다. `adaptive`는 실패한 객체만 절반씩 분할하고 마지막에 단일 객체로 격리합니다. 객체별 시도 상한 이후에도 응답이 없으면 결과 행을 제거하지 않고 `needs_review`로 보존합니다.

```powershell
py scripts/fixed_visual_sample.py run `
  "output\fixed_visual_samples\seoul-visual-fixed-v1\manifest.json" `
  --provider codex `
  --model "gpt-5.6-luna" `
  --batch-size 4 `
  --cache-mode off `
  --retry-missing adaptive `
  --max-split-depth 6 `
  --max-object-attempts 3 `
  --output-dir "output\fixed_visual_samples\runs\adaptive_retry"
```

`individual`은 기존 실험과의 호환을 위해 유지되며 누락 객체를 곧바로 한 번씩 재호출합니다. 운영 파이프라인과 같은 복구 정책을 평가할 때는 `adaptive`를 사용합니다.

모든 객체의 최종 상태는 `extracted`, `not_relevant`, `no_data`, `needs_review` 중 하나입니다. `results.jsonl`에는 시도 횟수와 종결 사유가, `batches.jsonl`에는 분할 깊이와 복구 경로가 기록됩니다. 두 실행의 `report.json`과 `report.md`를 비교합니다. VLM 응답은 확률적이므로 가능한 경우 각 조건을 3회 실행해 중앙값과 범위를 함께 보고합니다.

## 9. 근거 기반 병합 A/B

재시도 실험에서 저장한 `results.jsonl`을 그대로 재사용해 기존 병합과 근거 ID 병합만 비교합니다. 모델을 다시 호출하지 않으므로 두 결과의 차이는 병합 정책 차이입니다.

먼저 병합 주석 파일을 만듭니다.

```powershell
py scripts/fixed_visual_sample.py prepare-merge-annotations `
  "output\fixed_visual_samples\seoul-visual-fixed-v1\manifest.json" `
  --base "output\fixed_visual_samples\seoul-visual-fixed-v1\annotations_template.jsonl" `
  --output "output\fixed_visual_samples\seoul-visual-fixed-v1\annotations_merge.jsonl"
```

사람 검토자는 다음 필드를 확정합니다.

| 필드 | 의미 |
|---|---|
| `review_status` | 1차 원본 대조 초안은 `reviewed`, 독립 2차 검토까지 끝나면 `confirmed` |
| `expected_sheet` | 실제 값이 들어가야 할 시트명 또는 내부 키 |
| `expected_merge` | `accept`, `duplicate`, `needs_review`, `reject` 중 하나 |
| `expected_visual_rows` | 이미지·차트 자체에서 직접 판독되어야 하는 원시 정답 행 |
| `expected_merged_rows` | 최종 엑셀에 자동 병합되어야 하는 행의 핵심 셀 부분집합 |
| `fixture_evidence` | 실패 계약 재현용 `single`, `missing`, `multiple_ids`, `multiple_objects`, `object_not_extracted` |
| `fixture_baseline_rows` | 텍스트 중복·충돌을 재현할 기존 본문 행 |

`fixture_*`는 정답이 아니라 통제 입력입니다. 일반 양성 객체는 `single`, 실제 근거 누락 또는 복수 연결을 검사하는 표본만 해당 실패 유형으로 지정합니다.

```powershell
py scripts/fixed_visual_sample.py merge-ab `
  "output\fixed_visual_samples\seoul-visual-fixed-v1\manifest.json" `
  --results "output\fixed_visual_samples\runs\adaptive_retry\results.jsonl" `
  --annotations "output\fixed_visual_samples\seoul-visual-fixed-v1\annotations_merge.jsonl" `
  --output-dir "output\fixed_visual_samples\merge_ab\adaptive_retry"
```

`legacy_rows.jsonl`과 `evidence_rows.jsonl`은 실제 병합 행, `evidence_candidates.jsonl`은 근거 후보 전체, `needs_review.jsonl`은 자동 병합에서 격리된 후보입니다. `ab_report.json`과 `ab_report.md`는 오병합 감소, 병합 정밀도·재현율, 대상/실제 병합 시트 정확도, 정확 근거 매칭률, 복수 근거·전부 null·텍스트 충돌 격리율을 비교합니다. `reviewed` 또는 `confirmed` 주석이 없으면 운영 건수만 산출하고 정확도 지표는 비워 둡니다.

## 10. 지표 해석

| 지표 | 의미 |
|---|---|
| `response_coverage` | 표본 ID 중 실패 없이 응답이 돌아온 비율 |
| `expected_recall` | 기대 추출 양성 객체 중 `extracted`로 반환된 비율 |
| `negative_specificity` | 음성 객체 중 `not_relevant`로 거른 비율 |
| `classification_accuracy` | 양성과 음성 상태를 모두 맞힌 비율 |
| `numeric_value_coverage` | 수치가 있어야 하는 양성 객체 중 실제 숫자를 반환한 비율 |
| `value_accuracy` | 사람이 확정한 기대 셀과 일치한 비율 |

`response_coverage=1.0`만으로 정확하다고 판단하면 안 됩니다. 모델이 모든 객체에 답했어도 잘못된 숫자를 반환할 수 있으므로 `expected_recall`, `negative_specificity`, `numeric_value_coverage`, 확정 후 `value_accuracy`를 함께 봅니다.

## 11. 권장 합격 기준

개별 재시도 또는 객체별 출력 보장 변경을 전체 문서에 적용하려면 최소한 다음을 만족하는 것이 좋습니다.

1. 응답 커버리지가 기준선보다 낮아지지 않음
2. 7개 기존 실패 객체 중 복구 수가 증가함
3. 양성 대조군 리콜이 낮아지지 않음
4. 음성 특이도가 낮아지지 않음
5. 사람 확정 값 정확도가 낮아지지 않음
6. 추가 호출 수와 소요 시간이 허용 범위 안에 있음

표본에서 합격한 뒤 전체 무캐시 실행으로 82개 기대 시각 객체 리콜과 전체 골든셋 지표를 다시 확인합니다.

## 12. 현재 한계와 다음 단계

- 현재 표본은 서울 문서와 최근 감사 결과에 기반한 개발셋입니다. 다른 지자체 일반화는 별도 홀드아웃으로 확인해야 합니다.
- 현재는 사람 확정 객체 bbox가 없어 전체 페이지 렌더를 사용합니다. 잘못된 자동 크롭이 성능에 영향을 주지 않게 한 선택입니다.
- 향후 bbox를 사람이 확정하면 같은 객체에 `full_page`와 `object_crop` 변형을 만들고 입력 방식만 비교할 수 있습니다.
- 외부 사례 그래프도 시각 객체 인식에는 양성입니다. 모델 응답의 `scope=external_reference`로 구분하고 본문 시트 병합 단계에서 제외합니다.
- `annotations_template.jsonl`은 초안입니다. 값 정확도는 사람이 `review_status=confirmed`로 확정한 객체에 대해서만 계산됩니다.
