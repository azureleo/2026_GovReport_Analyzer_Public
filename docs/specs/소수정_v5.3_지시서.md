# v5.3 소수정 지시서 — 3지자체 실측 기반 일반화 수정 6건

> 대상 브랜치: `feat/v6-measurement-baseline`. 이 문서는 대화 맥락 없이 코드베이스만으로
> 구현 가능해야 한다. 모호하면 보수적(동작 불변) 선택.
> **핵심 원칙(사용자 지시)**: 이 프로젝트의 본질 문제는 지자체별 문서 비정형성이다.
> 수정은 특정 지자체 문서에 맞추는 패치가 아니라 **지자체 불변(invariant)**이어야
> 하며, 각 항목에 그 근거를 명시했다. 특정 문서 표기의 하드코딩 금지.

## 절대 제약 (기존과 동일 + 신규 게이트)

1. opt-in 기본값 변경·라우팅 로직 수정·프롬프트 문면 변경 금지. OrganizerAgent 순수
   Python 유지. 엑셀 시트 계약 불변.
2. 코드·주석·커밋 메시지 한국어. 새 외부 의존성 금지. 골든셋·출력 xlsx 수정 금지(읽기만).
3. 기존 테스트(현 176) 전부 통과 + 항목별 신규 회귀 테스트. 커밋별 통과. **push 금지.**
4. **3중 지자체 게이트(신규·필수)**: 최종 인수에서 다음을 실행해 결과를 보고에 포함한다.
   - 서울: `python scripts/score_against_golden.py output/서울_결과_gemini_v5.xlsx
     data/golden/서울특별시_골든셋_v1_초벌.xlsx --label v53게이트_서울` — 종합 리콜·값일치율
     무회귀(개선 기대).
   - 강원·경기: 기존 출력(`output/강원_결과_v6.xlsx`, `output/경기_결과_v6.xlsx`)을
     **재추출 없이** organizer 정제만 다시 통과시킬 방법이 없으므로, 각 xlsx의
     `19_검증리포트` "중복제거" 이슈 수와 03/04 시트의 빈 키 행 수를 수정 전후로
     비교하는 **오프라인 재정제 스크립트 실험**(아래 S7 산출물)으로 감소를 증명한다.

## S1. 부문 괄호 한정어 분리 — P0 (지자체 불변 근거: 가이드라인 2.3.2 표준 부문)

**증상(실측)**: GPT-5.5 실행이 `부문="에너지(연료 공급량 기준)"`처럼 괄호 한정어를
부문에 합쳐 넣어 03 시트 키가 가이드라인 구조(부문=에너지/세부부문=연료공급량기준)와
어긋난다(서울 03 리콜 0.15의 주원인).

**수정**: `organizer_agent`의 03/04 정제에서 부문 값이 `표준부문(한정어)` 형태이면
괄호 안을 세부부문으로 분리한다(세부부문이 비어 있을 때만 — 값 덮어쓰기 금지).
표준 부문 판별은 가이드라인 2.3.2 목록(에너지/산업공정 및 제품 생산/농업/LULUCF/
전력/열/폐기물)과 `config.SECTORS` 기반. 채점기는 organizer 별칭 재사용으로 자동 정합.

**수용**: "에너지(연료 공급량 기준)" → (에너지, 연료공급량기준) 단위 테스트 +
세부부문이 이미 있으면 불변 테스트.

## S2. IPCC 코드 프리픽스 정규화 — P1 (근거: 전 지자체 공통 국가 인벤토리 체계)

**증상(실측)**: `부문="1A 연료연소"`, `"4A 폐기물 매립(직접)"` 같은 IPCC 코드 수준
행이 부문 필드에 들어온다.

**수정**: 부문 값이 IPCC 코드 패턴(`^[1-4][A-D]?\d*` + 명칭)이면 코드 대분류를
가이드라인 부문으로 매핑(1→에너지, 2→산업공정 및 제품 생산, 3→농업, 4→폐기물 —
국가 인벤토리 공통 규약이라 지자체 불변)하고 원문 전체는 세부부문(비어 있을 때만)
+ `부문원문`에 보존한다. 매핑 불가 코드는 원문 유지(발명 금지).

**수용**: "1A 연료연소" → (에너지, 1A 연료연소) 테스트, "3C7 벼재배" → (농업, …).

## S3. 빈 배출유형/직간접구분 흡수 규칙 — P0 (근거: 3지자체 공통 실측 96/117/49건)

**증상(실측)**: 배출유형이 빈 행이 같은 (부문·세부부문·연도)의 채워진 행과 dedup
충돌을 일으킨다 — 서울 96·강원 117·경기 49건으로 **3곳 공통**.

**수정**: `_absorb_blank_detail_rows`(현재 세부부문 전용)를 일반화해 03의 `배출유형`,
04의 `직간접구분` 공란 행도 같은 규칙(다른 키 전 필드 일치 + 수치 충돌 없음 → 흡수,
충돌 시 기존대로 conflict 기록)으로 흡수한다. 흡수 필드 목록은 시트별 상수로 명시.

**수용**: 배출유형 공란 행이 동일 키 행에 흡수되는 테스트 + 수치 충돌 시 흡수 금지
테스트. 강원 xlsx 기준 빈 배출유형 충돌 수 감소 실측(S7 스크립트).

## S4. 중복 키 값 충돌의 결정론적 해소 보강 — P2 (근거: 3지자체 공통 1위 이슈)

**증상(실측)**: 같은 키 값 충돌이 서울 1,605·강원 737·경기 570건 — 현재 first-wins
후 conflict 기록. 채택 규칙이 배치 순서 의존이라 재현성이 약하다.

**수정(보수적)**: 충돌 시 채택 우선순위를 결정론화한다 — ① 값 채움 필드 수가 많은
행, ② 동률이면 출처페이지가 표 마커(`[표 N-N]`) 있는 페이지인 행(가이드라인 "표 우선
추출" 원칙), ③ 그래도 동률이면 기존 first-wins. 어떤 경우든 conflict 기록과
`데이터상태=conflicting`은 불변 — **조용한 해소 금지**, 채택 근거를 검증리포트
문구에 추가만 한다.

**수용**: 우선순위 각 단계 단위 테스트. 서울 골든 채점 무회귀(값일치율 하락 금지).

## S5. 코드성 텍스트 정규화 casefold — P2

**증상**: 직간접구분 매핑이 "DIRECT"(전대문자)를 놓친다(v5.2 검증 발견).

**수정**: `_DIRECT_INDIRECT_TYPE_MAP` 조회를 casefold 기반으로(맵 키를 소문자로 통일,
조회 전 casefold). 다른 유사 맵(_TYPE_MAP 등)도 동일 점검 — 값 자체는 불변.

## S6. 벤치마크 표본풀 붕괴 폴백 — P2 (도구 품질)

**증상(실측)**: 실측 벤치마크에서 무효 후보(claude quota 붕괴)가 교집합을 1개로
붕괴시켜 표본채점지가 무력화됐다.

**수정**: `scripts/vision_benchmark_workbook.py` 표본 선정에서 **기록 요소 수가
전체 기대치의 20% 미만인 후보는 교집합 계산에서 제외**(제외 사실을 표본채점지
머리말에 명기)한 뒤 교집합을 구성한다. 유효 후보가 1개뿐이면 그 후보의 기록 요소로
표본을 만든다(현행 폴백 유지).

## S8. 출력 실행 메타데이터 스탬프 — P1 (근거: 실측 사고 — 산출물 계보 식별 불가)

**증상(실측)**: 팀원 전달 파일이 구버전 산출물과 뒤바뀌었는데 출력만 봐서는 어떤
코드 버전·백엔드·모델이 만든 것인지 식별할 수 없었다(2026-07-08).

**수정**: `90_코드북` 시트에 `코드유형="실행정보"` 행들을 추가한다(컬럼·시트명 불변,
행 추가라 계약 안전): git 커밋 해시(가능하면), 백엔드/모델(텍스트·vision 각각),
실행 시각, 입력 파일명, 파이프라인 버전 문자열. git 정보를 얻을 수 없는 환경이면
"미상"으로 기록(실패해도 파이프라인은 계속).

**수용**: 출력 재로드 시 실행정보 행 존재·값 검증 테스트. CODEBOOK_SHEET_ENABLED=0이면
스탬프도 생략(기존 동작 존중).

## S7. 오프라인 재정제 실험 스크립트 — 게이트 도구 (신규 scripts/)

3중 게이트를 위해 `scripts/reclean_offline.py`를 신설한다: 기존 출력 xlsx를 읽어
시트별 행을 organizer의 정제 함수에 다시 통과시키고, 수정 전후의 dedup 충돌 수·
빈 키 행 수·행 수를 비교 리포트로 출력한다(LLM 0). 재추출 없이 정규화 개선 효과를
3개 지자체에서 실측하는 용도. 파이프라인 실행 경로와 무관한 독립 스크립트.
