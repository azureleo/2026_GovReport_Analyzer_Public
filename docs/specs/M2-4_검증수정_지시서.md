# M2-4+5 시각 병합 검증수정 지시서 (V1~V3)

> 대상: 86daa25 (`_apply_visual_labeled_merge` 계열, `agents/organizer_agent.py`).
> 근거 실측: `docs/audit/M2-4_활성화게이트_실측_20260710.md` — 플래그 on 실행에서
> 병합 0건(차단 1,491), G1 교정 실험에서도 G5 교차검증 발화 0건.
> 이 문서만으로 구현 가능해야 한다. 모호하면 보수적 선택.

## 절대 제약 (기존과 동일)

1. `VISUAL_MERGE_LABELED_ENABLED` 기본 False 불변. 기본 실행 출력 바이트 불변.
2. OrganizerAgent 무LLM. 기존 프롬프트 문면·라우팅·시트 계약 불변
   (프롬프트를 바꾸면 캐시가 깨진다 — V1은 organizer 쪽 해석 수정으로만).
3. 지자체 불변 — 조건은 메타데이터·스키마 키에만 의존.
4. 코드·주석·커밋 한국어, push 금지, 커밋별 테스트 통과.

## V1. G1 의미론을 파이프라인 관례에 맞춘다 (치명)

- 현상: image_agent 프롬프트(vision 지시 7번)는 축 추정값일 때만
  `fields.estimated=true`를 넣게 한다. 라벨 판독은 estimated 키가 아예 없다.
  현재 G1(`_visual_estimated_state(...) is not False`)은 명시적 false를 요구해
  실측에서 관찰값 1,491건 중 1,490건이 차단됐다.
- 수정: 기존 자동병합 경로(image_agent의 `fields.get("estimated") is True` 차단)와
  동일한 의미론으로:
  - 판독필드(fields)를 얻지 못한 관찰값 → 차단(사유 "G1 판독필드 없음").
  - `estimated`가 true(또는 "추정" 계열) → 차단(사유 "G1 축 기반 추정값").
  - 그 외(estimated 부재 포함) → G1 통과. `estimated=false` 명시도 당연히 통과.
- 실측 참고: 이 교정만 적용 시 병합 40건 발생(전부 02) — V2 없이는 저품질 병합이
  섞이므로 V1·V2는 같은 라운드에서 함께 커밋할 것(순서는 V1 → V2 권장, 커밋별
  테스트만 통과하면 됨).

## V2. 키 필드는 판독필드 실측값만 — 기본값으로 키를 만들지 않는다 (치명)

- 현상: `_visual_candidate_row`가 대상 시트 1차 키 필드를 기본값으로 채운다
  (02 지표범주="시각자료", 03 배출유형="직접배출", 05 시나리오="BAU",
  06 목표수준/목표범위 추론, 11 계획구분="온실가스감축대책"·재원구분="합계" 등).
  합성 키는 텍스트 행 키와 절대 일치하지 않아 G5 교차검증(M2-5)이 무력화되고
  ("생략"·"경고" 0건 실측), 저품질 행이 "텍스트 행 없음" 경로로 병합된다
  (병합 40건 중 골든 매칭 1건).
- 수정: `_VISUAL_MERGE_KEY_FIELDS`에 정의된 **1차 키 필드는 판독필드(fields) 또는
  관찰값의 명시 필드(연도·항목 등 image 스키마 필드)에서 온 값만** 인정한다.
  키 필드가 비면 기본값으로 채우지 말고 G3 차단(사유에 누락 필드 명기 — 현행 유지).
  - 항목→부문/지표명 승격(제목·항목 필드 사용)은 관찰값 명시 필드이므로 허용.
  - **비키 필드**(세부부문 등 absorb 대상, 단위, 출처 표기, 주요가정)는 기본값 허용.
  - 03 배출유형처럼 "판독필드에 있으면 쓰고 없으면 차단"으로 단순화. 06의
    항목값 기반 목표수준 추론("합계"→"총괄")은 관찰값 유래이므로 유지 가능하되,
    목표범위는 판독필드 없으면 차단.
- 주의: 지자체명은 키지만 파이프라인 전역 값이므로 예외(현행 유지).

## V3. 시각-시각 중복 병합을 방지한다 (중)

- 현상: `_visual_text_rows`가 visual_only 행을 제외하므로, 같은 키의 관찰값이
  2건이면 두 번째도 "텍스트 행 없음"으로 중복 병합된다(같은 차트가 두 번
  판독되는 경우 실재).
- 수정: 같은 키의 visual_only 행이 이미 있으면 병합하지 않고 "생략" 기록
  (사유 "동일 키 시각 행 존재"). 값이 0.5% 넘게 다르면 "경고" 기록(양쪽 값 명기,
  기존 행 유지 — 어느 쪽이 옳은지 결정 근거가 없으므로 보수적으로 첫 행 유지).

## 테스트 보강 (기존 테스트 파일에 추가)

1. **실스키마 G1**: estimated 키가 없는 판독필드(라벨 판독의 실제 형태) → G1 통과·
   병합. `estimated=true` → 차단. 판독필드 자체 부재 → 차단.
2. **키 기본값 차단**: 판독필드에 지표범주 없는 02 관찰값 → G3 차단(병합 0).
   판독필드에 지표범주가 있으면 그 값으로 병합되고, 같은 키의 텍스트 행이 있으면
   생략/경고가 발화하는지(G5 복구 확인).
3. **시각-시각 중복**: 같은 키 관찰값 2건 → 병합 1 + 생략 1.
4. 기존 테스트 중 "G1 라벨 기반 비추정 메타데이터 없음" 문구·`estimated: False`
   명시에 의존하는 부분은 새 의미론에 맞게 갱신(기본 False 불변 테스트는 그대로).

## 인수 절차

1. `python -m pytest tests/ -q` 전부 통과(커밋별). 기본 실행 출력 불변 재증명
   (`scripts/reclean_offline.py --json` 기본 지표 diff 0 또는 동등 증거).
2. 서울 캐시 재실측(실측 보고의 재현 명령, 비용 ~0): 병합/생략/경고/차단 분포와
   골든 채점(리콜·값일치율)을 `docs/audit/M2-4_활성화게이트_실측_20260710.md`에
   재실측 절로 추가할 수 있게 수치 보고. 기대: G5 생략·경고가 실제로 발화하고,
   병합 행의 골든 매칭 기여가 기본값 시절(40건 중 1건)보다 유의미하게 개선.
3. 활성화(기본 True) 결정은 여전히 사람 몫 — 이 라운드 범위 밖.
