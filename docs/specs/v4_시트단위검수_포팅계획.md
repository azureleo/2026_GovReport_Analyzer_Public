## Step 1 — `config.py` (하이브리드 블록, 103~131행 부근)

설정 4개 추가:

| 키 | 기본값 | 용도 |
|---|---|---|
| `HYBRID_SHEETWISE_FLOW_ENABLED` | `True` | 시트 단위 흐름 on/off (off면 기존 경로) |
| `HYBRID_PROGRESS_LOG_ENABLED` | `True` | 시트/배치별 진행 로그 |
| `HYBRID_ADJUDICATION_BATCH_SIZE` | `6` | 후보 몇 건씩 묶어 판정할지 |
| `HYBRID_ADJUDICATION_CONTEXT_CHARS` | `8000` | 묶음 판정 시 후보당 원문 문맥 길이 |

주의: 기본 `True`는 하이브리드 검수의 기본 동작을 바꾼다. `--legacy-hybrid-flow` 탈출구를 반드시 함께 제공.

## Step 2 — `agents/hybrid_review_agent.py` (작업량의 대부분)

### (a) 모듈 헬퍼 추가 — 팀원 코드 그대로 이식 가능
`_PROVIDER_ALIASES`, `_normalise_provider()`, `_command_available()`, `_backend_available()`
(gemini/openai는 API 키, codex/claude는 CLI 존재 여부, auto는 순차 확인),
`_effective_backend_model()` (provider가 codex/openai인데 모델명이 `gemini-*`면 provider 기본 모델로 교체),
`_default_adjudication()`, `_risk_flags()` (list/str 모두 수용). `typing`에 `Callable` 추가.

### (b) 백엔드 판별 교체
현재 355~368행 `_provider_available`과 531~537행 `_adjudication_provider_available`을
`_backend_available` 기반으로 교체. 판정 쪽 skip 사유는 `self._stats["adjudication"]["skipped"]`에 기록
(현재 호출부 666~677행에서 하드코딩된 사유 주입 → 그 줄 제거).

### (c) 호출부 보강
`_review_batch`(442~452행)와 `_adjudicate_candidate`(606~614행):
- `model`에 `_effective_backend_model` 적용
- `except llm_client.LLMCallError` → `except (llm_client.LLMCallError, RuntimeError)` 확장
  (codex/claude CLI 미설치 시 `_resolve_provider`의 RuntimeError로 파이프라인 전체가 죽는 것 방지)

### (d) 판정 로직 분해(리팩터)
현재 `adjudicate_and_merge`(666~764행)의 인라인 로직을 팀원 구조대로
`_prepare_candidate_for_adjudication` / `_record_adjudication_stats` / `_apply_adjudication`
3개 메서드로 분해하고, `adjudicate_and_merge`는 이를 재사용하도록 축소.
**동작 동일성이 합격 기준** (merge_log 스키마, stats 카운트 순서 불변).

### (e) 묶음 판정 신규
- `_adjudication_batch_prompt`: 후보 목록+candidate_id를 한 프롬프트에, "모든 candidate_id를 빠짐없이 판정" 지시
- `_normalise_batch_adjudications`: 응답 → candidate_id 매핑
- `_adjudicate_candidate_batch`: `temporary_backend`로 1회 호출, 실패 시 전원 needs_human 기본판정

⚠️ **팀원 버전에서 고칠 것**: `_normalise_batch_adjudications`의 위치 기반 폴백 — 팀원 코드는 응답 id가
안 맞으면 무조건 인덱스로 매칭해서, 모델이 일부 후보만 반환하면 판정이 밀려 오배정될 수 있다.
포팅 시에는 "응답 행에 id 필드가 아예 없고 응답 개수 == 후보 개수일 때만" 위치 매칭,
그 외 불일치는 `판정누락`(needs_human, 병합 안 됨)으로 fail-closed 처리.

### (f) `review_and_adjudicate_by_sheet` 신규
시트마다 `후보탐색(배치) → 묶음판정 → 즉시병합`을 끝내고 다음 시트로.
- `progress` 콜백 + `HYBRID_PROGRESS_LOG_ENABLED` 게이트, 시트별/묶음별 카운트 로그
- `target_sheets`/`routed_pages` 파라미터는 v5 폐루프 재도입 때 그대로 쓰이므로 시그니처 유지
- dedup key는 기존 `review()`와 동일한 `(대상시트, 후보유형, 후보행JSON)`
- 반환: `(final_data, review_candidates, merge_log)`

### (g) `report()` 확장
시트별 stat에 `판정/병합` 카운트 표기 (팀원 코드 그대로).

## Step 3 — `agents/supervisor.py`

- `_TIMING_ORDER`(33행~)의 "보조 모델 검수" 앞에 `"시트 단위 보조검수·병합"` 추가.
- STEP 3c/3d 블록(현재 321~371행 부근) 분기:
  - `HYBRID_SHEETWISE_FLOW_ENABLED=True` → `review_and_adjudicate_by_sheet` 1회 호출.
