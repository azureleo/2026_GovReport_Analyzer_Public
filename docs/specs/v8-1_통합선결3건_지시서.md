## S1 — 키 필드 공란 금지 (① — 03 `배출유형`·04 `직간접구분`)

원칙: **"빈칸 유지"는 값(수치) 필드에 한정한다. 행을 구분하는 키(축)
필드는 표 구조·캡션·용어에서 판정 가능하면 반드시 채우고, 채운 근거를
`derivation_type`으로 남긴다. 판정 불가면 빈칸 + 19_검증리포트 집계.**

### S1-1 표 객체 청크의 다단 헤더 보존 (원인 차단, 지자체 불변)

- `utils/document_objects.py::render_table_object_chunks`: 헤더 블록을
  `obj.rows[0]` 한 줄이 아니라 **선행 헤더 행 전체**로 반복한다. 헤더
  행 판정: 표 앞부분에서 "숫자 셀(연도 제외 정수·소수·%)이 하나도 없는
  연속 행"을 헤더로 본다(상한 3행, 최소 1행). 헤더 행에 연도(19xx/20xx)만
  있는 경우는 헤더로 취급한다(연도 헤더 표).
- 청크 본문은 헤더 행 제외 나머지를 `rows_per_chunk`로 나눈다(기존과
  동일). `table_to_markdown`은 헤더 행이 여러 줄이면 첫 줄만 헤더 구분선
  위에 두고 나머지 헤더 줄은 구분선 바로 아래에 **그대로** 둔다(정보
  무손실, 마크다운 문법 유지).
- 청크 머리에 `key_fields_hint` 한 줄을 추가한다(모든 시트 공통, 표 우선
  데이터 블록 안): "행 구분 필드(구분·유형·시나리오 등)는 위 헤더 행과
  caption·section에서 판정할 것". 지자체·시트 고유 문구 금지.
- 테스트: 2단 헤더 표(`구분|직접|간접` + `연도|2018|2019`)를 3청크로
  나눴을 때 모든 청크에 두 헤더 줄이 있음 / 1단 헤더 표는 기존 출력과
  동일 / 헤더 판정 상한 3행.

### S1-3 organizer 결정론 보완 (03 `배출유형`·04 `직간접구분`, 무LLM)

`_clean_emissions_management`·`_clean_emissions_regional`의 dedup 직전에
아래 순서로 빈 키 필드를 보완한다. 새 헬퍼 `_fill_emission_type_key(rows,
sector_field, subsector_field, key_field, municipality)` 하나로 두 시트를
처리한다(시트별 분기 최소화).

1. **관리부문/부문 자체가 흡수원**(`흡수원`·`LULUCF`·`산림` 정규화 동치) →
   `흡수`(03은 `흡수원`). `derivation_type=normalized`.
2. **에너지원 토큰 규칙**(세부부문·부문원문·관리부문원문 대상, 대소문자·
   공백 무시): `전력|전기|열|지역난방|스팀|steam|electricity` → 간접(03
   `간접배출`); `연료|연소|도시가스|LNG|LPG|석유|석탄|경유|등유|휘발유|
   fuel` → 직접(03 `직접배출`); `흡수원|LULUCF|산림|흡수` → 흡수.
   두 계열이 동시에 나오면(예: "전력+연료") 채우지 않는다.
   `derivation_type=inferred`.
3. **형제행 유일값 전파**: 같은 (지자체명, 관리부문/부문, 세부부문,
   출처페이지 집합 교집합 ≠ ∅) 행들 중 키 필드가 채워진 값이 **정확히
   한 종류**면 그 값으로 채운다. 두 종류 이상(가정 직접·가정 간접 병존)
   이면 채우지 않는다. `derivation_type=inferred`.
4. 남은 빈칸은 유지한다. 시트별로 `_remember_validation_issue(정보, 영역,
   "키 필드 공란", f"{key_field} 공란 {n}/{total}행 ({ratio:.1%}); 보완
   {filled_by_rule}건", "원문 표 헤더 확인")` 1건을 남기고,
   `pipeline_metrics`에 `key_field_blank_ratio.<sheet_key>.<field>`를
   기록한다(S2-4의 집계 함수와 공유).
- 기존 `_absorb_blank_key_rows`(빈 키 행을 동일 값의 키 행에 흡수)는 그대로
  두되 **S1-3 이후**에 실행되게 순서를 확인한다(보완된 행은 흡수 대상이
  아니어야 함).
- 지자체명·페이지 번호·문서 고유 라벨을 규칙에 넣지 않는다. 토큰 목록은
  에너지원 일반 명사로 한정한다.
- 테스트: 규칙 1~3 각각 / 두 계열 동시 등장 시 미보완 / 형제 두 종류 시
  미보완 / 골든 04의 (관리부문, 세부부문)→직간접구분 표를 픽스처로 넣어
  **규칙 2·3이 골든과 모순되는 값을 만들지 않음**(`가정(전력)`→간접,
  `가정`→미보완 또는 형제 유일값) / 검증리포트 1건·metric 기록.

### S1-4 05·09 키 필드 — 보완은 하지 않고 집계만

## S2 — 과잉 추출 격리를 03·04·05·09로 확대 (②)

### S2-1 자동 재분류 기본값 해제 (계약 충돌 제거)

- `config.SEMANTIC_ROUTING_AUTO_RECLASSIFY` 기본값 **False**. 검증
  (`오배치의심` 플래그·검증리포트·metrics)은 그대로 켠다. `.env.example`
  주석에 이유를 남긴다: "03/04의 전망 연도행 이동은 골든 계약(v7-4, 05에
  축 필드 없음)과 충돌 — 키 계약 명세 라운드에서 05 축 필드 신설 후 재검토".
- 켰을 때의 `_forecast_row` 시나리오 값 `"기준전망"`은 `"BAU"`로 바꾼다
  (enum 준수; `_FORECAST_SCENARIO_MAP`의 BAU 계열과 일치).
- 테스트: 기본값에서 03/04 미래연도 행이 이동되지 않고 `오배치의심`으로만

### S2-2 추출 원천 태깅과 표 우선 병합 (이중 추출 차단)

- 자식 태스크가 만든 행에 내부 필드 `_추출원천`을 붙인다: 표 객체 청크
  자식 → `"표객체"`, 본문 청크 자식 → `"본문청크"`, 그 외 → 없음. 부여
  위치는 `_run_sheet_children`/`_run_cluster_children`에서 자식 결과를
  병합하기 직전(자식 dict의 `object_id` 접두로 판별: 표 객체 id vs
  `p{n}_text`).
- `ExtractorAgent._merge_rows`: 같은 `stable_entity_id`의 충돌 쌍이
  `표객체` vs `본문청크`이고 **같은 페이지 집합**이면 `본문청크` 행을 버리고
  `run_state.record_conflicts`에 `resolution="table_object_preferred"`로
  남긴다(다른 조합은 현행대로 둘 다 보존 — "충돌값 자동선택 금지" 원칙은
  **원천이 같은 표일 때만** 예외). `merge_rows_stably`에 선택적 인자
  `prefer=("표객체", "본문청크")`를 추가해 구현하고 기본 인자에서는 동작
  불변.
- `_추출원천`은 `_INTERNAL_DEDUP_FIELDS`·`_VOLATILE_ROW_FIELDS`에 등록해
  엑셀·해시·체크포인트 비교에서 제외한다(`_strip_dedup_internal_fields`
  경유 확인).
- 테스트: 표객체·본문청크 동일 엔터티 충돌 → 표객체만 남고 conflict
  기록 / 페이지가 다르면 둘 다 보존 / 내부 필드가 엑셀 헤더·row_id에
  나타나지 않음.

### S2-3 API 백엔드의 배치 문자 상한 분리

- `EXTRACTION_MAX_BATCH_CHARS`는 로컬 에이전트(codex/claude) 전용으로
  두고, gemini/openai 백엔드는 새 설정 `EXTRACTION_MAX_BATCH_CHARS_API`
