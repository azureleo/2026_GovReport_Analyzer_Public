> 후속 명세다. 대화 맥락 없이 이 문서와 코드베이스만으로 구현 가능해야 한다.

## 0. 배경

v4는 배치 원장(ledger), 부분 실패 허용 병렬 실행(`parallel_map_collect`), JSON 파싱
재시도, dedup 정규화, 커버리지 기반 GapFill, 출처페이지, 검증리포트 확장, A/B 하네스,
텔레메트리를 도입했고 테스트 40개가 통과한다. 검수에서 다음 3가지 결함이 확인됐다.

1. **[중요] quota 발생 시 런 전체가 죽는 복구 공백.** v4가 `_retry_local_call`의
   quota 대기-재개 분기를 통째로 삭제해 `LLMQuotaExceededError`가 즉시 전파된다.
   `parallel_map_collect`도 quota만은 수집하지 않고 전파하며, Supervisor는 GapFill
   단계(STEP 3b)에만 quota catch가 있다. 결과: **추출(STEP 2)·이미지(STEP 2b) 중
   quota가 발생하면 그때까지 성공한 배치 결과까지 전부 버려지고 엑셀도 안 나온다.**
   (v3는 최대 6시간 대기 후 완주했으므로 이 시나리오에선 후퇴다.)
   부산물로 `utils/llm_client.py`의 `_parse_quota_reset_seconds`가 죽은 코드로 남았다.
2. **[제거 대상] 정체불명 죽은 코드 3종 + 스테일 테스트.** `config.SUMMARY_ITEMS`,
   `agents/organizer_agent.py`의 `_apply_context_summary_evidence`,
   `agents/supervisor.py`의 `_build_summary_context`는 파이프라인 어디서도 호출되지
   않는다. 존재하지 않는 `"summary"` 시트를 참조하고 특정 문서(서울) 전용 하드코딩
   regex("30% 감축", "줄어든 X천톤CO₂eq", 2035/2033 분기)를 담고 있다. 유일한 참조는
   옛 v6 커밋(126c13a)에서 온 스테일 테스트 `tests/test_supervisor_summary_context.py`
   뿐이며, v4 구현이 "기존 테스트 통과" 제약을 지키려고 이 죽은 함수들을 만들어 맞춘
   것으로 판단된다.
3. **[경미] JSON 파싱 성공 판정이 과도하게 좁다.** `llm_client._json_parse_ok`가
   (a) 최상위 JSON 배열을 실패로 간주하고, (b) 코드펜스로 감싼 `{}` 응답도 실패로
   간주해 불필요한 재시도 호출을 1회씩 유발한다.

## 1. 절대 제약 (v4 명세와 동일, 위반 금지)

1. **opt-in 플래그 기본값 변경 금지**: `EXTRACTION_SHEET_CLUSTERING`(False),
   `ROUTE_DROP_UBIQUITOUS_STRONG`(False), `HYBRID_REVIEW_ENABLED`(False).
   라우팅 샤프닝 검증은 별도 트랙에서 진행 중이므로 라우팅 점수/선택 로직
   (`_ubiquitous_strong_keywords`, `_score_page_for_sheet`, `_route_pages_by_sheet`)을
   **건드리지 마라** (v3에서 진행 중인 라우팅 검증 결과의 이월 가능성을 유지해야 한다).
2. OrganizerAgent는 결정론적 순수 Python 유지(LLM 호출 금지).
3. 엑셀 17시트 계약 유지(시트명·기존 컬럼 이름/순서 불변).
4. 코드·주석·로그는 한국어, 기존 스타일 유지. 새 외부 의존성 금지.
5. 튜닝값은 `config.py` + 환경변수 오버라이드(기존 `_env_*` 헬퍼).
6. 기존 테스트는 WP-B에서 명시적으로 삭제하는 1개 파일을 제외하고 계속 통과해야 하며,
   각 WP는 자체 테스트를 추가한다.
7. LLM 캐시 키 호환 유지(프롬프트 문면 불변 — 이번 명세는 프롬프트를 바꾸지 않는다).

## WP-A. quota 복구 공백 해소 (P0)

목표 동작(설계 원칙): **quota는 "짧게 기다려 회복을 시도하고, 안 되면 해당 배치만
실패로 기록하고 파이프라인은 부분 데이터로 완주"**한다. 어떤 경우에도 이미 성공한
배치 결과를 버리지 않는다.

### A-1. `_retry_local_call`에 유계(bounded) quota 대기-재개 복원 (`utils/llm_client.py`)

v2/v3에 있던 quota 대기 분기를 복원하되, v4의 짧은 기본값을 그대로 쓴다:

```python
except LLMQuotaExceededError as exc:
    consecutive_timeouts = 0
    if not getattr(config, "LLM_QUOTA_WAIT_ENABLED", True):
        raise
    parsed = _parse_quota_reset_seconds(str(exc))          # 죽은 코드 부활
    poll = int(getattr(config, "LLM_QUOTA_WAIT_POLL_SECONDS", 120))
    wait = (parsed + 30) if parsed is not None else poll
    cap = int(getattr(config, "LLM_QUOTA_WAIT_MAX_SECONDS", 1800))
    if quota_waited + wait > cap:
        logger.error(...)   # 누적 대기 상한 초과
        raise               # LLMQuotaExceededError 그대로 전파 (LLMCallError로 바꾸지 말 것)
    quota_waited += wait
    attempt -= 1            # quota 대기는 일반 재시도 예산을 소모하지 않는다
    _inc_stat("retries")
    logger.warning(...)     # 대기 후 자동 재개 안내 (기존 v3 문구 참고)
    _sleep_with_heartbeat(wait, label)
```

- 상한 초과 시 **반드시 `LLMQuotaExceededError` 타입 그대로** 전파한다. 상위
  (`parallel_map_collect`, Supervisor)의 quota 분기 판단이 타입에 의존한다.
- `_sleep_with_heartbeat`가 이미 `quota_wait_seconds` 텔레메트리에 가산하므로 추가
  계측은 불필요하다.
- 이 경로는 로컬 에이전트(codex/claude) 전용이다. gemini 경로(`_call_gemini_*`)는
  자체 재시도 후 quota를 던지는 기존 구조를 유지한다(변경 금지).
- config 주석을 실제 동작("명시적 quota도 짧게 대기 후 재개, 상한 초과 시 배치 실패로
  격리")에 맞게 갱신한다.

### A-2. `parallel_map_collect`의 quota 격리 (`utils/parallel.py`)

현재: quota 발생 시 `shutdown(cancel_futures=True)` 후 **재전파** → 완료된 결과까지 유실.

변경: quota도 수집하되, **남은 작업은 시작하지 않는다**.

- 어떤 항목이 `LLMQuotaExceededError`로 실패하면:
  1. 그 항목의 결과는 `(None, exc)`로 기록한다.
  2. `executor.shutdown(wait=False, cancel_futures=True)`로 **아직 시작 안 한 작업을
     취소**한다(quota 상태에서 어차피 전부 실패할 호출을 반복하지 않기 위해).
  3. 취소된/미완료 항목들의 결과는 `(None, exc)`(같은 quota 예외 또는
     `LLMQuotaExceededError("선행 배치 quota로 건너뜀")`)로 채운다.
  4. 이미 완료된 항목의 결과는 그대로 보존해 **정상 반환**한다(raise 하지 않는다).
- 이미 실행 중(취소 불가)인 작업의 결과 처리: `as_completed` 루프가 shutdown 후에도
  완료를 수거할 수 있으면 성공 결과로 기록하고, 구현이 복잡하면 실패로 채워도 된다
  — 단 docstring에 어느 쪽인지 명시한다.
- 순차 폴백 경로도 동일 의미론: quota 발생 시 해당 항목부터 나머지를 `(None, exc)`로
  채우고 반환한다.
- docstring의 "LLMQuotaExceededError는 즉시 전파" 문구를 새 의미론으로 갱신한다.
- **호출부는 수정 불필요**: extractor/gap_fill/image 는 이미 `(결과, 예외)` 튜플을
  받아 실패를 원장(`call_fail`)에 기록한다. quota 실패 배치도 자동으로
  19_검증리포트의 "원장 호출실패" 항목에 나타난다.

### A-3. 지자체명 추출의 quota 폴백 (`agents/extractor_agent.py`)

`_extract_municipality_name`은 병렬 밖의 단일 `call_text`라 A-2의 보호를 받지 못하고,
현재 `except LLMQuotaExceededError: raise`로 STEP 2 전체를 죽인다.

- quota 시에도 `LLMCallError`와 동일하게 **정규식 폴백(`_municipality_from_text`)으로
  진행**하도록 바꾼다(전용 예외 분기 삭제). 폴백 실패 시 "알 수 없음" 반환 — 기존
  LLMCallError 경로와 동일.

### A-4. Supervisor 최후 안전망 (`agents/supervisor.py`)

A-1~A-3 적용 후 STEP 2/2b에서 quota가 새어 나올 경로는 사실상 없지만, 방어적으로:

- STEP 2(텍스트 추출)와 STEP 2b(이미지 분석)를 각각 `try/except
  llm_client.LLMQuotaExceededError`로 감싼다. catch 시:
  - STEP 2: `raw_data = dict(extractor._raw_results)`가 아니라 — 내부 속성 접근 대신
    `ExtractorAgent`에 `partial_results()` 공개 메서드(또는 `raw_results` 프로퍼티)를
    추가해 그때까지 누적된 `_raw_results`의 얕은 사본을 받는다. 경고 로그를 남기고
    파이프라인을 계속 진행한다.
  - STEP 2b: 이미지 병합 없이 기존 `raw_data`로 계속 진행 + 경고 로그.
- 기존 GapFill quota catch(STEP 3b)는 그대로 둔다.

### 수용 기준 / 테스트 (`tests/test_quota_resilience.py` 신규)

`time.sleep`을 monkeypatch하고 config 상한을 작게 설정한 뒤:

1. `_retry_local_call`: quota 1회 후 성공하는 fn → 대기 1회 발생, 최종 성공,
   `get_llm_stats()['quota_wait_seconds'] > 0`.
2. `_retry_local_call`: 계속 quota인 fn → 누적 대기가 cap 초과 시
   `LLMQuotaExceededError` 타입으로 전파.
3. `parallel_map_collect`: 4개 항목 중 2번째가 quota → 반환값 길이 4, 1번째 완료
   결과 보존, 실패 항목들은 `(None, LLMQuotaExceededError)`, **raise 없음**.
4. `_extract_municipality_name`: `call_text`가 quota를 던져도 정규식 폴백으로
   지자체명 반환(예외 전파 없음).
5. 통합: 추출 배치 중 quota mock 상태에서 파이프라인(또는 extract→organize 경로)이
   완주하고, 검증리포트에 해당 배치의 "원장 호출실패" 항목이 남는다.

## WP-C. JSON 파싱 성공 판정 보정 (P2)

`utils/llm_client.py`의 `_json_parse_ok`를 다음 의미론으로 교체한다:

```
성공 조건:
- 원문(raw)이 공백뿐이면 실패.
- parse_json 결과가 dict 또는 list이고 비어 있지 않으면 성공.
- parse_json 결과가 빈 dict/빈 list인 경우: 코드펜스 제거(_strip_code_block) 후
  본문이 정확히 "{}" 또는 "[]"이면 성공(모델이 의도적으로 빈 결과를 반환한 것),
  아니면 실패(파싱이 내용을 잃었을 가능성).
```

- 기존 `_strip_code_block`을 재사용한다(중복 구현 금지).
- `call_text_json`/`call_vision_json`/`call_vision_batch_json`의 재시도 흐름은 그대로.
- 호출부(extractor/gap_fill/image)는 이미 `isinstance(parsed, dict)`를 추가로
  확인하므로 list 성공 판정이 새 동작을 만들지 않는다(불필요 재시도 제거 효과만).

### 수용 기준 / 테스트 (`tests/test_llm_json_retry_stats.py`에 케이스 추가)
- ` ```json\n{}\n``` ` 응답 → 재시도 없이 성공(ok=True).
- `[{"a": 1}]` 응답 → 재시도 없이 성공.
- `이것은 JSON이 아님` 응답 → 재시도 1회 후 ok=False (기존 동작 유지 확인).
