# M2-3 vision 교차 프로바이더 벤치마크 구현명세서

> 기준 문서: `docs/specs/프로젝트_마일스톤_로드맵.md` §M2-3. 대상 브랜치: `feat/v6-measurement-baseline`.
> 이 문서는 대화 맥락 없이 코드베이스만으로 구현 가능해야 한다. 모호하면 보수적(동작 불변) 선택.
> 배경(실측): M1 기준선에서 시각 리콜이 vision 백엔드에 따라 codex 0.988 vs
> gemini flash-lite 0.707로 갈렸다(`docs/audit/M1_기준선_잠정_20260706.md`). 이미지
> 추출·triage·필터 유실은 0 — 병목은 vision 판독뿐이다. 후보 모델들을 같은 잣대로
> 채점해 vision 스테이지 기본값 결정의 근거 표를 만든다. **교차 프로바이더 비교가
> 요구사항이다(gemini 내부 비교만으로 축소 금지 — 사용자 지시).**

## 절대 제약

1. **파이프라인 코드 무변경.** 신규 코드는 `scripts/benchmark_vision.py`와 테스트뿐.
   `STAGE_PROVIDER_VISION`/`STAGE_MODEL_VISION` env 오버라이드(기존 v5 인프라)만 사용한다.
2. **기본값 변경 금지.** 벤치마크는 근거 표를 만들 뿐, vision 기본값 채택은 리포트를
   보고 사람이 별도 커밋으로 결정한다.
3. **텍스트 스테이지 재호출 0 보장.** 모든 변형 실행은 `LLM_CACHE_DIR=.cache/llm_responses_gemini_v5`
   를 공유하고 텍스트 백엔드를 기본(gemini)으로 고정한다 — 텍스트 호출은 전부 캐시
   히트여야 하며, 실행 후 원장/로그에서 텍스트 신규 호출 수가 0에 가까움을 확인해
   리포트에 기록한다(잔존 503 배치 8개 재시도는 허용).
4. 채점(감사·집계)은 LLM 호출 0. vision 호출은 파이프라인 경유만.
5. 코드·주석·로그·리포트·커밋 메시지 한국어. 새 외부 의존성 금지.
6. 기존 테스트 165개 전부 통과 + 신규 회귀 테스트. 커밋별 테스트 통과. **push 금지.**

## 범위 밖

- vision 기본값 실제 변경(제약 2). 이미지 전처리(해상도·크롭) 튜닝 — 승자 결정 후 후속.
- 판독 값의 전수 정답 채점 — 시각 유래 골든이 아직 없다. 아래 §4의 표본 절차로 대체.
- M2-2(텍스트리스 VLM 우회), M2-4(병합 완화), M2-5(교차 검증).

## 1. 후보 매트릭스

| 태그 | STAGE_PROVIDER_VISION | STAGE_MODEL_VISION | 조건 |
|---|---|---|---|
| `flashlite` (기준) | gemini | (기본 = gemini-2.5-flash-lite) | 이미 캐시에 있음 — 재실행 시 vision도 캐시 히트, 비용 0 |
| `flash` | gemini | gemini-2.5-flash | |
| `pro` | gemini | gemini-2.5-pro | 비용 최대(입력 단가 ~12×) — 이미지 배치 그대로, 사전 추정치 리포트 기재 |
| `claude` | claude | (기본) | claude CLI 필요(설치돼 있음). 사용자 구독 quota 소모 — 실행 전 로그에 고지 |
| `codex` | codex | (기본) | codex CLI 필요(설치돼 있음). 기존 0.988은 풀-codex 실행이었으므로, 텍스트=gemini 고정 조건에서 재측정해 공정 비교 |
| `openai` | openai | (기본 = OPENAI_MODEL) | **OPENAI_API_KEY 있을 때만**. 없으면 스킵하고 리포트에 "키 부재로 미측정" 명기(조용한 누락 금지) |

## 2. 오케스트레이터 `scripts/benchmark_vision.py`

```
python scripts/benchmark_vision.py <source.pdf> \
    --inventory data/golden/서울_시각요소_인벤토리_v1.xlsx \
    [--candidates flashlite,flash,pro,claude,codex,openai] \
    [--out-dir output/vision_bench] [--skip-run 태그,...]
```

동작(후보별 순차 — vision 동시성은 파이프라인 내부 `VISION_WORKERS`에 맡긴다):

1. **실행**: `LLM_CACHE_DIR` 공유 + 해당 태그의 STAGE_* env로
   `python main.py <source> -o {out-dir}/서울_vision_{태그}.xlsx` 서브프로세스 실행.
   출력이 이미 존재하면 기본은 재사용(`--force-run`으로 재실행) — 반복 실행 안전.
   실행별 소요 시간·(로그에서 집계 가능한) vision 호출 수를 기록한다.
2. **채점**: `scripts/audit_visual_inventory.py audit`를 서브프로세스로 실행해
   리콜·상태분포를 얻고, 출력 xlsx의 `16_시각자료목록`에서 보조 지표를 직접 집계:
   행 수, `데이터포함여부=TRUE` 비율, `디지타이징필요=FALSE` 비율(=자동 신뢰 비율).
3. **표본 채점 준비**(§4): 모든 후보가 공통으로 기록한 요소 중 N=15개(그래프 위주,
   페이지 분산)를 뽑아, 후보별 해당 요소의 `추출값요약`을 나란히 놓은
   `{out-dir}/표본채점지.md`를 생성한다(정답 판정은 사람/Claude 후속 — 스크립트는
   비교지만 만든다).
4. **리포트**: `{out-dir}/M2-3_vision벤치마크_{timestamp}.md` + 동일 구조 json.
   - 후보별 표: 리콜 / vision_유실 / 기록 행수 / 데이터포함 비율 / 실행 시간 /
     신규 vision 호출 수 / (스킵 시) 사유
   - 요소유형별(그래프/이미지/이미지표) 리콜 분해
   - 유형별 유실 요소 ID 목록(후보 간 대칭 차이 — "A만 놓친 요소" 식별)
   - 텍스트 스테이지 캐시 히트 확인(제약 3 증빙)
   - 결론 문단은 쓰지 않는다 — 숫자와 차이만. 판정은 사람이 한다.

## 3. 채점 지표 정의

- **1차: 인벤토리 리콜** — `audit` 리콜(기대추출 82 기준). 후보 간 동일 인벤토리·동일
  기준이므로 직접 비교 가능.
- **2차: 커버리지 품질** — 데이터포함 비율(값을 실제로 읽어냈는가),
  요소당 기록 행수(과소/과다 판독 신호).
- **3차(후속·사람): 표본 값 정확도** — §2-3의 표본채점지로 원문 대조. 이 명세의
  구현 범위는 채점지 생성까지.

## 4. 표본 선정 규칙 (표본채점지)

- 모든 후보가 "기록됨"인 요소 교집합에서 그래프 ≥10개 + 도식 ≤5개, 페이지 구간
  (전반/중반/후반) 각 ≥3개. 교집합이 15 미만이면 있는 만큼 쓰고 리포트에 명기.
- 각 표본 행: 요소ID, 페이지, 제목, 후보별 추출값요약(원문 그대로), 판정 빈칸.

## 5. 테스트 (`tests/test_benchmark_vision.py`)

파이프라인 실행 없이 순수 로직만(서브프로세스는 mock):

1. 후보 매트릭스 → env 구성이 정확한지(태그별 STAGE_PROVIDER/MODEL 값).
2. OPENAI_API_KEY 부재 시 openai 후보가 스킵되고 사유가 결과에 남는지.
3. `--skip-run`/기존 출력 재사용 분기.
4. 16 시트 보조 지표 집계(합성 워크북 — 데이터포함 비율 등).
5. 표본 선정 규칙(교집합·유형·페이지 분산 조건, 15 미만 폴백).
6. 리포트에 후보별 필수 컬럼과 "미측정 사유"가 렌더링되는지.
