## 0. 배경

이 프로젝트의 목표는 환경부 가이드라인(`carbon_guideline.md`, 원문 HWP에서 구조화)을
기준으로 지자체 탄소중립 계획 문서에서 데이터를 추출해 17시트 엑셀로 정규화하고,
**사람의 수동 입력·수동 검증을 파이프라인 하나로 대체**하는 것이다.

v4/v4.1로 실행 안정성(원장·부분실패 허용·quota 격리)과 근거 추적(출처페이지·검증리포트
확장)은 확보됐다. 검수에서 확인된 남은 구조적 격차:

1. **가이드라인이 형식적으로만 소비된다.** `GuidelineAgent.get_all_prompts()`는
   carbon_guideline.md를 키워드 점수로 뽑은 **500자 스니펫 최대 3개**로만 프롬프트에
   붙인다(`_compact_text`가 개행을 뭉개 표 구조 소실). 실제 스키마 충실도는
   `extractor_agent._SHEET_CONFIGS` 하드코딩에 의존하며, md를 고쳐도 파이프라인에
   거의 반영되지 않는다. 또한 `guideline_agent.py`에 v6 이전 레거시(구 4~5시트
   `GUIDELINE_SCHEMA`, `document_meta→vehicle_by_use` 같은 `_EXTRACTOR_KEY_MAP`,
   미사용 `get_extraction_prompt`)가 잔존한다.
2. **단일 모델 파이프라인.** 대량 추출·정밀 차트 판독·의심 행 재검수는 요구 특성이
   다른데 전부 같은 백엔드로 돈다. 기존 `HYBRID_REVIEW_ENABLED` 인프라는 전량 재검수
   방식이라 비싸고 꺼져 있다.
3. **가이드라인 부록 참조 사전 미활용.** 부록4 사업목록 507개(부문별 연번 전수 검증
   완료)와 부록3 감축원단위 114개가 원문 덤프에 텍스트로 존재하는데, 사업명↔표준부문
   매칭(§10.1 `matching_confidence`)과 원단위 검증에 쓰이지 않는다.
4. **행 단위 데이터상태(§6.4) 부재.** reported/visual_only/calculated/conflicting 구분이
   없어 사람이 어떤 행을 재확인해야 하는지 알 수 없다.
5. **organizer 코드북 소수 누락**: 전망방법 2종, 부문 원문 표기 미보존(§11-8),
   관리권한 시트의 `"전력"→"전환"` 오분류 위험.
6. **실측 검수(서울 v3 폐루프)에서 확인된 계통 오류.** Codex 폐루프 검수
   (`서울_시트폐루프_Codex검수.xlsx`, 후보 798건/5개 수치 시트)에서 다음이 실제로
   관찰됐다 — 원문 PDF 표본 대조로 근거 페이지·수치의 정확성을 확인함:
   - **관리번호 이중 넘버링 오염**: 서울 원문은 제3장 "기존 계획의 평가"(p148~160)와
     본계획(p201~ 표 5-5, 제6장 사업카드)이 **같은 관리번호를 서로 다른 사업에**
     부여한다(예: p149 M1-2=청소차량 전환 vs p253 M1-2=전기차 보급 촉진). 기본 추출본은
     두 넘버링을 섞었고, 검수자(Codex)도 구계획 목록을 기준 삼아 양방향 오탐을 냈다. → WP7
   - **관리부문 "에너지"→"전환" 오변환 실증**: p109 표 2-27의 "에너지 44,173(2005)"이
     최종 04 시트에 `관리부문="전환"`으로 저장됨. → WP6-3의 실측 근거
   - **폐루프 정합 결함**: 병합로그 '반영' 251건 중 235건은 최종 시트에 존재하나,
     10건은 organizer 정규화로 항목명이 변형되고 **6건(06_감축목표 5건)은 병합 후
     dedup에 소멸**해 로그와 시트가 불일치. 06 dedup 키가 목표범위(인벤토리 기준)를
     무시해 GIR 기준과 자체 인벤토리 기준 행이 충돌·소실됨. → WP3-B·WP6-4
   - **후보 생성 ↔ 병합 게이트 dedup 키 불일치**: '누락후보'(기본본에 없음) 686건 중
     283건이 병합 단계에서 '기본본중복'으로 차단 — 두 단계가 "이미 있음"을 서로 다른
     키로 판정. accept+high인데 보류된 173건 중 156건이 이 사유. → WP3-B
   - **00_문서메타 중복 3행**(기준연도 null/2018, 목표연도 표기 3종 병존) → WP6-5

가이드라인 md 자체는 원문 대조 검증(32항목 + 이미지 대조, 표10 포함)에서 **검증 완결**
— 일치 31 / 불일치 1(합성 목차) / 외부지식 보충 1(공유재산 분류) / 미확인 0.
남은 것은 WP1의 주석·각주 반영뿐이다.

**폐루프 이력**: 팀원이 v3 계열(커밋 `b73ac1c`, origin/perf/optimization-v3)에서
"시트별 폐루프 검수 모드"를 실험 구현했다 — 시트마다 `추출 → 정제 → 보조검수·판정·병합`을
닫고 다음 시트로 넘어가는 경로. 이 중 **시트 단위 검수+묶음 판정+진행 로그**
(`HybridReviewAgent.review_and_adjudicate_by_sheet`)는 이미 v4에 포팅 완료됐고
(2026-07-04, `docs/specs/v4_시트단위검수_포팅계획.md` 참조), 서울 소형 PDF 스모크로
sheetwise/legacy 양 경로가 검증됐다. **폐루프 전체**(추출까지 시트 단위로 닫는 실행
경로)는 v4의 병렬 추출(`parallel_map_collect`) 구조와 충돌해 보류됐으며, 본 명세의
WP8이 이를 "시트는 순차, 시트 내 배치는 병렬"로 재설계해 도입한다. 팀원 구현에서
확인된 결함(전역 판정 상한이 시트당으로 리셋, 병합-정제 순서로 인한 로그·시트 불일치)은
WP8·WP3-C에서 구조적으로 교정한다.

## 1. 절대 제약 (이전 명세와 동일 + 추가)

1. **opt-in 플래그 기본값 변경 금지**: `EXTRACTION_SHEET_CLUSTERING`(False),
   `ROUTE_DROP_UBIQUITOUS_STRONG`(False), `HYBRID_REVIEW_ENABLED`(False),
   `SHEET_CLOSED_LOOP_ENABLED`(False — WP8 신규, 실험 경로).
   라우팅 점수/선택 로직(`_ubiquitous_strong_keywords`, `_score_page_for_sheet`,
   `_route_pages_by_sheet`) 수정 금지(별도 검증 트랙 진행 중).
2. OrganizerAgent는 결정론적 순수 Python 유지(LLM 호출 금지).
3. 엑셀 17시트 계약 유지: 기존 시트명·컬럼 이름/순서 불변. 컬럼 추가는 항상 맨 뒤 +
   opt-out 플래그(v4 `PROVENANCE_ENABLED` 패턴).
4. 코드·주석·로그 한국어, 새 외부 의존성 금지, 튜닝값은 config + env 오버라이드.
5. 기존 테스트 전부 통과 + WP별 신규 테스트.
6. **기존 추출 프롬프트 문면 변경은 WP2에서만 허용**(가이드라인 주입 블록 교체).
   WP3의 타깃 검수용 **신규** 프롬프트 작성(3-B·3-C)은 허용 — 기존 추출·빈칸보완
   프롬프트는 건드리지 않는다. WP2는 LLM 캐시 무효화를 유발하므로(의도된 효과)
   커밋 메시지에 명시한다.
7. v4 원장·parallel_map_collect·quota 격리 의미론을 깨지 않는다.

## WP2. 가이드라인 구조적 주입 + 레거시 제거 (P0)

### 2-A. 구조 파서 (`agents/guideline_agent.py` 재구축)

- md를 헤딩(`#`~`####`) 단위 섹션으로 파싱하고, WP1 앵커(`<!-- sheets: ... -->`)로
  시트키→섹션 목록 매핑을 만든다. **표는 markdown 표 그대로(개행 보존)** 유지한다.
- `get_all_prompts()`를 다음으로 교체 (반환 타입은 기존과 동일 `dict[str, str]`):
  시트키별로 ① 해당 앵커 섹션들, ② §5.3에 해당 시트 컬럼 표가 있으면 그 표, ③ §7
  매핑 규칙 중 해당 시트 관련 항목 — 을 이 우선순위로 이어붙이고, 시트당
  `GUIDELINE_PROMPT_MAX_CHARS`(config, 기본 3000자)에서 **섹션 경계 단위로** 자른다
  (표 중간 절단 금지 — 표가 상한을 넘으면 그 표는 통째로 제외하고 다음 우선순위 진행).
- 프롬프트 앞머리는 기존 형식 유지: `[가이드라인 보조 지침: {sheet_key}]`.

### 2-B. 레거시 제거

삭제: `GUIDELINE_SCHEMA`의 구 시트 정의(vehicle_by_use/energy_by_use/greenhouse_gas/
reduction_strategy/summary_card), `_EXTRACTOR_KEY_MAP`, `_GUIDELINE_CONTEXT_RULES`(구),
`get_extraction_prompt`, `_build_agent_spec`, `_normalise_agent_spec`,
`_AGENT_SPEC_SYSTEM`, 관련 config `GUIDELINE_AGENT_SPEC_ENABLED`.
- HWP fallback 경로(`--guideline` 옵션, md 부재 시)는 유지하되 `_GUIDELINE_CONTEXT_RULES_V2`
  키워드 스니펫 방식으로 동작시킨다(HWP는 앵커가 없으므로 스니펫이 유일한 수단 —
  이 경로에서만 기존 `_extract_guideline_context` 로직 재사용).

## WP5. 행 단위 데이터상태 컬럼 (P1)

가이드라인 §6.4 코드 중 파이프라인이 결정론적으로 판정 가능한 부분집합만 구현:

- 값: `reported`(기본) / `visual_only`(이미지 파이프라인 유래 행) /
  `gap_fill`(빈칸보완 유래 — 기존 `보완출처` 필드 승계) / `calculated`(organizer가
  값을 계산·교정한 행, 현재는 감축률 재계산이 유일) / `conflicting`(dedup 값충돌
  리포트 대상 행 — 유지된 쪽에 표시).
- 판정 위치: 전부 organizer(결정론). 이미지 유래는 image_agent가 행에 넣는
  `출처`("이미지 p.N") 또는 별도 마커 필드로 식별 — 식별 필드가 없는 시트는
  image_agent가 병합 시 `"데이터상태": "visual_only"`를 직접 넣는 방식이 더 단순하면
  그렇게 해도 된다(어느 쪽인지 주석으로 명시).
- 엑셀: 16개 데이터 시트(00~15) 맨 뒤(출처페이지 다음)에 `데이터상태` 컬럼.
  `DATA_STATUS_ENABLED`(기본 True) opt-out — v4 `PROVENANCE_ENABLED`와 동일 패턴으로
  `excel_writer._headers_for_output`에서 필터.
- dedup 병합 시 상태 우선순위: conflicting > calculated > visual_only > gap_fill >
  reported (더 "주의 필요"한 쪽이 살아남는다).
- `not_reported`는 행이 없는 상태라 행 단위 컬럼으로 표현 불가 — 구현하지 않는다
  (빈 시트 원인 분류가 이미 검증리포트에서 담당).

### 수용 기준
- 이미지 유래 행 visual_only, 감축률 교정 행 calculated, 충돌 행 conflicting이
  각각 단위 테스트로 확인. `DATA_STATUS_ENABLED=0` + `PROVENANCE_ENABLED=0`이면
  v3 스키마와 동일.

   기준 행이 하나로 합쳐지며 한쪽이 소실된다(서울 실측: 자체 인벤토리 기준 총괄·부문
   행 5건 소멸, GIR 값과 자체 값 혼재 행 다수). `_clean_reduction_targets`(또는 06
   담당 dedup)의 키에 정규화된 `목표범위`를 추가하고, 목표범위가 비어 있는 행끼리만
   기존 키로 병합한다. 키 확장으로 행이 늘어나는 것은 의도된 동작(서로 다른 인벤토리
   기준은 다른 행이어야 함).
5. **00_문서메타 단일 행 병합**: 배치별로 추출된 문서메타 후보가 중복 행으로 남는다
   (서울 실측: 3행 — 기준연도 null/2018 병존, 목표연도 "2033"/"2030,2033,2050"/
   "2030,2050" 병존). organizer에서 지자체당 1행으로 병합: 필드별로 ① 비-null 우선
   ② 더 구체적인 값(더 길거나 법적근거처럼 정보가 많은 쪽) 우선 ③ 값이 상충하면
   합집합 표기가 가능한 필드(목표연도)는 정렬·중복제거한 합집합, 불가능한 필드는
   최빈값을 채택하고 검증리포트 "정보" 항목을 추가한다.

### 수용 기준
- "MARKAL-MACRO 모형 활용" → hybrid 코드, "MARKAL 최적화" → optimization 코드.
- 관리권한 행 {관리부문: "전력"} 또는 {관리부문: "에너지"} → 부문 미변경 + 리포트 1건.
- 06: 목표범위만 다른 두 행이 병합되지 않음(단위 테스트).
- 00: 상충 메타 3행 입력 → 1행 + 검증리포트 항목(단위 테스트).
- 기존 organizer 테스트 전부 통과.

## WP7. 장 문맥 프로비넌스 + 관리번호 일관성 검증 (P1)

### 배경 (서울 실측)

지자체 기본계획 원문은 "기존 계획의 평가" 장(서울: 제3장, p148~160)에 **이전 계획의
사업목록·과제번호·성과지표 달성도**를 싣는다. 이 번호 체계는 본계획(서울: p201~
표 5-5, 제6장 사업카드)과 **같은 형식(M1-2, B1-5 등)이지만 다른 사업**을 가리킨다.
현재 라우팅은 키워드 점수 기반이라 이 장의 페이지도 08/09/10/11 시트로 보내고,
추출된 구계획 행이 본계획 행과 섞여 관리번호-사업명 충돌을 만든다(Codex 검수에서
08/10 시트 값충돌의 대부분이 이 유형). 구계획 평가 내용의 올바른 자리는
14_점검실적(성과지표 달성도)이거나 최소한 별도 표식이다.

**결정론 원칙**: 라우팅 로직은 수정 금지(절대 제약 1)이므로, 추출 후 organizer에서
v4 `출처페이지`로 판별한다. LLM 호출 없음.

### 7-A. 장 경계 맵 (supervisor → organizer)

- `pdf_reader`/`hwp_reader`가 반환한 페이지 텍스트에서 결정론 휴리스틱으로
  "기존계획 평가" 장의 페이지 구간을 찾는다:
  - 페이지 상단(첫 200자)에서 장 제목 패턴 매칭: `기존\s*계획.{0,6}(평가|분석)`,
    `기존\s*(시책|사업).{0,6}평가`, `이전\s*계획.{0,6}평가` 등 — config에
    `PRIOR_PLAN_HEADING_PATTERNS` 리스트로 두고 env로 확장 가능하게.
  - 장 시작 페이지부터, 다음 장 제목(숫자+제목 헤딩 패턴)이 나오는 페이지 직전까지를
    구간으로 본다. 서울 기준 p148~160이 잡혀야 한다(테스트 픽스처로 헤더 문자열 사용).
  - 탐지 실패(패턴 0건)면 구간 없음 — 전 기능이 no-op (보수적 기본).
- supervisor가 이 구간을 `prior_plan_pages: set[int]`로 organizer 검증 패스에 전달.

### 7-B. 행 태깅 + 이동 없이 보고 (organizer, 결정론)

- 08/09/10/11 시트 행의 `출처페이지`(예: "p149", "p149,p150" — v4 형식)를 파싱해
  **모든** 근거 페이지가 `prior_plan_pages` 안이면 내부 필드 `계획구분="기존계획"`을
  기록한다(그 외 "본계획", 출처페이지 없으면 미기록). 엑셀 헤더에는 추가하지 않는다
  (내부 필드 — WP3 타깃 검수와 검증리포트가 참조).
- **행을 자동 이동·삭제하지 않는다.** 대신 검증리포트에 시트별 집계 1건 +
  행 단위 "경고"("08_감축사업목록 행 X: 기존계획 평가 장(p149) 유래 — 본계획 사업
  목록과 관리번호 충돌 가능")를 추가한다. 자동 이동은 골든셋 검증 후 별도 트랙.

### 7-C. 관리번호-사업명 일관성 검증 (organizer, 결정론)

- `계획구분="기존계획"`이 아닌 08 시트 행에서 `관리번호→사업명` 레지스트리를 만든다
  (사업명은 NFKC 정규화). 같은 관리번호에 서로 다른 정규화 사업명이 2개 이상이면
  검증리포트 "경고"("관리번호 M1-2에 사업명 2종: '…', '…'").
- 09/10/11 시트 행의 (관리번호, 사업명) 쌍이 레지스트리와 다르면 "정보" 항목.
  관리번호 형식 불일치(F2-02 vs F2-2)는 `_normalize_project_id`(영문+숫자 구간의
  선행 0 제거)로 흡수하고, 흡수된 경우도 "정보"로 남긴다.
- 자동 수정 금지 — 어느 쪽이 옳은지는 원문 확인이 필요하므로 WP3 타깃 검수 대상으로
  넘긴다(검증리포트 경고 → 3-B 선정 기준 1에 자동 포함됨).

### 수용 기준
- 서울 픽스처(제3장 헤더 텍스트 포함 페이지 시퀀스)에서 p148~160 구간 탐지.
- 기존계획 페이지 유래 행에 `계획구분` 태깅 + 검증리포트 경고 생성(단위 테스트).

- 탐지 패턴 0건 문서에서 v4.1과 완전 동일 출력(no-op 회귀 테스트).
- 엑셀 스키마 불변(내부 필드만 추가).

## WP8. 시트 폐루프 실행 경로 (P2)

### 배경·목적

팀원의 v3 실험(커밋 `b73ac1c`)이 원형. v4는 **검수 단계만** 시트 단위로 돌리지만
(`review_and_adjudicate_by_sheet`), 폐루프는 **추출부터** 시트 단위로 닫는다:
`시트 추출 → 시트 정제 → 시트 검수·판정·병합 → 재정제 → 다음 시트`. 기대 효과:

1. **중단 내성**: quota·장애로 실행이 끊겨도 완료된 시트는 추출→검수까지 끝난
   완결 상태다(현재는 전체 추출이 끝나기 전 중단되면 검수가 하나도 안 됨).
2. **검수 반영 기준본**: 병합된 행이 같은 실행 안에서 후속 정제·검증의 입력이 된다.
3. **진행 가시성 확장**: 추출 단계까지 시트 단위 진행이 보인다.

원형 구현의 두 결함을 반드시 교정한다: ① `HYBRID_ADJUDICATION_MAX_CANDIDATES`
전역 상한이 시트당으로 리셋됨 ② 병합→재정제 순서 때문에 병합로그와 최종 시트가
불일치(WP3-C '반영' 불변식 위반).

### 8-A. 실행 경로 (`agents/supervisor.py`, `main.py`, `config.py`)

- `SHEET_CLOSED_LOOP_ENABLED`(config, 기본 **False**) + main.py `--sheet-closed-loop`
  플래그. 실행 헤더에 "시트별 폐루프: 활성/비활성" 출력.
- `Supervisor._run_sheet_closed_loop()`: 지자체명 추출 1회(v4 `_municipality_from_text`
  폴백 유지) → 라우팅 1회 → **시트 순차 루프**:
  1. 해당 시트의 배치들을 기존 `parallel_map_collect`로 **병렬 추출**
     (시트 간 병렬을 시트 내 배치 병렬로 좁힌 것 — 원장 기록·부분실패 허용·quota
     격리 의미론 그대로. 8-B의 `extract_sheet_pages` 사용).
  2. `organizer.organize_sheet()`로 해당 시트만 정제.
  3. `HYBRID_REVIEW_ENABLED`이고 시트가 `HYBRID_REVIEW_SHEETS`에 있으면
     `review_and_adjudicate_by_sheet(target_sheets=[sheet_key],
     routed_pages={sheet_key: pages}, max_candidates_override=남은 전역 예산)`
     호출. **전역 판정 상한은 supervisor가 시트 경계를 넘어 차감·전달한다**
     (메서드에 `max_candidates_override: int | None = None` 파라미터 추가 — None이면
     기존 config 동작, v4 기존 호출부는 변경 없음).
  4. 병합 반영분이 있으면 해당 시트만 재정제(2번 재호출) 후 다음 시트로.
- 시트 루프 종료 후 기존 순서 유지: 이미지 분석 → 빈칸 보완 → **최종 organize
  (교차 시트 검증 패스 포함)** → 엑셀. 폐루프 모드에서는 STEP 3c/3d의 sheetwise
  검수를 다시 돌리지 않는다(이미 수행됨). WP3-B 타깃 에스컬레이션 검수는
  검증리포트 기반이므로 폐루프와 무관하게 최종 organize 후에 그대로 수행.
- **quota 처리**: 시트 검수 중 `LLMQuotaExceededError`가 나면 그 시점까지의
  후보·병합로그를 보존한 채(시트 완료 시점마다 누적) 남은 시트의 **검수만** 비활성
  플래그로 끄고 추출은 계속한다. 반복 대기로 전체 실행이 늘어지는 것을 막고,
  v4에서 확인된 "quota 시 감사 로그 유실" 엣지도 함께 해소한다.

### 8-B. 에이전트 지원 메서드

- `ExtractorAgent.extract_sheet_pages(sheet_key, sheet_pages, municipality,
  extraction_prompts, ...)`: 기존 병렬 태스크 빌더에서 **한 시트 분량의 태스크만**
  생성해 `parallel_map_collect`로 수집. 원장(성공/호출실패/파싱실패) 집계 포맷 동일.
  기존 `extract()`는 이 메서드를 재사용하도록 리팩터해도 되고(동작 불변 증명 필요)
  분리 유지해도 된다 — 어느 쪽인지 주석으로 명시.
- `ExtractorAgent.route_pages(pages)`: 라우팅 결과 공개 래퍼
  (`FULL_DOCUMENT_SCAN` 처리 포함). supervisor·hybrid가 같은 라우팅을 공유해
  중복 계산을 없앤다.
- `OrganizerAgent.organize_sheet(sheet_key, rows, municipality)`: 해당 시트
  cleaner만 실행. **교차 시트 검증 패스(19_검증리포트 생성)는 수행하지 않는다**
  — 그것은 최종 organize 전용(교차 시트 정보가 필요하므로).
- **cleaner 멱등성 요구**: 폐루프는 정제된 행을 재정제하므로(4번 단계·최종 organize)
  폐루프 대상 시트의 cleaner는 `clean(clean(rows)) == clean(rows)`여야 한다.
  멱등이 아닌 cleaner가 발견되면 멱등으로 고치고 회귀 테스트를 남긴다.

### 8-C. 정합 요구 (WP3-C 연계 — 선행 필수)

- WP3-C-1 dedup 키 단일화, WP3-C-2 '반영' 불변식이 폐루프 경로에도 그대로 적용:
  시트 내 병합 행이 재정제·최종 organize dedup에서 소멸하면 병합로그를
  `보류(병합후중복제거)`로 갱신한다.
- 이미지 분석·빈칸 보완이 폐루프 **이후** 행을 추가하므로, 검수가 본 기준본과
  최종본이 다를 수 있다 — 알려진 한계로 README·docstring에 문서화한다
  (최종 검증 패스가 최종본 기준으로 재검증하므로 데이터 정합은 유지됨).

### 수용 기준

- `SHEET_CLOSED_LOOP_ENABLED=0`(기본)에서 전 파이프라인 산출 불변 — 기존 테스트
  전체 통과 + no-op 회귀 테스트.
- 스텁 LLM 단위 테스트(신규 `tests/test_sheet_closed_loop.py`):
  1. 호출 순서가 시트 단위로 인터리브됨(시트A 추출→검수 → 시트B 추출→검수 …).
  2. 전역 판정 상한이 시트 경계를 넘어 유지됨(상한 3, 시트당 후보 2건 × 2시트 →
     판정 3건에서 정지).
  3. 시트 내 배치가 병렬 실행됨(활성 워커 ≥2 관측 — `tests/test_parallel_pipeline.py`
     패턴 재사용).
  4. 검수 중 quota → 완료 시트의 후보·병합로그 보존 + 남은 시트 검수 스킵 +
     추출은 계속.
  5. 폐루프 대상 시트 cleaner 멱등성.
- 원장 리포트가 폐루프 경로에서도 동일 포맷으로 출력.
- 서울 소형 PDF 스모크: `--sheet-closed-loop --hybrid-review`로 시트별
  `추출→정제→검수` 로그 순서 확인(수동, 인수 절차에 포함).
