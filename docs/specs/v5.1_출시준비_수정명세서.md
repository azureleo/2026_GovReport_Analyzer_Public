## F2. 출력 경로 사전 검증 + 저장 실패 폴백 — P0

**증상**: 출력 경로 검증이 최종 `wb.save()`(excel_writer.py:144)에만 있다.
존재하지 않는 디렉터리(`-o results/out.xlsx`) → FileNotFoundError,
Windows에서 대상 파일을 Excel로 열어둔 채 실행 → PermissionError.
**수 시간 LLM 작업 후 STEP 4에서 크래시해 결과 전체 유실.**

**수정**:
1. main.py에서 파이프라인 시작 **전에**: 출력 경로의 부모 디렉터리가 없으면
   `mkdir(parents=True)`로 생성하고, 같은 이름의 임시 파일을 써봐서(쓰기 후 즉시 삭제)
   쓰기 가능성을 검증한다. 실패 시 한국어 에러 + exit 1 (LLM 호출 0회 상태에서 실패).
2. excel_writer(또는 supervisor의 저장 호출부)에서 `wb.save()`가
   PermissionError/OSError로 실패하면 같은 디렉터리에
   `{원본stem}_{YYYYMMDD_HHMMSS}.xlsx`로 **1회 재저장**을 시도하고, 성공 시
   "원본 경로가 잠겨 있어 대체 경로에 저장했습니다: …"를 출력한다.
   재저장도 실패하면 그때 예외 전파.

**수용 기준**: 없는 디렉터리 → 자동 생성 후 정상 저장(테스트), 부모 생성 불가 경로
(예: 파일을 디렉터리처럼 지정) → 시작 시점 에러(테스트), save 1차 실패 mock →
타임스탬프 파일로 저장 + 안내(테스트).

## F3. 로컬 에이전트 임시 디렉터리 정리 경합 수정 — P1

**증상**: `utils/llm_client.py:377-391` `_call_local_agent`가
`with tempfile.TemporaryDirectory(...)` **안에서** 응답을 return한다. CLI가 임시
디렉터리에 만든 상태 디렉터리(실측: `.omx`)를 CLI 종료 직후 백그라운드 훅이 계속
쓰는 사이 rmtree가 경합 → `OSError: Directory not empty`. 이 OSError가 **이미
성공적으로 받은 응답을 버리고** `_retry_local_call`의 일반 오류 분기로 들어가 호출
전체를 재실행한다(스모크에서 경고 2회 실측). `MAX_RETRIES` 연속 발생 시 성공한
응답이 있었음에도 배치가 call_fail로 유실될 수 있다.

**수정**: 임시 디렉터리 정리 실패가 호출 실패로 분류되지 않게 한다 —
`tempfile.TemporaryDirectory(ignore_cleanup_errors=True)`(Python 3.10+) 사용, 또는
응답 확보를 with 블록과 분리하고 정리는 try/except로 감싸 실패 시 warning 로그만
남긴다. 두 방식 중 하나를 택하고 주석으로 이유를 명시.

**수용 기준**: 정리 단계에서 OSError가 나도 응답이 정상 반환되고 재시도가 발생하지
않음(mock 테스트 — rmtree 실패 주입).

## F4. 엑셀 셀 값 정제(sanitize) — P1

**증상** (전부 실측 확인됨): excel_writer가 값을 무검사로 `ws.cell()`에 넣는다.
- LLM이 자유 텍스트 필드에 중첩 dict/list를 반환하면 `ValueError: Cannot convert …
  to Excel`로 STEP 4 전체 크래시(F2와 결합 시 결과 유실).
- 제어문자(\x00-\x08 등) 포함 문자열 → `IllegalCharacterError` 크래시.
- `=`로 시작하는 문자열 → openpyxl이 수식으로 저장(결과 파일 오염·수식 주입).

**수정**: `utils/excel_writer.py`에 셀 쓰기 직전 정제 함수 `_sanitize_cell_value`를
추가한다:
1. dict/list → `json.dumps(value, ensure_ascii=False)` 문자열로 변환.
2. str이면 openpyxl의 `ILLEGAL_CHARACTERS_RE`(openpyxl.utils.escape 또는
   cell.cell 모듈에 있음)로 제어문자 제거.
3. `=`/`+`/`@`로 시작하는 문자열은 수식이 아닌 텍스트로 저장되도록 셀 기록 후
   `cell.data_type = "s"` 강제(값 자체는 변형하지 않는다 — `'` 접두어 삽입 금지).
4. 그 외 타입(int/float/bool/None/str)은 그대로.

**수용 기준**: dict 값/제어문자/`=SUM(A1)` 문자열 각각이 크래시 없이 저장되고,
재로드 시 수식이 아닌 텍스트로 읽힘(openpyxl 왕복 테스트). 기존 정상 값의 출력 불변.

## F5. 소수정 묶음 — P1

각각 작은 수정이며 하나의 커밋으로 묶어도 된다. 번호별 회귀 테스트(문서 수정 제외).

1. **`-r 0` NameError**: `main.py`의 `-r/--retries`에 1 미만 값이 오면 argparse 검증
   에러("1 이상이어야 합니다")로 즉시 종료. (`supervisor.py:340`의
   `range(1, n+1)`이 0에서 한 번도 안 돌아 `organizer` 미정의 NameError가 났음.)
2. **텍스트 없는 문서(스캔본) 경고**: STEP 0 직후 전체 페이지 텍스트 합이 임계
   (`MIN_DOCUMENT_TEXT_CHARS`, config 신설, 기본 500자) 미만이면 한국어 경고
   출력("텍스트 레이어가 거의 없습니다 — 스캔본 PDF일 수 있으며 추출 결과가 비어
   있을 수 있습니다") + `19_검증리포트`에 "정보" 항목 추가. **실행은 계속한다**
   (중단 금지 — 보수적).
3. **Windows 리다이렉트 UnicodeEncodeError**: main.py 시작부에서
   `sys.stdout`/`sys.stderr`에 `reconfigure(errors="replace")` 적용(인코딩은 유지,
   인코딩 불가 문자만 대체 — cp949 리다이렉트에서 em dash로 죽던 문제 차단).
   함께 `utils/llm_client.py:242` `subprocess.run(..., text=True)`에
   `encoding="utf-8", errors="replace"`를 명시해 hwp_reader와 통일.
4. **암호 PDF 안내**: `utils/pdf_reader.py`에서 open 직후 `doc.needs_pass`가 True면
   한국어 에러("암호로 보호된 PDF입니다. 암호를 해제한 사본으로 다시 실행하세요")로
   즉시 종료. 아울러 `doc.close()`를 try/finally로 보호(예외 시 핸들 누수 방지).
5. **엑셀 저장 후 최종 검수 quota**: `agents/supervisor.py:171-172`가
   `LLMQuotaExceededError`를 re-raise해 **결과 파일이 정상 저장됐는데도** 실행이
   실패(exit 1)로 끝난다. 엑셀 저장 이후 단계인 LLM 최종 검수에서 quota가 나면
   삼키고 "한도 초과로 최종 검수는 생략했습니다. 결과 파일은 저장되어 있습니다:
   {경로}"를 출력한 뒤 정상 종료한다. (저장 **이전** 단계의 quota 의미론은 불변.)
6. **pytest 의존성**: `requirements.txt`에 `pytest>=8.0.0` 추가(README·CLAUDE.md가
   pytest 실행을 지시하는데 미포함이라 신규 설치자가 실패).
7. **`LOCAL_AGENT_TIMEOUT` 3중 불일치**: 실제 기본값은 300(config.py:85, 주석에
   900 회피 사유 명시). `main.py:97` 도움말의 "기본값: 900" → 300으로,
   `.env.example:56`의 `LOCAL_AGENT_TIMEOUT=900` → `300`으로 수정
   (.env.example 복사만으로 config가 의도적으로 회피한 값이 복원되는 문제).
