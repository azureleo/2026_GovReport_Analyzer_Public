# M2-1 시각 요소 인벤토리 리콜 감사 구현명세서

> 기준 문서: `docs/specs/프로젝트_마일스톤_로드맵.md` §M2-1.
> 대상 브랜치: `feat/v5-guideline-orchestration` (히스토리 재작성 금지, 일반 커밋만).
> 이 문서는 대화 맥락 없이 코드베이스만으로 구현 가능해야 한다. 모호하면 보수적(동작 불변) 선택.
> 목적: 서울 문서의 **모든 차트·이미지 표·그래프의 사람 확정 목록**과 파이프라인의
> `16_시각자료목록`을 대조해, 시각 요소가 파이프라인의 어느 단계(이미지 추출 → triage →
> vision → 인벤토리 기록)에서 유실되는지 요소 단위로 판정하는 감사 도구를 만든다.
> 격차 근거: 로드맵 G1·G3 — triage는 Pillow 휴리스틱(`IMAGE_TRIAGE_MIN_SCORE=5`)이고
> 리콜이 한 번도 검증된 적 없다.

## 절대 제약

1. **파이프라인 코드 동작 불변.** 신규 코드는 `scripts/audit_visual_inventory.py`와
   테스트뿐. `agents/image_agent.py`·`utils/pdf_reader.py`는 수정하지 않고 **임포트만**
   한다(triage 재실행용). 재사용에 공개 별칭이 필요하면 M1-2와 같은 방식(본문 수정 없는
   별칭 추가)만 허용.
2. **config 기본값 변경 금지.** `IMAGE_TRIAGE_MIN_SCORE`, `VECTOR_RENDER_MIN_DRAWINGS`
   등 임계 완화는 이 마일스톤의 산출물이 아니다 — 감사 리포트가 **근거 숫자**를 만들고,
   완화 여부·수치는 리포트를 보고 사람이 별도 결정한다("측정 없이 완화 금지" 원칙).
3. 감사 도구는 **LLM 호출 0회** — pdf_reader(PyMuPDF)·Pillow triage·openpyxl만.
   vision 백엔드 호출 금지.
4. 코드·주석·로그·리포트 한국어. 새 외부 의존성 금지.
5. 기존 테스트 128개 전부 통과 + 신규 회귀 테스트. 커밋별 테스트 통과. **push 금지.**

## 범위 밖 (하지 말 것)

- 임계값·승격 규칙의 실제 변경(위 제약 2). 텍스트리스 페이지 VLM 우회(M2-2),
  vision 모델 벤치마크(M2-3), 병합 정책 완화(M2-4).
- vision 판독 **정확도**(값이 맞는가) 평가 — M1-2 골든셋 하네스의 출처유형 분해가 담당.
  여기서는 **리콜**(요소가 인벤토리에 잡히는가)만.
- 사람 인벤토리 확정 작업 자체 — 도구는 초안을 만들어 주고, 확정은 사람이 한다.

## 1. 사람 인벤토리 형식 (감사의 정답지)

- 경로: `data/golden/서울_시각요소_인벤토리_v1.xlsx` (도구는 경로 인자로 받음).
- 시트명 `시각요소`, 1행 = 헤더. 컬럼:

| 컬럼 | 필수 | 값 |
|---|---|---|
| `요소ID` | 필수 | 사람 부여 일련번호 `E001`, `E002`… |
| `페이지` | 필수 | PDF 1-기준 페이지 정수. 두 페이지에 걸치면 시작 페이지 |
| `요소유형` | 필수 | `그래프` / `이미지표` / `이미지` / `지도·사진` / `장식` 중 하나 |
| `제목` | 권장 | 원문 캡션(`[그림 2-3] …`) 또는 요약 |
| `데이터포함` | 필수 | `Y`/`N` — 정량 데이터를 담고 있는가 |
| `기대추출` | 필수 | `Y`/`N` — 파이프라인이 잡아야 하는 요소인가. `지도·사진`·`장식`은 N |
| `관련시트` | 선택 | `03_배출현황_지역` 같은 계약 시트명 |
| `비고` | 선택 | 자유 텍스트 |

- **리콜 분모 = `기대추출=Y` 행.** `기대추출=N` 행은 반대로 "잡히면 정밀도 손실 후보"
  통계에 쓴다(자동 실패 판정은 하지 않음 — 참고 지표).
- `요소유형` 판정 지침(사람용): 텍스트 레이어가 살아 있는 표는 시각 요소가 아니므로
  **인벤토리에 넣지 않는다**(그건 텍스트 추출 경로 담당). 이미지로만 존재하는 표가 `이미지표`.
- 같은 페이지에 요소가 여러 개면 행을 나눈다.

## 2. 감사 도구 `scripts/audit_visual_inventory.py`

두 서브커맨드(또는 상호배타 플래그). 공통: LLM 0, 네트워크 0.

### 2.1 초안 생성 모드 — 사람 작업 가속

```
python scripts/audit_visual_inventory.py dump <source.pdf> [--out data/golden/시각요소_초안.xlsx]
```

- `utils.pdf_reader.extract_pdf`를 실행해(vision 호출 아님 — 파싱만) 페이지별로:
  - 추출된 이미지 각각: 페이지, 크기(w×h), full render 여부(caption의 `full render`),
    `_is_relevant_image` 통과 여부, `_triage_image` 점수·사유(passed 포함).
  - 페이지 텍스트에서 `[그림 N-N]`·`[표 N-N]` 캡션 라인(image_agent
    `_visual_title_from_text`와 같은 패턴) 수확.
  - `page.get_drawings()` 개수(벡터 차트 후보 신호 — pdf_reader의 벡터 렌더 판정과
    동일 소스).
- 결과를 1번 형식과 같은 컬럼 + 자동 채움 보조 컬럼(`자동_트리아지점수`,
  `자동_이미지크기`, `자동_캡션후보`, `자동_벡터드로잉수`)으로 초안 xlsx 저장.
  `요소유형`·`데이터포함`·`기대추출`은 비워 두고 사람이 채운다.
- 주의: 초안은 "파이프라인이 본 것"의 목록이므로 **파이프라인이 통째로 놓친 요소는 초안에
  없다**. 리포트 머리말에 이 한계를 명시하고, 사람이 원문 PDF를 넘기며 누락 요소를 행으로
  추가해야 최종 인벤토리가 된다(이 문구를 초안 xlsx 첫 시트에도 넣는다).

### 2.2 감사 모드 — 핵심 산출물

```
python scripts/audit_visual_inventory.py audit <인벤토리.xlsx> <파이프라인출력.xlsx> <source.pdf> \
    [--report-dir output]
```

요소(`기대추출=Y`)별로 파이프라인 깔때기(funnel)의 어느 단계까지 도달했는지 판정한다:

1. **이미지 확보 단계**: `extract_pdf` 결과에서 해당 페이지에 이미지(임베드 또는 full
   render)가 존재하는가. 없으면 상태 = `이미지_미추출` — 이때 그 페이지의
   `get_drawings()` 수를 함께 기록해 `VECTOR_RENDER_MIN_DRAWINGS`(기본 60) 몇으로
   낮추면 렌더됐을지를 보인다.
2. **triage 단계**: 해당 페이지 이미지들에 `image_agent._triage_image`를 재실행
   (`_coverage_reduce_images` 적용 후 기준 — 실제 파이프라인과 동일 입력). 전부
   탈락이면 상태 = `triage_탈락`(최고 점수·사유 기록). 참고: `_has_reference_context`
   제외에 걸리면 별도 상태 = `참고자료_제외`.
3. **인벤토리 기록 단계**: 출력 xlsx의 `16_시각자료목록`에서 `시각자료ID`(`V{페이지}-{idx}`
   형식)로 페이지를 파싱해, 해당 페이지 항목이 있으면 상태 = `기록됨`(복수면 전부 나열,
   `데이터포함여부`·`디지타이징필요` 값 포함). triage는 통과했는데 16 시트에 없으면
   상태 = `vision_유실`(vision이 "해당없음" 판정했거나 관찰값이 비었던 경우 — 재현
   호출은 하지 않고 상태만 기록).
- 매칭 키는 **페이지 번호**. 같은 페이지에 인벤토리 요소가 여러 개인데 16 시트 항목이
  더 적으면, 항목 수 부족분만큼 `동일페이지_부분기록`으로 판정(요소↔항목 1:1 대응은
  유형 문자열 유사도까지 시도하지 않는다 — 보수적으로 페이지 단위).

### 2.3 리포트

`{report-dir}/visual_inventory_audit_{timestamp}.md` (+`.json`):

1. **요약**: 기대추출 요소 수, 기록됨 수, **리콜**, 상태 분포
   (이미지_미추출 / triage_탈락 / 참고자료_제외 / vision_유실 / 부분기록 / 기록됨).
2. **요소유형별 분해**: 그래프/이미지표/이미지 각각의 리콜과 유실 단계 분포 —
   "triage가 무엇을 놓치는가"의 직접 답.
3. **요소별 상세 표**: 요소ID, 페이지, 유형, 상태, triage 점수·사유, 벡터 drawing 수,
   16 시트 매칭 항목. 전량 나열(조용한 유실 금지).
4. **임계 민감도 시뮬레이션** (기본값 변경의 근거 자료 — 변경은 하지 않음):
   - `IMAGE_TRIAGE_MIN_SCORE` ∈ {3,4,5,6}: 각 값에서의 요소 리콜(triage 단계 기준)과
     triage 통과 이미지 총수(= vision 비용 프록시) 표. triage 점수는 이미 계산돼 있으므로
     재실행 없이 집계만 바꾼다.
   - `이미지_미추출` 요소들의 페이지 drawing 수 분포: `VECTOR_RENDER_MIN_DRAWINGS`를
     {30,45,60}으로 뒀을 때 렌더 대상이 됐을 요소 수.
5. **기대추출=N 참고 통계**: 잡히지 말아야 할 요소 중 16 시트에 기록된 수(과추출 신호).
6. 실행 정보: 입력 3개 경로, 인벤토리 행 수, 형식 오류(필수 컬럼 누락 등은 한국어로
   명확히 보고하고 중단).

## 3. 테스트 (`tests/test_audit_visual_inventory.py`)

핵심 판정 로직은 순수 함수로 분리해(PageContent·이미지 dict·행 dict를 받는 형태)
실 PDF 없이 검증한다:

1. funnel 판정: 이미지 없음 → `이미지_미추출`, triage 전탈락 → `triage_탈락`,
   통과+16시트 없음 → `vision_유실`, 16시트 있음 → `기록됨`.
2. `시각자료ID` 파싱: `V161-003` → 페이지 161, 페이지 없는 `V003` → 페이지 미상 처리.
3. 동일 페이지 요소 2개 vs 16시트 항목 1개 → `동일페이지_부분기록` 1건.
4. 민감도 집계: 점수 {4,5,6}인 요소 3개에서 MIN_SCORE=5로 2개, 3으로 3개 통과.
5. 인벤토리 형식 오류(필수 컬럼 누락, 요소유형 오타)가 한국어 오류로 보고됨.
6. dump 모드 스모크: PyMuPDF로 코드 생성한 2페이지 초소형 PDF(이미지 1장 삽입 +
   벡터 사각형 다수 페이지)에서 초안 xlsx가 생성되고 자동 컬럼이 채워짐
   (픽스처 파일 커밋 금지 — tmp_path에 코드로 생성).
7. 기존 `_triage_image`·`_coverage_reduce_images` 임포트 사용이 image_agent 동작을
   바꾸지 않음(모듈 diff 없음 — 별칭 추가 시 별칭 동일성 테스트).

## 5. 최종 인수 절차

1. `python -m pytest tests/ -q` — 기존 128개 + 신규 전부 통과, 커밋별로도 통과.
2. dump 스모크: `서울특별시_탄소중립계획.pdf`로 초안 xlsx 생성(LLM 0, 수 분 내).
   초안 행 수·자동 컬럼 채움을 눈으로 확인.
3. audit 스모크: 초안에서 아무 행 10개를 임시로 `기대추출=Y` 표시한 가짜 인벤토리 +
   기존 `output/`의 서울 출력 xlsx로 감사 리포트가 생성되는지 확인(리콜 숫자의 의미는
   사람 확정 인벤토리 이후 — 여기선 동작 확인만).
4. config·agents·utils의 diff가 (별칭 추가 외) 0줄임을 확인.
5. 이후 사람 작업: dump 초안을 원문 대조로 확정(`서울_시각요소_인벤토리_v1.xlsx`) →
   audit 재실행 → 리콜 기준선 확보 → 임계 완화 여부는 그 숫자로 결정(별도 트랙).
