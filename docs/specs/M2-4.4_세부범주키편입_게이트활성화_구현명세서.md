## 배경 (사용자 결정 2026-07-12)

M2-4.2~4.3 실측(`docs/audit/M2-4.2_병합경로_실측_20260712.md`)에서 3지자체
값 오병합 0·품질 동반 상승·시리즈 붕괴 해소를 확인, 사용자가 권고안 ②를
채택했다: **잔여 차트 간 키 충돌을 세부범주 키 편입으로 닫은 뒤
`VISUAL_MERGE_LABELED_ENABLED` 기본값을 True로 전환**한다.

잔여 충돌의 실측 정체(서울 flag-on 경고 14): M2-4.3에서 지표명이 시리즈
라벨로 짧아지며(예: '도시가스'), **서로 다른 차트**(2005 실적 vs 2005 전망)의
행이 같은 키 (에너지, 도시가스, 2005)로 충돌 — V3가 첫 행만 유지. 두 행은
세부범주(차트 수준 명칭)가 서로 다르므로, 세부범주를 키에 넣으면 갈라진다.

## 절대 제약

1. G1~G5 판정 로직·V3 중복 방지·estimated 관례·프롬프트 불변.
   **캐시 전량 히트(재호출 0)가 인수 조건.**
2. 지자체 하드코딩 금지. 채점기(`scripts/`) 수정 금지.
3. 코드·주석·커밋 한국어, push 금지, 커밋별 `python -m pytest tests/ -q` 통과.

## 구현

### S1 지표세부범주의 병합 키 편입 (agents/organizer_agent.py)

1. `_VISUAL_MERGE_KEY_FIELDS["regional_conditions"]`에 `"지표세부범주"`를
   `"지표명"` 앞 위치에 추가:
   `["지자체명", "지표범주", "지표세부범주", "지표명", "연도"]`.
2. `_VISUAL_OPTIONAL_KEY_FIELDS`에 `"지표세부범주"` 추가 — 기존 세부부문과
   같은 와일드카드 의미론(`_visual_keys_match`): **한쪽이라도 공란이면 그
   필드는 무시하고 매칭**. 효과:
   - 시각-시각: 두 행 모두 세부범주가 있고 서로 다르면 키가 갈라져 충돌 해소.
   - G5 텍스트 교차검증: 텍스트 행은 세부범주가 공란인 경우가 많아
     와일드카드로 기존 매칭이 보존된다.
3. G3 필수 키 검사는 `_VISUAL_OPTIONAL_KEY_FIELDS` 제외 방식이 이미 구현돼
   있으므로(`required_key_fields`) 추가 작업 없음 — 세부범주 공란 후보가
   G3에서 차단되지 않는지 테스트로 확인만 한다.
4. **알려진 트레이드오프(명세 승인 사항, 코드로 막지 말 것)**: 텍스트 행과
   시각 행의 세부범주가 둘 다 비공란인데 어휘가 다르면 G5 매칭에서 빠져
   visual_only로 병합될 수 있다 — 서로 다른 세부범주는 다른 지표로 본다는
   키 의미론의 일관된 귀결이며, 실측 절차에서 생략/경고 변화로 관찰한다.

### S2 기본 활성화 (config.py)

`config.py:193`의 기본값 전환:
```python
VISUAL_MERGE_LABELED_ENABLED = _env_bool("VISUAL_MERGE_LABELED_ENABLED", True)
```
env `VISUAL_MERGE_LABELED_ENABLED=0`으로 끄는 경로는 그대로 살아 있어야 한다.
README에 이 플래그의 기본값 서술이 있으면 갱신, 없으면 추가하지 않는다.

### S3 테스트

1. 차트 간 충돌 해소: 같은 (지표범주, 지표명, 연도)에 세부범주가 다른
   관찰값 2건이 **둘 다 병합**되고 V3 경고 0.
2. 와일드카드 보존: 세부범주 공란 시각 후보가 세부범주 있는 기존 시각 행과
   같은 (범주, 지표명, 연도)이면 기존대로 중복 판정(생략/경고) — 공란
   와일드카드 의미론 확인.
3. G3 무영향: 세부범주 공란 후보가 "G3 1차 키 누락"으로 차단되지 않음.
4. 기본값: config 재로드 없이 `VISUAL_MERGE_LABELED_ENABLED`가 True이고
   env=0이면 False가 되는지(기존 _env_bool 경로) 확인.
5. **기존 테스트 전수 통과가 원칙.** 기본 True 전환으로 깨지는 기존 테스트는
   "기본 off"를 명시적으로 단언하던 것에 한해 monkeypatch 또는 기대값을
   수정하되, 수정 목록과 사유를 커밋 메시지에 남긴다. 그 외 실패는 구현
   결함으로 보고 고친다.
