## 0. 프로젝트의 진짜 목표 (발주자 의도)

> 본 프로젝트는 차트·표·그림·그래프 등이 혼재된 한글(HWP) 정부 문서를 입력으로 받아
> 문서의 구조와 의미를 자동으로 이해하고 핵심 정량 정보를 추출하여 엑셀과 같은
> 구조화된 스프레드시트 형태로 변환하는 멀티모달 AI 시스템을 설계·구현하는 것을
> 목표로 한다. 텍스트 인식(OCR), 레이아웃 분석, 표·차트 해석, 의미 기반 정보 정렬
> 과정을 단계적으로 구현하며, 실제 공공 문서에서 발생하는 난독성·비정형성 문제를
> 해결하는 실무형 파이프라인.

해석과 우선순위 (발주자가 명시한 것):

1. **본질은 시각 데이터다.** 지자체 문서에는 텍스트만으로 처리할 수 없는 비정형
   데이터 — 그래프, 표, 이미지, 이미지로 된 그래프 — 가 혼재한다. 이것을
   시각적 수단(OCR/VLM/vision LLM 무엇이든)으로 **완벽하게 추출·정리해내는 것**이
   프로젝트의 핵심이다. OCR 같은 특정 기술의 사용 여부는 본질이 아니다 —
   **가장 성능이 좋은 수단을 쓴다.**
2. **비정형성이 문제의 원인이다.** 지자체마다 같은 내용을 전혀 다른 서식·구조로
   작성한다. 원래 사람이 문서를 하나하나 보고 검증하며 정리하던 일을 파이프라인이
   대체해야 한다.
3. **가이드라인 md 고정은 의도적 스코프 결정이다.** 원래 비전은 가이드라인
   HWP 자체도 입력으로 받아 맨 앞단에서 추출하는 것이지만, "지자체 문서는 바뀌어도
   가이드라인은 고정"이므로 가이드라인을 미리 `carbon_guideline.md`로 구조화해 두고
   지자체 문서 변환을 먼저 완성한다. 가이드라인 일반화는 **최후 단계**.
4. **HWP 직접 입력은 최후순위.** 현재 지자체 문서(PDF) 처리도 완성되지 않았으므로,
   HWP 멀티모달 패리티는 PDF 경로가 완성된 뒤로 미룬다.

## 2. 마일스톤

### M1. 골든셋 + 정확도 측정 하네스 — 모든 것의 전제

"완벽하게"는 측정 없이는 달성도, 개선도 불가능하다. **시각 데이터가 핵심이므로
골든셋에 시각 요소 유형별 정답을 반드시 포함한다.**

- M1-1 (사람 작업): 서울 골든셋 확정. 기존 수작업본
  `서울특별시_탄소중립계획_정리.xlsx`를 17시트 스키마로 정리하되, 각 정답 행에
  **원문 출처 유형**(본문 텍스트 / 텍스트 표 / 이미지 표 / 그래프 / 이미지)을
  표기한다 — 이게 있어야 M2에서 "시각 유래 데이터의 리콜"을 따로 측정할 수 있다.
- M1-2 (구현): `scripts/run_ab_validation.py --golden` 연결 — 파이프라인 출력 vs
  골든셋의 시트별 리콜/정밀도 + **출처 유형별 분해 리포트**(텍스트 유래 vs 시각
  유래 정확도를 분리 산출). 행 매칭 키는 organizer의 dedup 키 체계를 재사용.
- 완료 기준: 서울 풀런 1회의 유형별 정확도 숫자가 나온다. 이 숫자가 이후 모든
  마일스톤의 기준선(baseline)이다.

### M2. 시각 데이터 추출 완성 — 프로젝트의 본질 (최우선 개발 트랙)

목표: 텍스트로 못 뽑는 데이터(그래프·이미지 표·이미지화된 차트·스캔 페이지)를
**가장 성능 좋은 수단으로** 추출해 본 시트까지 정확하게 반영한다. 수단은 열려
있다(vision LLM 풀페이지 판독, 전용 OCR, 레이아웃 모델 등) — M1의 측정으로 골라라.

- M2-1 **시각 요소 인벤토리 리콜 감사**: 서울 문서의 모든 차트·이미지 표·그래프
  목록(사람이 1회 작성)과 `16_시각자료목록`을 대조 — triage가 놓치는 요소 파악.
  필요 시 triage 임계 완화/벡터 차트 렌더링 승격 규칙 확장.
- M2-2 **텍스트리스 페이지 VLM 우회 경로**: 페이지 텍스트가 임계
  (`MIN_DOCUMENT_TEXT_CHARS` 계열) 미만인 페이지를 PyMuPDF로 렌더링해
  `STAGE_PROVIDER_VISION` 백엔드로 풀페이지 추출하는 경로 신설. 기존 이미지
  파이프라인 인프라(렌더링·vision 호출·병합 게이트) 재사용. 결과 행은
  `데이터상태=visual_only`. 스캔본 문서가 "경고 후 빈 엑셀"에서 "시각 추출로
  처리됨"으로 바뀐다.
- M2-3 **VLM 성능 벤치마크**: 같은 시각 요소 셋에 대해 후보 모델
  (Gemini 2.5 Pro vs Flash, Claude vision, GPT vision — `STAGE_MODEL_VISION`으로
  교체만 하면 됨)을 골든셋 채점으로 비교, 최고 성능 모델을 vision 스테이지
  기본값으로. 필요 시 이미지 전처리(해상도·크롭) 튜닝 포함.
- M2-4 **병합 정책 데이터 근거 완화**: 현재 "표 유형+high confidence만 자동 병합"
  이라는 보수 정책을, M1 측정에서 그래프 판독 정확도가 임계(예: 95%) 이상인
  유형부터 단계적으로 본 시트 병합 허용. `데이터상태=visual_only`로 추적성 유지,
  검증리포트에 병합 근거 기록. **측정 없이 완화 금지.**
- M2-5 **텍스트-시각 교차 검증**: 같은 수치가 본문 텍스트와 차트 양쪽에 있으면
  대조해 불일치 시 검증리포트 경고(기존 교차 검증 패스에 추가) — 시각 추출의
  자체 신뢰도 신호로 활용.
- 완료 기준: 골든셋의 **시각 유래 정답 행 리콜/정밀도가 텍스트 유래와 대등한 수준**
  (구체 목표치는 M1 기준선을 보고 설정).

### M3. 타지자체 일반화 — 비정형성 증명

- 레포의 강원·경기 PDF로 풀런 → 골든셋이 없으므로 우선 검증리포트·행수·라우팅
  커버리지 기반 진단 → 서울 과적합 지점(라우팅 키워드, 장 경계 패턴, 관리번호
  형식, 부문 표기) 교정. 여력이 되면 1개 지자체 골든셋 추가 제작.
- 완료 기준: 최소 2개 타지자체 문서가 사람 개입 없이 완주하고, 검증리포트가
  가리키는 문제 행 비율이 서울 수준.

### M4. 정확도 수렴 루프 — "사람 검증 대체" 달성

- M1 하네스로 측정→수정→재측정 반복. 보류 중인 opt-in(라우팅 샤프닝, 시트
  클러스터링)을 골든셋 게이트 통과 시 활성화. 기존계획 행 자동 이동, 잘못된
  JSON 캐시 정리, `-r` 캐시 공회전 등 이연 항목도 이 루프에서 처리.
- 완료 기준: 목표 정확도(팀이 설정, 예: 시트별 리콜 ≥95%·정밀도 ≥98%) 달성 +
  main 머지. 이 시점부터 실무 투입(사람은 검증리포트·17/18 시트가 지목한 행만 확인).

### M5. HWP 직접 입력 멀티모달 패리티 (후순위 — 발주자 지시)

- 권장 경로: HWP→PDF 변환을 앞단 스텝으로 추가(한컴/LibreOffice CLI)하고 기존
  PDF 멀티모달 경로 전체를 재사용. kordoc 이미지 추출 직접 구현보다 훨씬 싸다.
- 완료 기준: 같은 문서의 HWP 입력과 PDF 입력이 대등한 골든셋 점수.

### M6. 가이드라인 프런트엔드 일반화 (최후 단계)

- 임의의 가이드라인 HWP를 받아 현재의 `carbon_guideline.md`(시트 앵커·컬럼 표·
  매핑 규칙 포함)를 자동 생성하는 전처리기. v5의 구조적 주입 덕분에 이 단계는
  "HWP → 구조화 md 생성기" 문제로 축소되어 있다 — md만 만들면 파이프라인 전체가
  그대로 동작한다. 부록 참조 사전 생성(`scripts/build_reference_data.py`)도 같은
  프런트엔드에 편입.
- 완료 기준: 새 가이드라인 HWP 하나로 md·참조 CSV·앵커가 자동 생성되고 기존
  파이프라인이 무수정 동작.

## 3. 순서와 의존성

```
M1 (골든셋+측정) ──┬─▶ M2 (시각 데이터 완성)  ← 프로젝트의 본질, 최우선
                   ├─▶ M3 (타지자체 일반화)   ← M2와 병행 가능
                   └─▶ M4 (수렴 루프·실무 투입)  ← M2·M3 결과를 소비
M4 완료 후 ─▶ M5 (HWP 패리티, 후순위) ─▶ M6 (가이드라인 일반화, 최후)
```

- M1이 유일한 하드 선행 조건이다. M1-1(골든셋 제작)은 사람 작업이므로 **지금 즉시
  시작**하고, 그동안 에이전트는 M1-2(하네스)와 M2-1(인벤토리 감사)을 진행할 수 있다.
- M2 내부에서 M2-2(텍스트리스 우회)와 M2-3(벤치마크)은 골든셋 완성 전에도 착수
  가능하다(채점만 골든셋 대기).

## 4. 전 마일스톤 공통 원칙 (기존 명세서들과 동일)

1. opt-in 플래그 기본값 변경 금지, 검증된 게이트 통과 전 라우팅 로직 수정 금지.
2. OrganizerAgent는 결정론적 순수 Python 유지(LLM 호출 금지).
3. 엑셀 시트 계약(시트명·컬럼 이름/순서) 불변, 컬럼 추가는 맨 뒤 + opt-out 플래그.
4. 조용한 데이터 유실 금지 — 실패·불확실은 원장·검증리포트·데이터상태로 드러낸다.
5. 코드·주석·로그 한국어. 새 외부 의존성은 필요 최소한(M2에서 OCR 엔진 도입 시
   대안 대비 성능 근거를 문서로 남길 것).
6. 각 마일스톤은 구현 전 상세 명세서 작성 → 구현 → 기존 테스트 전체 + 신규 회귀
   테스트 → 커밋별 테스트 통과(bisect 안전) → 검증 후 푸시 순서를 따른다.
