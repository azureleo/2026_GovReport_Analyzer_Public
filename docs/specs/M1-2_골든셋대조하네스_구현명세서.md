# M1-2 골든셋 대조 하네스 구현명세서

> 기준 문서: `docs/specs/프로젝트_마일스톤_로드맵.md` §M1.
> 대상 브랜치: `feat/v5-guideline-orchestration` (푸시된 브랜치 — 히스토리 재작성 금지, 일반 커밋만).
> 이 문서는 대화 맥락 없이 코드베이스만으로 구현 가능해야 한다. 모호하면 보수적(동작 불변) 선택.
> 목적: 파이프라인 출력 xlsx vs 골든셋 xlsx의 시트별 리콜/정밀도/값일치율 + **출처유형별
> (텍스트 유래 vs 시각 유래) 분해 리포트**를 LLM 토큰 0으로 산출하는 채점기.
> 이 숫자가 M2~M4 전체의 기준선(baseline)이 된다.

## 절대 제약

1. **파이프라인 코드 동작 불변.** `main.py`, `agents/*`, `utils/*`의 실행 경로를 바꾸지
   않는다. 허용되는 변경은 두 가지뿐: ① `scripts/` 신규 스크립트, ② 재사용을 위해
   `agents/organizer_agent.py`의 기존 private 함수에 **공개 별칭을 추가**하는 것
   (함수 본문 수정 금지, 별칭 추가만).
2. opt-in 플래그 기본값 변경 금지, 라우팅 로직 수정 금지, OrganizerAgent 순수 Python 유지.
3. 엑셀 시트 계약(시트명·컬럼 이름/순서) 불변.
4. 채점기는 **LLM 호출 0회** — openpyxl + 순수 Python만.
5. 코드·주석·로그·리포트 한국어. 새 외부 의존성 금지(openpyxl·pytest는 기존 의존성).
6. 기존 테스트 128개 전부 통과 + 신규 회귀 테스트. 커밋별 테스트 통과(bisect 안전).
   **push 금지.**

## 범위 밖 (하지 말 것)

- 골든셋 xlsx 제작 자체 — M1-1 사람 작업. 이 명세서는 **형식 계약**만 정의한다.
- 채점 결과에 따른 파이프라인 수정(라우팅·프롬프트·병합 정책) — M2/M4에서.
- `16_시각자료목록` 채점 — M2-1 인벤토리 감사가 담당(이 하네스는 00~15만).
- CI 게이트/`--fail-under` — 기준선이 나온 뒤 M4에서.

## 1. 골든셋 엑셀 형식 (M1-1 사람 작업 계약 — 하네스는 이 형식만 읽는다)

### 1.1 파일·시트

- 경로: `data/golden/서울특별시_골든셋_v1.xlsx` (하네스는 경로를 인자로 받으므로 파일명은 자유).
- 시트명: `config.EXCEL_HEADERS`의 계약 시트명과 **정확히 동일** — `00_문서메타` ~
  `15_변경과제_조치` 16개. (`16_시각자료목록`·`90_코드북`은 있어도 무시.)
- **부분 골든 허용**: 없는 시트는 채점 생략하고 리포트에 "골든 없음"으로 표기.
  행이 일부만 작성된 시트도 그대로 채점한다(리콜의 분모는 골든 행 수).

### 1.2 헤더 (중요 — 기존 수작업본과 다른 점)

- **1행 = 헤더 행.** 제목 행 금지. (기존 `output/서울특별시_탄소중립계획_정리.xlsx`는
  1행이 "00. 문서·계획 메타" 같은 제목이라 그대로 쓸 수 없다 — M1-1에서 제거할 것.)
- 헤더는 `config.EXCEL_HEADERS[시트명]`의 계약 컬럼을 **같은 이름·같은 순서**로 쓰되,
  `출처페이지`·`데이터상태` 두 컬럼은 생략한다(파이프라인 산출 전용).
- 계약 컬럼 뒤에 골든 전용 컬럼 4개를 이 순서로 추가한다:

| 컬럼 | 필수 | 값 |
|---|---|---|
| `골든_출처유형` | 필수(00 제외) | 아래 1.3의 5개 코드 중 하나 |
| `골든_출처페이지` | 필수(00 제외) | PDF 1-기준 페이지. 복수면 콤마 오름차순 `"161"`, `"12,13"`. 구간 표기(`12~15`) 금지 |
| `골든_채점제외` | 선택 | `1`이면 그 행은 분모·분자 모두에서 제외(모호·중복 행 격리용). 사유는 비고에 |
| `골든_비고` | 선택 | 자유 텍스트 |

- 하네스는 `골든_` 접두 컬럼과 계약 외 컬럼을 값 비교에서 무시한다(작업 편의 컬럼 허용).

### 1.3 출처유형 코드 (5종 고정 — 로드맵 M1-1 문구 그대로)

| 코드 | 정의 |
|---|---|
| `본문텍스트` | 문장·서술형 본문에서 읽은 값 |
| `텍스트표` | PDF 텍스트 레이어가 살아 있는 표 |
| `이미지표` | 이미지로 렌더링된 표(텍스트 레이어 없음) |
| `그래프` | 막대·선·원 등 차트(벡터·이미지 불문)에서 읽은 값 |
| `이미지` | 그 외 이미지·그림·도식에서 읽은 값 |

- 한 행의 값이 여러 출처에 있으면 **주 출처 하나**를 적고 나머지는 `골든_비고`에.
  판단 규칙: 시각 출처(이미지표/그래프/이미지)가 하나라도 있으면 시각 쪽을 주 출처로
  적는다 — M2의 목적이 "시각 유래 리콜" 측정이므로 시각 커버리지를 보수적으로 넓게 잡는다.
- 리포트의 2분류 집계: 텍스트 유래 = {본문텍스트, 텍스트표}, 시각 유래 = {이미지표, 그래프, 이미지}.

### 1.4 값 작성 규칙 (사람 작업 지침)

1. 수치는 **숫자 셀**로(텍스트 셀 금지), 천 단위 콤마 금지. 단위는 단위 컬럼에만.
2. 원문이 "천 tCO2eq" 단위면 값은 원문 숫자 그대로 적고 단위 컬럼에 `천 tCO2eq`
   (스케일 환산은 하네스·organizer 몫이 아니라 비교 시 단위 컬럼까지 함께 본다).
3. 연도는 4자리 정수. 연도 구간 데이터는 **연 단위 행으로 분해**해서 작성.
4. `관리번호`는 원문 표기 그대로(`R-01` 등) — 정규화는 하네스가 한다.
5. 부문·배출유형 등 코드성 필드는 원문 표기 그대로 — 정규화는 하네스가 한다.
6. 값이 원문에 없으면 빈칸. `-`, `없음`, `N/A` 같은 대용 문자 금지.
7. `00_문서메타`는 1행 가로형 그대로 작성(골든_출처유형·출처페이지는 생략 가능,
   비고만 사용). 필드 단위로 채점된다.

## 2. 채점기 `scripts/score_against_golden.py`

### 2.1 CLI

```
python scripts/score_against_golden.py <파이프라인출력.xlsx> <골든셋.xlsx> \
    [--report-dir output] [--json] [--label 라벨]
```

- LLM 토큰 0, 네트워크 0. 종료 코드는 파일/형식 오류에만 비0 — 점수 자체로는 실패하지
  않는다(측정 도구이지 게이트가 아님).
- 산출물: `{report-dir}/golden_score_{label|timestamp}.md` + (옵션) 같은 이름 `.json`.
- 골든 헤더가 1.2 계약과 다르면(계약 컬럼 누락, 1행이 제목 행으로 추정 등) 시트별로
  명확한 한국어 오류를 모아 출력하고 해당 시트는 채점 생략 — **조용히 넘어가지 않는다**.

### 2.2 정규화 (organizer 재사용 — 복제 금지)

- 키 텍스트: `agents/organizer_agent.py`의 `_dedup_key_text`(내부적으로
  `normalise_key_text` + 공백 제거)를 재사용. 공개 별칭 `dedup_key_text = _dedup_key_text`
  를 organizer 말미에 추가하고 스크립트·테스트는 별칭만 임포트한다.
- 관리번호: `_normalize_project_id` 재사용(동일하게 공개 별칭 `normalize_project_id`).
- 수치 파싱: `_to_float` 재사용(공개 별칭 `to_float`).
- 페이지 문자열: `_normalize_provenance_pages` 재사용(공개 별칭 추가) — 출처페이지
  겹침 통계(2.5)용.
- 별칭 3~4개 추가 외에 organizer 수정 금지. (선례: `scripts/verify_routing_coverage.py`가
  `extractor_agent`의 내부 함수를 쓰지만, 이번에는 별칭으로 의존을 명시화한다.)

### 2.3 행 매칭

시트별 매칭 키(아래 표). `지자체명`은 모든 키에서 제외한다(단일 문서 채점이므로 변별력
없고, 골든/출력 간 표기 차이("서울시" vs "서울특별시")로 인한 허위 미스만 만든다).

| 시트 | 1차 키(엄격) | 2차 키(완화 — 1차 미매칭 잔여끼리만) |
|---|---|---|
| 01_계획개요 | 개요유형+항목명 | 항목명 |
| 02_지역여건 | 지표범주+지표명+연도 | 지표명+연도 |
| 03_배출현황_지역 | 배출유형+부문+세부부문+연도 | 배출유형+부문+연도 |
| 04_배출현황_관리권한 | 관리부문+세부부문+직간접구분+연도 | 관리부문+연도 |
| 05_배출전망 | 시나리오+부문+연도 | 부문+연도 |
| 06_감축목표 | 목표수준+목표범위+부문+목표연도 | 부문+목표연도 |
| 07_비전전략 | 전략수준+전략명 | 전략명 |
| 08_감축사업목록 | 관리번호(정규화) | 사업명 |
| 09_연차별이행계획 | 관리번호+연도 | 사업명+연도 |
| 10_정량감축량 | 관리번호+연도+모니터링인자 | 사업명+연도 |
| 11_재정투자계획 | 계획구분+부문+사업명+재원구분+연도 | 부문+재원구분+연도 |
| 12_대응기반강화 | 과제ID(있으면), 없으면 대응기반영역+과제명 | 과제명 |
| 13_이행관리환류 | 거버넌스기구+절차단계 | 거버넌스기구 |
| 14_점검실적 | 점검연도+관리번호 | 점검연도+사업명 |
| 15_변경과제_조치 | 점검연도+관리번호 | 사업명 |

- 02~06은 organizer의 dedup 키 체계(`_deduplicate_rows` 호출부)와 동일 집합에서
  지자체명만 뺀 것 — 로드맵의 "dedup 키 체계 재사용" 요구.
- 매칭은 두 pass: ① 1차 키 완전 일치(정규화 후), ② 잔여 행끼리 2차 키 일치.
  같은 키에 복수 행이 있으면 순서대로 1:1 탐욕 매칭(초과분은 미매칭). 2차 키로 맺어진
  매칭은 리포트에 "완화매칭"으로 별도 카운트한다.
- 관리번호 빈 행은 1차 키를 건너뛰고 2차 키로만 매칭.
- `골든_채점제외=1` 행은 로드 시점에 제거(제외 수는 리포트에 표기).

### 2.4 값 비교 (키 매칭된 쌍에 대해)

- 시트별 **핵심 값 필드**에서만 값일치율을 산출한다:
  02 `값·단위` / 03 `배출량·단위` / 04 `배출량·단위` / 05 `전망값·단위` /
  06 `기준배출량·배출전망·목표감축량·목표배출량·감축률(%)` / 09 `목표물량` /
  10 `활동량·예상감축량` / 11 `예산액·예산단위` / 14 `달성여부`.
  나머지 시트(01·07·08·12·13·15)는 텍스트성이라 매칭율만 1차 지표로 삼고 값일치율은
  산출하지 않는다(필드별 채움 여부만 참고 표기).
- 수치 비교: 양쪽 `to_float` 후 상대오차 ≤ 0.5% 이면 일치 — organizer
  `_values_conflict`의 0.005 기준과 동일. 한쪽만 빈칸이면 "골든만 있음/출력만 있음"으로
  각각 카운트(불일치와 구분).
- 텍스트 비교(`단위`·`달성여부` 등): `dedup_key_text` 동등이면 일치.
- `06_감축목표`의 감축률 컬럼 실제 헤더는 `감축률(%)` — 헤더 문자열 그대로 읽는다.

### 2.5 리포트 내용

md 리포트에 다음을 포함한다(json도 동일 구조):

1. **시트별 표**: 골든 행수 / 출력 행수 / 매칭 수(엄격·완화 구분) / 리콜 / 정밀도 /
   값일치율 / 골든만 있는 값 / 출력만 있는 값.
2. **출처유형별 분해** (핵심 산출물): `골든_출처유형` 5종 각각 + 텍스트 유래/시각 유래
   2분류의 리콜·값일치율. 전 시트 합산 + 수치 시트(02~06·09~11·14)만의 합산을 둘 다.
3. **미매칭 상세**: 골든 미매칭 행 전량을 시트·키·골든_출처유형·골든_출처페이지와 함께
   나열(사람 확인용 — 조용한 유실 금지). 출력 측 미매칭(정밀도 손실) 행도 동일하게.
4. **값 불일치 상세**: 필드별 골든 값 vs 출력 값 나열.
5. **출처페이지 참고 통계**: 매칭 쌍에서 출력 `출처페이지`와 `골든_출처페이지`의 교집합
   존재 비율(같은 값을 다른 페이지에서 읽었는지 참고 신호 — 채점에는 미반영).
6. 헤더에 실행 정보: 두 파일 경로, 시각, 채점제외 행 수, 형식 오류로 생략된 시트.

## 3. `run_ab_validation.py --golden` 연결

- 현재 `--golden`은 `verify_routing_coverage.py`만 호출한다. 이를 유지한 채, 스니펫/구조
  두 결과 xlsx 각각에 대해 `score_against_golden.py`를 서브프로세스로 실행하고 요약
  섹션("골든셋 채점 — 스니펫", "골든셋 채점 — 구조")을 A/B 리포트에 추가한다.
- 단, `verify_routing_coverage.py`는 제목행 형식의 구 정리본을 전제로 앵커를 수확하므로
  **새 골든셋 형식에서도 동작하는지 확인만** 하고(1행이 헤더여도 `_harvest_anchors`는
  셀 단위 수확이라 무해할 것으로 예상), 수정이 필요하면 별도 커밋으로 최소 수정.
- 단독 채점(`score_against_golden.py` 직접 실행)이 주 사용 경로다 — A/B 연결은 부가.

## 4. 테스트 (`tests/test_score_against_golden.py`)

합성 워크북을 openpyxl로 만들어(픽스처 파일 커밋 금지, 코드로 생성) 최소 다음을 검증:

1. 키 매칭: 03 시트에서 동일 키 행이 매칭되고 리콜/정밀도가 손으로 계산한 값과 일치.
2. 정규화 매칭: 관리번호 `R-01` vs `R1`, 공백·전각 차이가 있는 텍스트 키가 매칭됨.
3. 완화 매칭: 세부부문이 골든에만 있는 행이 2차 키로 매칭되고 "완화매칭"으로 집계됨.
4. 수치 허용오차: 상대오차 0.4%는 일치, 1%는 불일치.
5. 출처유형 분해: 그래프 2행 중 1행만 매칭 → 시각 유래 리콜 0.5.
6. `골든_채점제외=1` 행이 분모에서 빠짐.
7. 골든에 없는 시트 → 채점 생략 + 리포트 표기. 계약 컬럼이 빠진 시트 → 오류 표기 +
   해당 시트만 생략.
8. 00_문서메타 필드 일치율(기준연도 일치, 목표연도 `2033,2050` 같은 다중값은
   집합 비교).
9. organizer 공개 별칭이 기존 private 함수와 동일 객체임(동작 불변 증명).
