## S1. 직간접구분 값 정규화 — P0 (채점·dedup 정합성)

**증상(실측)**: 골든셋(codex 유래)의 `직간접구분="direct"` vs gemini 추출 `"직접"`.
`04_배출현황_관리권한`의 dedup·채점 키가 직간접구분을 포함하므로 표기 차이만으로 키가
깨지고, 채점기에서 완화키(관리부문+연도)로 흘러 **오결합 다발**(04 값일치율 0.49의
주원인이 이 아티팩트). 파이프라인 자체 dedup에서도 같은 원인으로 중복 행이 남을 수 있다.

**수정**: `agents/organizer_agent.py`의 `_clean_emissions_management`에서 직간접구분을
정규화하는 순수 매핑을 추가한다: {"direct","Direct","직접배출"}→"직접",
{"indirect","Indirect","간접배출"}→"간접". 그 외 값은 원문 유지(발명 금지).
매핑 표는 모듈 상수로 두고 공개 별칭으로 노출해 채점기(`golden_score_contract.키값`)도
같은 표를 재사용한다(복제 금지).

**수용**: "direct" 행과 "직접" 행이 같은 dedup 키로 병합되는 단위 테스트 +
채점기에서 양 표기가 엄격키로 매칭되는 테스트.

## S2. 04 시트 완화키 과소식별 보정 — P0 (채점기만)

**증상(실측)**: `scripts/golden_score_contract.py` `이차키["04_배출현황_관리권한"]=
["관리부문","연도"]`가 너무 느슨해서, 같은 (부문,연도)의 상이한 세부부문 행들이
잘못 짝지어짐(골든 3453 vs 출력 102 같은 무관 쌍 다수 실측).

**수정**: 이차키를 `["관리부문","직간접구분","연도"]`로 강화(S1 정규화 전제).
파이프라인 코드는 건드리지 않는다 — `이차키` 딕셔너리 한 줄 + 테스트.

**수용**: 세부부문만 다른 두 행이 완화 단계에서 서로 엉키지 않는 회귀 테스트.
서울 실채점(gemini_v5 vs 골든)에서 04 값일치율이 개선되는지 수치 확인(리포트 첨부).

## S3. gemini SDK 클라이언트 타임아웃 — P0 (파이프라인 신뢰성)

**증상(실측)**: 503 폭풍 중 gemini 호출 1건이 응답 없는 연결에 매달려 **35분+ 완전
정지**(CPU 증가 0, 로그 0 — 2026-07-06 run1, kill로만 해소). SDK 기본 타임아웃 부재.

**수정**: `utils/llm_client.py`의 gemini 클라이언트 생성/호출에 요청 타임아웃을 설정한다
(google-genai의 `http_options` timeout — SDK 버전에 맞는 방식 확인). config에
`GEMINI_REQUEST_TIMEOUT_SECONDS`(기본 180) 신설, env 오버라이드 가능. 타임아웃 발생 시
기존 재시도 루프가 이어받는다(새 의미론 금지 — 그냥 "행 대신 오류"로 바꾸는 것).

**수용**: mock으로 타임아웃 발생 시 재시도 경로 진입 테스트. 기본값 180초 문서화.

## S4. M1-2 검증 LOW 3건 — P1 (채점기 품질)

1. **값일치율 분모 정의**: 현재 `값일치율=일치/전체`에서 전체가 "한쪽만 빈칸"을 포함해
   정확도와 커버리지가 섞임. 분모를 "양쪽 값 존재 쌍"으로 바꾸고, 골든만/출력만은
   기존대로 별도 컬럼 유지(리포트 컬럼 추가 없음 — 계산식만 변경, 리포트 문서에 정의 1줄).

   **경고 수집**(시트 무효화 금지 — 행 단위 경고를 리포트 실행 정보에 나열).
3. **컬럼-누락 형식오류 분기 테스트**: `workbook.py`의 "계약 컬럼이 명세와 다름" 분기와
   "골든_ 컬럼 없음" 분기에 회귀 테스트 추가(현재 제목행 경로만 테스트됨).

## S5. gemini 의존성 셋업 갭 — P1

**증상(실측)**: 신규 환경에서 기본 백엔드(gemini) 실행 시
`google-genai`/`google-api-core` 부재로 즉시 실패. 게다가 `google-api-core`만 없어도
오류 메시지가 "google-genai 패키지를 설치하세요"로 **오안내**(llm_client.py:978-983의
3중 임포트가 한 try에 묶임).

**수정**: ① `requirements.txt`에 `google-genai`, `google-api-core` 추가.
② 임포트 실패 메시지가 실제 누락 모듈명을 안내하도록 개선(ImportError의 모듈명 사용).

**수용**: 각 모듈 부재 mock 시 올바른 모듈명이 메시지에 나오는 테스트.
