# 골든 채점기 의미완화(3차) 매칭 구현명세서

> 대상 브랜치: `feat/v6-measurement-baseline` (HEAD 2e7e064 이후). 새 브랜치
> `feat/score-semantic-relax` + **별도 worktree** 필수.
> M1-2 채점 하네스(`scripts/golden_score_*.py`)의 확장. 파이프라인 코드 무변경.
> 이 문서만으로 구현 가능해야 한다. 모호하면 보수적 선택.

## 측정 근거

1. 시각 골든 편입(2e7e064) 후 첫 시각 리콜 실측 0.013(4/308) — 원인은 추출
   실패가 아니라 **02 지표명·분류 명명의 골든-파이프라인 발산**
   (`docs/golden/시각정답_사람확인목록.md` "첫 시각 리콜 실측과 진단" 절):
   골든 "경제산업/수송·교통/자동차 등록 대수(휘발유)" vs 출력
   "인문사회/교통/자동차 등록 대수" — 같은 원천 데이터가 키 불일치로 미매칭.
2. 현 채점기는 2단 매칭(엄격=일차키, 완화=이차키, `golden_score_matching.매칭하기`)
   이며 두 단 모두 키 문자열 **정확 일치**라 명명 발산을 흡수하지 못함.
3. v5.3 교훈: 무분별한 완화 매칭은 가짜 매칭을 만든다(S4에서 20건 제거) —
   의미완화는 값 일치를 전제로 하는 **진단 전용 티어**로 격리해야 한다.

## 목표

`매칭하기`에 3차 "의미완화" 티어를 추가해 "파이프라인이 같은 값을 의미상 같은
지표로 추출했는가"를 측정한다. **헤드라인 지표(리콜·정밀도·값일치율)의 정의와
숫자는 불변** — 의미완화는 별도 칼럼·절로만 보고한다. 부산물로 골든-출력
지표명 대응 쌍 목록을 남겨 향후 명명 규약(로드맵 후보 ①)의 재료로 쓴다.

## 절대 제약

1. **기존 숫자 불변**: 동일 (출력, 골든) 입력에 대해 기존 리포트의 모든 절
   (시트별 표의 기존 칼럼, 출처유형별 분해, 미매칭 상세)의 수치가 바이트
   수준으로 동일해야 한다. 의미완화 매칭 행은 기존 `matches` 집계·값일치율
   분자·분모에 절대 포함하지 않는다.
2. 적용 시트는 **02_지역여건만**(발산 실증 시트). 시트 목록은 모듈 상수로 두어
   실측 후 확장 가능하게 하되 이번 라운드에서는 02만.
3. 채점기(`scripts/golden_score_contract.py`, `golden_score_matching.py`,
   `golden_score_report.py`, 필요시 `score_against_golden.py`)만 수정.
   파이프라인·organizer·프롬프트·골든 데이터 무변경. LLM 호출 0 유지.
4. 지자체 불변 — 토큰화·정규화는 일반 규칙만, 특정 지자체·문서 어휘 금지.
5. 코드·주석·커밋 한국어, 커밋별 `python -m pytest tests/ -q` 통과, push 금지.

## 1. 의미완화 매칭 규칙 (02_지역여건)

3차 패스: 엄격·완화 종료 후 남은 `remaining_golden × remaining_output`에서만.

매칭 조건 (전부 필수):
1. **연도 일치**: `키값("연도", …)` 기준 정확 일치. 어느 한쪽이라도 연도가
   비면 후보 아님.
2. **단위 일치**: 양쪽 모두 단위가 있으면 `dedup_key_text` 정규화 후 일치해야
   함(예: '천대'='천 대'). 한쪽이라도 비면 이 조건은 통과로 본다.
3. **지표명 토큰 유사**: 아래 토큰화 후 자카드 유사도 ≥ `SEMANTIC_MATCH_MIN_JACCARD`
   (모듈 상수, 기본 0.6).
4. **값 일치**: `_상대오차일치`(0.5%) 기준 값('값' 컬럼)이 일치해야 함.
   값이 어느 한쪽이라도 비면 후보 아님.

토큰화: `지표명`과 `지표세부범주`를 이어 붙인 문자열에서 괄호·구두점을 공백으로
치환 → 공백 분리 → 각 토큰 `dedup_key_text` 정규화 → 빈 토큰 제거 → 집합.
(예: "자동차 등록 대수(휘발유)" → {자동차, 등록, 대수, 휘발유}. 출력
"자동차 등록 대수"+세부범주 "교통" → {자동차, 등록, 대수, 교통} — 자카드
3/5 = 0.6 ≥ 0.6 매칭. "평균 강수량" vs "5일 최다강수량 전망" → 교집합 0 비매칭.)

후보가 여럿이면: 자카드 최고 1개 선택, 최고 동률이면 **매칭하지 않음**(보수).
1:1 유지 — 의미완화로 소비된 출력 행은 다른 골든 행과 재매칭 금지. 매칭 순서에
따른 비결정성이 없도록 골든 행 순서로 순회하고 후보는 (자카드 내림차순,
출력 행 인덱스 오름차순)으로 정렬해 재현 가능하게 한다.

값 일치가 매칭 전제이므로 이 티어는 **값일치율 통계에 넣지 않는다**(항상 1이
되어 무의미). 매칭 방식 라벨은 "의미완화".

## 2. 리포트 확장 (`golden_score_report.py`)

기존 절·칼럼은 그대로 두고 추가만:
1. 시트별 표에 "의미완화" 칼럼(해당 시트의 의미완화 매칭 수. 02 외는 0 또는 "-").
2. 출처유형별 분해(전체·수치 시트) 표 아래에 병기 행:
   "시각 유래(의미완화 포함)" — 매칭수 = 기존 + 의미완화 중 시각 유래 골든 행,
   리콜 재계산. 텍스트 유래도 동일 병기(의미완화가 텍스트 행을 잡을 수 있음).
3. 신규 절 "## 의미완화 매칭 쌍": 행마다
   `골든(지표범주/지표세부범주/지표명/연도/값) ⇔ 출력(지표범주/지표세부범주/지표명/값)`
   전부 나열(명명 규약 재료). JSON 리포트에도 동일 배열 추가.
4. 요약(실행 정보)에 "의미완화 매칭: N건(02_지역여건)" 한 줄.

## 3. 테스트 (신규 파일 `tests/test_semantic_relax_matching.py`)

1. 실증 사례 매칭: 골든 "경제산업/수송·교통/자동차 등록 대수(휘발유)/2013/1622/천대"
   vs 출력 "인문사회/교통/자동차 등록 대수(휘발유)/2013/1622/천대" → 의미완화 매칭.
2. 토큰 상이 비매칭: "평균 강수량" vs "5일 최다강수량 전망"(연도·값 동일해도) → 비매칭.
3. 값 불일치 비매칭: 지표명 유사·연도 일치·값 3116 vs 1622 → 비매칭.
4. 1:1·동률 보수: 출력 1행에 골든 2행(휘발유/LPG)이 같은 자카드로 걸리면
   값 일치하는 쪽만 매칭되고, 값까지 동률로 모호하면 비매칭.
5. **기존 숫자 불변 회귀**: 의미완화 매칭이 존재하는 픽스처에서 기존 매칭 수·
   값일치율·미매칭 목록이 의미완화 도입 전과 동일함을 검증(의미완화 티어를
   끈 상태와 비교하거나 기대값 하드코딩).
6. 02 외 시트에 의미완화가 적용되지 않음.
