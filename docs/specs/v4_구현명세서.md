# v4 구현 명세서 — 실행시간 안정화 · 유실 가시화 · 병합/검증 강화

> 대상 브랜치: `perf/optimization-v3` 위에 신규 브랜치(`feat/v4-reliability`) 생성 후 작업.
> 이 문서는 구현 담당 LLM(Opus)에게 전달되는 자기완결 명세다. 대화 맥락 없이 이 문서와
> 코드베이스만으로 구현 가능해야 하며, 모호한 부분은 "보수적(동작 불변) 선택"을 기본으로 한다.

## 0. 프로젝트 배경 (구현자가 알아야 할 최소 맥락)

이 프로그램은 환경부 가이드라인(`carbon_guideline.md`)을 기준으로 지자체 탄소중립
계획 PDF/HWP에서 데이터를 추출해 **17개 시트(16 데이터 + 1 시각자료목록) 엑셀**로
정규화하는 파이프라인이다. 원래 사람이 가이드라인과 수백 페이지 문서를 대조하며
수동 입력·수동 검증하던 작업을 LLM 파이프라인으로 대체하는 것이 목표다.
따라서 **"조용한 데이터 유실"이 최악의 결함**이고, "사람이 검증할 수 있는 근거를
남기는 것"이 두 번째로 중요하다. 속도는 그 다음이다.

파이프라인: `main.py` → `Supervisor.run()` → 문서파싱 → GuidelineAgent →
ExtractorAgent(시트별 페이지 라우팅 + 배치 추출) → ImageAgent → OrganizerAgent(결정론적
정제/dedup/검증) → GapFillAgent(빈칸 보완 재추출) → (선택)HybridReviewAgent → ExcelAgent.

현재 증상(사용자 보고 + 코드 검수로 확인됨):
1. codex/claude 로컬 에이전트 모드에서 실행 시간이 과도하게 김(수 시간).
2. 데이터는 늘었지만 중복 행이 남고(병합 실패), 일부 데이터는 조용히 유실됨.

## 1. 절대 제약 (위반 금지)

1. **opt-in 플래그의 기본값을 바꾸지 마라.**
   `EXTRACTION_SHEET_CLUSTERING`(기본 False), `ROUTE_DROP_UBIQUITOUS_STRONG`(기본 False)은
   아직 정답지 기반 무회귀 검증이 안 된 상태다. 효과·회귀 여부를 "현재는 알 수 없다"로
   간주한다. 이 명세의 어떤 작업도 이 플래그들을 켜는 것을 포함하지 않는다.
   (WP7이 검증 도구를 정비하지만, **활성화 결정은 사람이 한다**.)
2. **OrganizerAgent는 결정론적 순수 Python 유지.** LLM 호출을 추가하지 마라.
3. **엑셀 17시트 계약 유지.** 기존 시트명·기존 컬럼의 이름/순서를 바꾸지 마라.
   컬럼 추가는 이 명세가 명시한 곳(WP5)에서만, 항상 맨 뒤에 붙인다.
4. **코드·주석·프롬프트·로그는 한국어**, 기존 스타일(주석 밀도, print 로그 포맷)을 따른다.
5. 새 외부 의존성 추가 금지(표준 라이브러리 + 기존 requirements만).
6. 모든 튜닝값은 `config.py`에 두고 환경변수로 오버라이드 가능하게 한다(기존 `_env_*` 헬퍼 사용).
7. 기존 테스트(`python -m pytest tests/`)가 계속 통과해야 하며, 각 WP는 자체 테스트를 추가한다.
8. LLM 캐시(`utils/llm_cache.py`)와의 호환 유지: 같은 프롬프트 → 같은 캐시 키.
   프롬프트 문면을 바꾸는 변경(WP5)은 캐시 무효화가 자연히 일어나므로 허용되지만,
   불필요한 프롬프트 변경은 피한다.

## WP1. 실행시간 안정화 (P0)

### 문제
- `utils/llm_client.py`의 `_retry_local_call()`: 호출당 타임아웃 900초 × 연속 2회
  타임아웃이면 "throttling 추정"으로 전환 → 10분 대기 반복, 누적 상한 6시간.
  한 배치가 이 경로에 빠지면 그것만으로 30분+α가 소모되고, 병렬 4워커에서는 이런
  호출이 여러 개 동시에 잠들어 전체 실행이 수 시간으로 늘어난다.
- `utils/parallel.py`의 `parallel_map()`: 한 작업의 예외가 전체로 전파되어,
  이미 성공한 다른 배치 결과까지 통째로 버려진다.

### 변경 1-A: config 기본값 조정 (`config.py`)
```python
LOCAL_AGENT_TIMEOUT = _env_int("LOCAL_AGENT_TIMEOUT", 300)          # 900 → 300
LLM_QUOTA_WAIT_POLL_SECONDS = _env_int("LLM_QUOTA_WAIT_POLL_SECONDS", 120)   # 600 → 120
LLM_QUOTA_WAIT_MAX_SECONDS = _env_int("LLM_QUOTA_WAIT_MAX_SECONDS", 1800)    # 21600 → 1800
```
- 주석에 근거를 남긴다: 추출 호출은 정상적으로 1~2분 내 완료되므로 900초 대기는
  hang을 15분씩 방치하는 효과였고, quota 대기 상한 6시간은 "밤새 걸려도 완주"용이라
  기본값으로 부적합(원하면 env로 되돌릴 수 있음).
- `LLM_TIMEOUT_AS_QUOTA_THRESHOLD`(2)와 quota 메시지 파싱 로직은 유지한다.

### 변경 1-B: 수집형 병렬 실행 (`utils/parallel.py`)
`parallel_map()`의 시그니처와 기존 의미론(예외 전파)은 유지하되, 새 함수를 추가한다:

```python
def parallel_map_collect(fn, items, *, workers) -> list[tuple[Any, Exception | None]]:
    """items[i] → (결과, None) 또는 (None, 예외). 입력 순서 보존.
    LLMQuotaExceededError 만은 수집하지 않고 즉시 전파한다(전체 중단이 맞는 상황:
    한도 초과는 다른 배치도 어차피 실패하고, 상위 Supervisor가 단계별로 처리한다).
    그 외 예외(LLMCallError, 타임아웃 상한 초과 등)는 해당 항목의 실패로 수집하고
    나머지 작업은 계속 진행한다."""
```
- 순차 폴백(비활성/workers<=1/단일 항목)에서도 동일한 (결과, 예외) 튜플 형태를 반환.
- `LLMQuotaExceededError` 즉시 전파 시에는 기존 `parallel_map`처럼
  `executor.shutdown(wait=False, cancel_futures=True)` 후 raise.

### 변경 1-C: 호출부 전환
- `agents/extractor_agent.py`: 라우팅 모드·full-scan 모드·클러스터 모드의
  `parallel_map(...)` → `parallel_map_collect(...)`로 전환.
  - 성공 항목: 기존과 동일하게 `self._raw_results[sheet_key].extend(items)`.
  - 실패 항목: 행 추가 없이 WP2의 원장에 실패로 기록하고,
    `print(f"  [{sheet_key}] 배치 {i}/{n} ({page_range}): 호출 실패({예외타입}) — 원장 기록")`.
- `agents/gap_fill_agent.py`, `agents/image_agent.py`: 동일 패턴으로 전환.
  이미지 쪽 실패 배치는 분석 결과 없이 건너뛰되 실패 수를 최종 로그에 포함.
- Supervisor 변경 없음(각 에이전트가 예외를 삼키고 결측을 기록하므로 상위는 그대로).

### 수용 기준
- 임의 배치 1개가 `LLMCallError`를 던지도록 mock 했을 때: 파이프라인이 끝까지 완주하고,
  나머지 배치의 행은 모두 보존되며, 실패 배치가 로그와 (WP2 이후) 원장에 남는다.
- `LLMQuotaExceededError` mock 시: 기존과 동일하게 단계 수준에서 중단/스킵된다.
- 신규 테스트: `tests/test_parallel.py` — 수집형 동작, 순서 보존, quota 즉시 전파,
  순차 폴백 동등성.

## WP2. 추출 원장(extraction ledger) + JSON 파싱 실패 재시도 (P0)

### 문제
1. `utils/llm_client.py`의 `parse_json()`은 파싱 실패 시 경고 한 줄 남기고 `{}`를
   반환한다 → 그 배치의 행 전체가 **조용히 유실**되고, 어느 시트·어느 페이지가
   유실됐는지 아무 데도 남지 않는다.
2. v3의 `GAP_FILL_SKIP_ALREADY_ROUTED=True`는 "1차에서 **보낸** 페이지"를 보완
   대상에서 제외하는데, "보냈다 ≠ 추출에 성공했다". 파싱 실패/호출 실패로 유실된
   페이지는 GapFill 도 영구히 못 잡는다.

### 변경 2-A: 파싱 실패 1회 재시도 (호출부 레벨)
`parse_json()` 자체는 순수 함수로 유지한다. 대신 `utils/llm_client.py`에 헬퍼 추가:

```python
def call_text_json(prompt, system="", max_retries=config.MAX_RETRIES) -> tuple[Any, bool]:
    """call_text 후 parse_json까지 수행. 1차 파싱 실패(빈 dict인데 응답은 비어있지 않음)면
    같은 프롬프트에 재요청 지시문을 덧붙여 1회 재시도한다.
    반환: (파싱 결과, 파싱 성공 여부). 재시도까지 실패하면 ({} 또는 부분 결과, False)."""
```
- 재시도 프롬프트: 원 프롬프트 뒤에
  `"\n\n[재요청] 직전 응답이 유효한 JSON이 아니었습니다. 설명·코드블록 없이 유효한 JSON만 다시 출력하세요."`
  를 덧붙인다(캐시 키가 달라져 캐시된 불량 응답을 재사용하지 않게 됨 — 의도된 효과).
- "파싱 실패" 판정: 응답 원문이 공백/`{}` 가 아닌데 `parse_json` 결과가 `{}`인 경우,
  또는 기대 타입(dict)이 아닌 경우.
- 적용 지점: `extractor_agent._extract_sheet`, `_extract_cluster`,
  `gap_fill_agent._reextract`, `image_agent`의 JSON 기대 호출부. 각 호출부는
  `(parsed, ok)`를 받아 `ok=False`면 원장에 `parse_fail`로 기록한다.

### 변경 2-B: 추출 원장
`agents/extractor_agent.py`에 추가(새 모듈 불필요, dataclass 권장):

```python
@dataclass
class BatchRecord:
    sheet_key: str          # 클러스터 모드에서는 대표로 각 멤버 시트마다 1건씩 기록
    page_nums: list[int]
    status: str             # "ok" | "call_fail" | "parse_fail"
    rows: int               # 성공 시 추출 행 수
    error: str = ""         # 실패 시 예외 타입/요약
```
- `ExtractorAgent.ledger: list[BatchRecord]` 로 보관. GapFillAgent 도 자기 재추출을
  동일 원장 형식으로 기록(자체 리스트).
- `ExtractorAgent`에 파생 프로퍼티 추가:
  - `extracted_page_nums: dict[str, set[int]]` — **status=="ok"인 배치의 페이지만** 집계.
  - 기존 `routed_page_nums`는 유지(라우팅 통계용).

### 변경 2-C: GapFill 제외 기준 교체
- `agents/supervisor.py`: `gap_agent.enhance(...)`에 `routed_page_nums=` 대신
  `extracted_page_nums=getattr(extractor, "extracted_page_nums", None)`를 전달
  (파라미터명도 의미에 맞게 변경; 하위 호환 불필요 — 내부 API).
- 효과: 1차에서 호출/파싱 실패한 페이지는 GapFill 후보에 다시 포함된다.
- `GAP_FILL_SKIP_ALREADY_ROUTED` 플래그 이름은 유지하되 docstring/주석을
  "이미 **성공적으로 추출된** 페이지 제외"로 갱신.

### 변경 2-D: 원장 → 사용자 가시화
- Supervisor 최종 요약에 한 줄 추가:
  `[감독관] 추출 원장: 배치 N건 중 성공 X, 호출실패 Y, 파싱실패 Z (실패 페이지: p12~15, p88~90)`
- 실패가 1건 이상이면 19_검증리포트에도 심각도 "경고"로 시트별 실패 항목을 추가
  (WP6의 `_validate_final_data`에서 원장을 받아 처리; WP6 전이라면 Supervisor에서
  `cleaned["validation_report"]`에 직접 append 해도 된다 — 중복 구현하지 말고 WP6와 합칠 것).

### 수용 기준
- 특정 배치의 응답을 "이것은 JSON이 아님"으로 mock: 1회 재시도가 발생하고,
  재시도도 실패하면 원장에 `parse_fail`로 남으며 GapFill이 그 페이지들을 후보에 포함한다.
- 신규 테스트: `tests/test_extraction_ledger.py` — 원장 기록, extracted_page_nums가
  실패 배치 페이지를 제외하는지, GapFill 제외 집합이 성공 페이지 기준인지.

## WP3. dedup 키 정규화 + 값 충돌 리포트 (P1)

### 문제
`agents/organizer_agent.py`의 `_deduplicate_rows()`는 `str(값).strip()` 완전 일치
키를 쓴다. GapFill·이미지 병합으로 같은 데이터가 표기만 다르게 들어오면
(공백/가운뎃점 차이, 세부부문 `""` vs `"도로"`) 중복 행이 그대로 남는다.
또 같은 키에서 값이 충돌하면(예: 배출량이 서로 다름) 첫 행이 이기고 **충돌 사실이
아무 데도 기록되지 않는다.**

### 변경 3-A: 키 정규화 함수
```python
def _dedup_key_text(val: Any) -> str:
    """dedup 키 생성 전용 텍스트 정규화(원본 행 값은 바꾸지 않는다).
    - None → "", str(val) 후 NFKC 정규화
    - 연속 공백 → 단일 공백, strip
    - '·'/'ㆍ'/'･' → '·', '（）' → '()' 등 전각·반각 통일
    - 소문자화(영문 단위 표기 차이 흡수)"""
```
- `_deduplicate_rows`의 키 생성을 `tuple(_dedup_key_text(row.get(f)) for f in key_fields)`로 교체.
- **원본 셀 값은 절대 변경하지 않는다**(정규화는 키 비교에만 사용).

### 변경 3-B: 빈 세부키 흡수 병합
- 대상: 키 필드 중 "보조 세부 필드"(현재는 `세부부문`만, 시트별 cleaner에서 명시)가
  빈 행과 채워진 행이 공존하는 경우.
- 규칙(보수적): 나머지 키 필드가 모두 같고, 빈-세부 행의 **모든 비키 필드 값이
  채워진-세부 행과 충돌하지 않으면**(같거나 한쪽이 None) 빈-세부 행을 흡수(제거하고
  None 필드만 채움). 하나라도 값이 충돌하면 두 행 모두 유지.

### 변경 3-C: 값 충돌 리포트
- `_deduplicate_rows`가 `(rows, conflicts)` 를 반환하도록 확장하거나, 모듈 수준
  수집 리스트를 쓴다(스레드 문제 없음 — organizer는 단일 스레드).
- 충돌 정의: 같은 dedup 키에서 수치 필드(`배출량`, `전망값`, `예산액`,
  `예상감축량`, `목표배출량` 등 — 각 cleaner가 아는 값 필드)가 둘 다 non-None인데
  다른 경우(float 비교는 상대오차 0.5% 초과일 때만 충돌로 본다).
- 충돌 시 동작: 기존과 동일하게 **첫 행 유지**(순서상 텍스트 추출 → 이미지 →
  GapFill이므로 텍스트 우선이 유지됨). 단 19_검증리포트에
  `_issue(municipality, "경고", 시트명, f"중복 키 값 충돌({키요약})", f"유지값 A vs 폐기값 B", "원문 페이지 재확인")` 추가.

### 수용 기준
- 테스트 `tests/test_organizer_dedup.py`:
  - `"도로 수송"` vs `"도로수송"`, `"공원·녹지"` vs `"공원ㆍ녹지"` 가 같은 키로 합쳐진다.
  - 세부부문 빈 행 흡수: 충돌 없으면 1행, 값 충돌 있으면 2행 유지 + 리포트 1건.
  - 기존 dedup 테스트(있다면) 통과.

## WP4. GapFill 발동 기준 재설계 (P1)

### 문제
`agents/gap_fill_agent.py`의 `_needs_backfill()`은 organizer 정제 **후** 데이터로
채움률을 계산하는데, 대상 8시트 중 6시트는 organizer가 이미 값 없는 행을
`_filter_empty_rows`로 제거한 뒤라 채움률이 사실상 항상 100%다. 결국 "빈 시트"일
때만 발동하는 죽은 로직이고, 빈 시트 재추출은 임계값(2)이 낮아 노이즈 행을 만들 수 있다.

### 변경 4-A: 커버리지 술어 기반 발동
`_needs_backfill`을 시트별 커버리지 술어로 교체한다. 반환은 기존과 동일
`(needs: bool, reason: str)`.

| sheet_key | 발동 조건(하나라도 참이면 보완) |
|---|---|
| (공통) | 시트가 빈 경우 — 기존 유지 |
| `emissions_regional` | 등장 부문 수 < 4 (`config.SECTORS` 8부문 기준) 또는 연도 수 < 2 |
| `emissions_management` | 등장 관리부문 수 < 2 |
| `emissions_forecast` | 연도 수 < 2 |
| `reduction_targets` | {2030, 2050} 중 등장하지 않는 목표연도가 있음 |
| `quantitative_reductions` | 행 수 < `mitigation_projects` 행 수의 30% (사업 대비 정량감축 커버리지) |
| `financial_plan` | 연도 수 < 2 또는 부문 수 < 2 |
| `annual_implementation` | 행 수 < `mitigation_projects` 행 수의 30% |
| `regional_conditions` | 기존 채움률 로직 유지(이 시트는 cleaner가 지표명만 있어도 살리므로 채움률이 유효함) |
- 임계값(4, 2, 30% 등)은 `config.GAP_FILL_COVERAGE_THRESHOLDS` dict로 빼고 env 오버라이드 가능하게.
- 술어가 다른 시트(`mitigation_projects`)를 참조하므로 `_needs_backfill(sheet_key, rows)` →
  `_needs_backfill(sheet_key, cleaned)` 로 시그니처 변경.

### 변경 4-B: 재추출 노이즈 억제
- `_relevant_pages()` 선별 조건에 "strong 키워드 1개 이상 포함"을 추가:
  `_score_page_for_sheet(page, sheet_key) >= min_score` **and** 해당 시트
  `_ROUTE_CONFIGS[sheet_key]["strong"]` 중 1개 이상이 페이지 텍스트+표에 존재.
  (min_score=2는 weak 2개만으로도 도달 가능해 무관 페이지가 섞이는 것을 막는다.)
- GapFill이 추가하는 모든 행에 `"보완출처": "gap_fill"` 마킹 필드를 넣는다.
  organizer cleaner들은 이 필드를 그대로 통과시키고(제거 금지), 엑셀에는 쓰지 않는다
  (EXCEL_HEADERS에 없는 키는 자동으로 안 쓰임). WP6 리포트와 디버깅에 사용.

### 수용 기준
- 테스트 `tests/test_gap_fill_trigger.py`: 부문 3개짜리 emissions_regional → 발동,
  8부문·3개 연도 → 미발동. reduction_targets 2030만 있음 → 발동.
- 발동 사유 문자열이 리포트에 그대로 남는다(예: `"부문 3/8, 연도 1"`).

## WP5. 행 단위 출처 페이지 provenance (P1)

### 목적 (신규 제안 — 가이드라인 §5.1이 직접 요구하는 항목)
사람이 하던 "원문 대조 검증"을 대체하려면 각 행이 **어느 페이지에서 나왔는지**가
필수다. 현재는 배치(여러 페이지 묶음) 단위 호출 후 행 단위 출처가 사라진다.

**가이드라인 근거** (`carbon_guideline.md`) — 이 컬럼 추가는 시트 계약 위반이 아니라
가이드라인 준수도를 높이는 변경이다:
- §5.1 "모든 시트 공통 컬럼": 모든 데이터 시트에 `source_page`, `source_section`,
  `source_text`, `data_status`, `confidence` 등을 붙이는 것을 권장. `출처페이지`는
  이 중 `source_page`의 구현이다.
- §9 처리 절차 8: "근거 로그 작성: 모든 수치와 주요 텍스트에 페이지/표/그림/원문 인용을 남김."
- §11 원칙 2: "모든 값은 원문값·표준화값·근거를 분리한다."
- 선례: `17_보조검수후보`/`18_보조병합로그`에 이미 "근거페이지" 컬럼 존재.
- 주의: `02_지역여건`의 기존 "출처" 컬럼은 통계 출처(`source_name`, 예: GIR)로
  페이지 근거와 별개다. 혼동하지 말고 그대로 두고 `출처페이지`를 따로 추가한다.

향후 확장 여지(이번 범위 아님, 구현하지 말 것): §5.1의 `source_text`(근거문구),
`data_status`(reported/visual_only/conflicting 등 §6.4 코드북), §5.2의
`91_source_evidence` 근거 로그 시트. `출처페이지`가 안정화된 뒤 별도 명세로 다룬다.

### 변경 5-A: 추출 프롬프트에 출처 필드 요구
- `_build_page_text()`가 배치 텍스트에 이미 `=== 페이지 N ===` 마커를 넣는지 확인하고
  (없다면 추가), 각 시트 프롬프트(`_SHEET_CONFIGS[sk]["prompt"]`) 뒤에 공통 지시문을
  덧붙인다(개별 프롬프트 16개를 일일이 수정하지 말고 `_extract_sheet`/`_extract_cluster`에서
  조립 시 1회 삽입):
  `"각 행에 \"출처페이지\" 필드를 추가하고, 그 행의 근거가 된 페이지 번호(=== 페이지 N === 마커 기준)를 정수 또는 정수 배열로 기록하세요. 확실하지 않으면 null."`
- LLM이 안 주거나 잘못 준 경우의 폴백: 배치의 페이지 범위(`page_nums`)를
  `"출처페이지추정"`으로 행에 기록(추출 코드에서 결정론적으로 채움).

### 변경 5-B: organizer/엑셀 반영
- 각 cleaner는 `출처페이지`를 통과시키되 정규화: 정수/정수배열/문자열 → `"12"` 또는
  `"12,13"` 형태의 문자열로 canonical 화. dedup 병합 시 두 행의 출처는 합집합.
- `config.EXCEL_HEADERS`의 16개 데이터 시트 각각에 **맨 마지막 컬럼**으로
  `"출처페이지"` 추가. `PROVENANCE_ENABLED = _env_bool("PROVENANCE_ENABLED", True)`
  플래그를 두고, False면 헤더에서 제외(엑셀 계약을 원복하고 싶을 때용).
  - 구현 주의: EXCEL_HEADERS는 모듈 로드 시 상수이므로, 플래그 처리는
    `utils/excel_writer.py`에서 헤더 리스트를 쓰기 직전에 필터링하는 방식이 안전하다.
- dedup 키에는 절대 포함하지 않는다.

### 수용 기준
- 샘플 배치 mock 응답에 출처페이지가 있으면 엑셀 해당 컬럼에 기록되고,
  없으면 배치 페이지 범위가 `출처페이지` 컬럼에 추정값으로 남는다(값 형식 동일,
  추정 여부는 `19_검증리포트`가 아닌 값 자체로 구분하지 않아도 됨 — 단순 유지).
- `PROVENANCE_ENABLED=0`이면 기존과 완전히 동일한 엑셀이 나온다.
- 테스트: `tests/test_provenance.py`.

## WP6. 검증리포트(19_검증리포트) 확장 (P1)

### 목적 (신규 제안)
수작업 검증을 대체하려면 "무엇이 빠졌고 무엇이 안 맞는지"를 기계가 최대한 지적해야
한다. 기존 `organizer_agent._validate_final_data()`(감축률 재계산, 8부문 커버리지,
2030/2050 존재, 단위 스케일 혼재, 재정 합계 교차검증)를 다음으로 확장한다.
모두 결정론적 Python이어야 한다.

### 추가 점검 항목
1. **교차시트: 감축목표 기준배출량 vs 배출현황**
   `reduction_targets`의 (기준연도, 기준배출량) 총괄 행과 `emissions_regional`의
   같은 연도 합계(부문 "합계" 행이 있으면 그것, 없으면 부문 합산)를 비교.
   상대오차 > 5% → 경고. 단위 스케일이 다르면(천톤 vs 톤) 1000배 보정 시도 후 비교하고,
   보정으로 맞으면 "단위 스케일 차이로 추정" 정보 항목으로만 남긴다.
2. **교차시트: 정량감축량 합 vs 목표감축량**
   `quantitative_reductions`의 목표연도별 예상감축량 합 vs `reduction_targets`의
   같은 연도 목표감축량(총괄). 상대오차 > 10% → 정보(계획서 자체가 안 맞는 경우가
   흔하므로 심각도는 "정보").
3. **빈 시트 원인 분류** (WP2 원장 필요):
   최종 데이터에서 빈 데이터 시트마다 원인을 판정해 1건씩 기록 —
   `라우팅 0페이지`(routed_page_nums에 없음) / `추출 0행`(배치는 성공했으나 행 없음) /
   `호출·파싱 실패`(원장에 실패 있음) / `정제에서 전부 제거`(raw에는 있었으나 cleaned가 빔).
   마지막 케이스를 위해 organize()가 시트별 (raw 행 수 → cleaned 행 수)를 기록하게 한다.
4. **GapFill 기여 요약**: `보완출처=="gap_fill"` 행 수를 시트별 정보 항목으로 기록
   (WP4-B 마킹 사용).
5. **원장 실패 항목**(WP2-D): 시트별 호출실패/파싱실패 배치와 페이지 범위, 심각도 "경고".

### 인터페이스
- `_validate_final_data(cleaned, municipality)` → 시그니처를
  `_validate_final_data(cleaned, municipality, *, ledger=None, raw_counts=None)`로 확장.
  Supervisor → organizer 호출 경로에서 원장을 전달한다
  (`organize(raw_data, ledger=...)` 파라미터 추가, 기본 None이면 관련 점검 생략).

### 수용 기준
- 각 점검 항목별 단위 테스트(`tests/test_validation_report.py`): 정상 데이터 → 0건,
  의도적으로 어긋난 데이터 → 해당 항목 정확히 1건.
- 19_검증리포트는 기존처럼 데이터가 있을 때만 생성(OPTIONAL_EXCEL_SHEETS 유지).

## 부수 수정 (어느 WP에든 편승 가능한 소형 항목)

1. `agents/extractor_agent.py` `_route_pages_by_sheet()`:
   `getattr(config, "ROUTE_DROP_UBIQUITOUS_STRONG", True)` 의 폴백 기본값이 config
   정의(False)와 불일치. **False로 고친다** (config 항목이 사라져도 검증 안 된 샤프닝이
   조용히 켜지지 않도록). `ROUTE_DROP_UBIQUITOUS_WEAK` 폴백도 config와 일치 확인.
2. `_deduplicate_rows`의 in-place 부작용: `seen[key][k] = v` 가 입력 행 dict를 직접
   수정한다. raw_data 재사용(GapFill 후 재정제) 경로에서 원본 오염 가능 —
   병합 시 `dict(row)` 복사 후 수정으로 변경 (WP3에서 함께).
3. `gap_fill_agent.enhance()`의 재정제 경로: Supervisor가 `enhanced_raw is not raw_data`
   로 재정제 여부를 판단하므로, enhance가 "추가 0건이어도 새 dict를 반환"하지 않도록
   현재의 `return updated if self._total_added > 0 else raw_data` 계약을 깨지 말 것
   (WP1/WP2 수정 시 회귀 주의 — 테스트로 고정).
