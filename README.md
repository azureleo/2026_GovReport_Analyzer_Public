# 가이드라인 기반 지자체 탄소중립 계획 정보 추출 시스템

환경부 「지자체 탄소중립 녹색성장 기본계획 수립 및 추진상황 점검 가이드라인」을 기준으로 PDF·HWP·HWPX의 텍스트·표·이미지를 읽어 **16개 업무 시트의 Excel**로 정리하는 연구 프로젝트입니다.

핵심 목표는 **원문 정보를 추출하고, 정리 과정의 정보 손실을 추적하며, 실제 저장 결과를 검증하는 것**입니다. 판독 성공, 업무 데이터 병합, Excel 저장, 사실 정확도를 구분하여 기록합니다.

> 2026년 10월 29일 정리한 공개용 개발 스냅샷입니다. 개발 커밋 `2b5a86a`의 파일을 기준으로 하며, 공개 저장소의 커밋 해시는 달라집니다. 실제 문서에서 누락·단위·배율·오배치 문제가 남아 있어 결과 검토가 필요합니다.

## 처리 구조

```text
원본 PDF / HWP / HWPX
  → 페이지·표·이미지 및 원문 객체 구성
  → 가이드라인을 참고한 시트별 텍스트·표 추출
  → 선택한 저장 OCR의 변경 객체 추가 추출
  → 이미지·그래프 판독 및 근거를 보존하는 결과 병합
  → Organizer의 정리·중복·충돌 처리
  → 선택적 의미 검증
  → Excel 저장
  → 실제 저장 셀 재조회·규칙 검사·선택 골든 대조
  → 감사 파일·실행 상태·LLM 보조 설명 저장

별도 보완 경로
  원문 대조 → 사람이 누락 항목 확인 → 추가 판독 대상 예산 정보 선정
  → 호출·시간 상한을 둔 2차 판독 → 검증 후 기존 결과와 통합 → 새 Excel

실패 배치 복구 경로
  기존 Excel·성공 응답 고정 → 저장된 감축목표 재정리
  → 명시적으로 선택한 실패 배치만 복구 → 기존 셀 보존·새 셀 저장 확인
```

2차 판독과 실패 배치 복구는 서로 다른 실행기입니다. 원문 대조를 활성화하는 것만으로 추가 모델 호출이 자동 시작되지는 않습니다.

## 현재 구현

| 기능 | 현재 동작 | 결과와 범위 |
|---|---|---|
| 시트별 추출 | 관련 페이지를 선별하고 배치 단위로 업무 필드를 추출 | 본문 16시트의 원시 입력 |
| 원문 객체와 출처 | 객체 ID·근거 ID·페이지·원천·계보를 보존 | 업무 행의 추적 열과 감사 파일. 배치 근거가 개별 셀 좌표를 보장하지는 않음 |
| 이미지 판독 | 이미지·렌더링 후보를 선별해 표·그래프 정보를 읽고 병합 | `--no-images`로 제외 가능. 후보 수와 정확도는 별개 |
| 저장 OCR 연결 | 사전 생성 Markdown/TXT/JSONL을 검증하고 변경 객체만 관련 시트에 추가 추출 | OCR 로드·판독·업무 추출·본문 반영 상태를 구분 |
| 보수적 정리·병합 | 범위·시나리오·세부부문·단위 등 사실 구분 기준을 보완 | 동일 사실의 근거를 합치고 충돌은 보존·검토 |
| 감축목표 보존 | 목표범위·기준연도·단위를 구분해 중복 판정 | 서로 다른 범위의 목표 값이 첫 행에 가려지는 손실 보완 |
| 내부 원장 저장 | 격리 원행·충돌·객체 상태 등 내부 기록을 파일로 저장 | run-state OFF에서도 `pipeline_audit.json` 저장 시도 |
| 원문 항목 대조 | 지원 표의 사업·연도·값·단위를 실제 저장 결과와 비교 | 누락 후보·충돌·해석 보류 기록. 전 문서 정확도 채점 아님 |
| 제한적 2차 판독 | 사람이 확인한 예산 누락만 호출·시간 상한 안에서 추가 판독 | 검증 후 새 Excel로 저장. 기존 셀 보존 |
| 예산 분류 보완 | 명시된 절 제목·사업 번호·부문 머리글 등으로 빈 계획구분·부문 연결 | 근거가 모호하거나 충돌하면 보류 |
| 저장 응답 복구 | 성공 응답과 Excel을 고정하고 감축목표 재정리·실패 텍스트 배치 복구 | 원본 입력·배치 지문 확인, 원응답 저장, 반복 호출·중복 추가 방지 |
| 저장 후 품질 검사 | 실제 Excel의 필수 정보·지역·기간·단위·중복·충돌·저장 일치 검사 | JSON·Markdown·셀별 JSONL. 종합 사실 정확도 점수로 환산하지 않음 |
| 선택 골든 대조 | 원문·골든 해시와 승인 상태·평가 범위를 확인한 뒤 채점 | 골든이 없으면 정확도 미평가와 사유 표시 |
| 최종 LLM 검토 | 규칙 검사와 검증 범위를 바탕으로 참고 의견 생성 | 진단용이며 자동 수정 루프가 아님 |

`DirectoryOCRBackend`는 **이미 생성된 OCR 파일을 읽는 로더**입니다. UnlimitedOCR 모델을 직접 실행하지 않습니다. 같은 페이지에 있다는 이유만으로 무관한 객체를 모두 적용하지 않으며, 선택 후보가 없으면 의도치 않은 전체 파일 로드를 막습니다.

객체마다 모델을 호출하는 모드, 과거 Reading A/B 연결 계층, 타깃 보조검수·폐루프·빈칸 보완, 참조 CSV 보강, 텍스트 최적화는 개발 경로별 구현 범위가 다릅니다. 구형 파일이나 설정 이름이 남아 있어도 이 스냅샷의 일반 `main.py`에서 실행된다는 뜻은 아닙니다. 선별·미이식 범위는 [통합 점검 문서](docs/main_v9_integration_report.md)를 참고하세요.

보조 시트는 `16_시각자료목록`, `17_검증리포트`입니다. 기본 출처 열에는 `출처페이지`, `근거ID`, `객체ID`, `추출원천`, `검수상태`, `추출엔진`, `OCR보완여부`, `출처계보`가 있습니다.

이 스냅샷은 과거의 5시트 요약카드 구조나 `90_코드북`·보조검수 후보 시트 구성을 일반 출력으로 설명하지 않습니다. 원문 존재 진단은 감사 JSON에 기록하며, 현재 코드가 마킹 PDF를 항상 생성한다고 안내하지 않습니다.

## 설치와 설정

Python 3.10 이상을 사용하며, 개발 검증은 Python 3.13 환경에서 진행했습니다. 아래 예시는 Windows PowerShell 기준입니다.

```powershell
git clone https://github.com/azureleo/2026_GovReport_Analyzer_Public.git
Set-Location -LiteralPath ".\2026_GovReport_Analyzer_Public"
git switch codex/october-2026-snapshot

py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pip install pytest

if (-not (Test-Path -LiteralPath ".env")) {
    Copy-Item -LiteralPath ".env.example" -Destination ".env"
}
```

아직 원격에 해당 브랜치를 게시하지 않았다면 게시 후 가져와야 합니다.

위 가상환경을 이용한다면 이후 예시의 `py`를 `.\.venv\Scripts\python.exe`로 바꾸어 실행합니다.

`HWP/HWPX` 입력이나 HWP 가이드라인을 사용하려면 Node.js와 프로젝트 의존성이 추가로 필요합니다.

```powershell
npm ci
```

Codex CLI 또는 Claude Code CLI를 이용하려면 해당 도구 설치와 로그인을 별도로 완료해야 합니다. 예시의 `--agent-model`은 해당 계정과 CLI에서 사용할 수 있는 모델명으로 지정하세요.

현재 `.env.example`은 새 기능의 설정 설명을 포함하며 개인 실행 환경 전체를 재현하지 않습니다. 실제 `.env`는 Git에 추가하지 않습니다. 모델·호출 시간 등 실행 조건을 명확히 하려면 다음처럼 직접 지정할 수 있습니다.

```dotenv
LLM_PROVIDER=codex
LOCAL_AGENT_MODEL=gpt-5.6-luna
LOCAL_AGENT_TIMEOUT=900
```

`config.py`의 provider 기본값은 `gemini`이므로 예시 명령은 `--agent codex`를 명시합니다. Gemini API는 별도 API 키가 필요하며, 이 스냅샷의 `--agent`는 `codex/claude/auto/gemini`를 지원합니다. 구형 브랜치의 `--env-file`이나 단계별 모델 설정이 그대로 연결된다고 가정하지 마세요.

## 실행 방법

입력 문서는 별도로 준비합니다. 아래 `문서.pdf`는 예시 이름입니다. 테스트마다 출력 이름을 다르게 지정하면 이전 결과를 보존할 수 있습니다.

```powershell
$runTag = Get-Date -Format "yyyyMMdd_HHmmss_ffffff"

py main.py ".\문서.pdf" `
  --agent codex --agent-model gpt-5.6-luna `
  --output ".\output\전체검증_$runTag.xlsx" `
  --retries 1 --source-coverage audit --evaluation-mode off
```

`--retries 1`은 추출·정리 파이프라인 시도를 한 번으로 설정합니다. 개별 모델 호출의 내부 재시도 횟수와는 별개입니다. `--evaluation-mode off`는 골든 대조만 끄며 저장 후 규칙 검사는 유지합니다.

| 목적 | 옵션 |
|---|---|
| 텍스트 기준선 | `--no-images` |
| 모든 페이지를 추출 후보로 사용 | `--full-scan` — 모든 사실의 추출 성공을 보장하지 않으며 호출량이 늘 수 있음 |
| 이미지 후보 상한 | `--max-images 숫자` — 미지정·0은 상한 없음 |
| 저장 OCR 결과 보완 | `--selective-ocr --ocr-results-dir .\ocr_results` |
| 객체 단위 청킹 | `--object-batching` |
| 입력 문자·표 셀 상한 | `--batch-max-chars 숫자`, `--batch-max-table-cells 숫자` — 0은 제한 없음 |
| 의미 진단·이동 | `--semantic-routing audit` 또는 `--semantic-routing apply` |
| 배치 체크포인트 | `--run-state-dir .\output\실행_state` |
| 동일 지문 성공 배치 재개 | 위 상태 경로와 함께 `--resume` |
| 저장 후 규칙 검사 | `--quality-report on` 또는 `off` |
| 골든 대조 정책 | `--evaluation-mode auto`, `off`, `required` |

선택 기능은 한 번에 모두 켜기보다 기준선과 나누어 비교합니다. 객체 ID 보존과 객체별 추가 호출은 구분해야 합니다. 재개는 원문·지침·설정·구현 지문이 같은 성공 텍스트 배치를 복원하는 경로이며, 코드 변경 뒤 과거 상태를 강제로 재사용하지 않습니다. Vision 전체와 모든 단계의 무호출 재개를 보장하는 옵션도 아닙니다.

## 기존 결과 재사용과 추가 판독

### 원문 대조만 다시 실행

추가 모델 호출 없이 저장된 객체와 Excel을 대조합니다. 같은 실행의 원본 문서·Excel·감사 파일이 필요하며, 새 출력 이름을 지정합니다.

```powershell
$auditTag = Get-Date -Format "yyyyMMdd_HHmmss_ffffff"
py scripts/audit_source_coverage.py `
  --input ".\문서.pdf" `
  --excel ".\output\기준실행.xlsx" `
  --pipeline-audit ".\output\기준실행_pipeline_audit.json" `
  --output-prefix ".\output\재대조_$auditTag"
```

대조 범위는 식별 가능한 사업·과제가 있는 지원 표에 한정됩니다. `missing_candidate`는 자동 규칙으로 대응하지 못한 후보이며, 실제 누락 확정과 다릅니다. 후보 수를 전 문서 정답 분모로 사용하지 않습니다. [범위·분류 기준](docs/source_coverage_audit.md), [V2](docs/source_coverage_rules_v2.md), [V3](docs/source_coverage_rules_v3.md)를 참고하세요.

### 사람이 확인한 예산 정보의 제한적 2차 판독

확정 대상 JSON은 해당 실행의 원문 검토·Excel·감사 파일 해시에 연결됩니다. 다른 실행에 같은 대상 목록을 그대로 합치지 않습니다.

```powershell
# 기본은 계획 검증만 수행. 실제 판독은 --execute에서만 시작.
py scripts/run_second_pass.py --targets ".\confirmed_targets.json" `
  --input ".\문서.pdf" --output-dir ".\output\second_pass_run"
```

기본 상한은 새 판독 4회·300초, 누적 판독 시간은 기준 실행 시간의 20% 이내입니다. 성공 응답은 저장하고 재사용하며, 실패·중단 표를 자동 재호출하지 않습니다. 이 상한은 운영 제한이며 성능 향상 예측치가 아닙니다. [대상 준비·실행·재개](docs/second_pass_runner.md), [예산 분류 연결](docs/second_pass_context.md)을 참고하세요.

### 저장 응답 고정과 실패 배치만 복구

아래 기본 명령은 저장 응답의 감축목표 정리만 재평가합니다. 과거 전체 원시 Vision 결과를 재구성하지 않으며, 기존 Excel을 기준으로 새 사실을 보완합니다.

```powershell
$repairDir = ".\output\saved_recovery_$(Get-Date -Format yyyyMMdd_HHmmss_ffffff)"

py scripts/recover_saved_extractions.py ".\output\기준실행.xlsx" `
  --output-dir "$repairDir"

# 명시적으로 실패 배치만 최대 한 번 호출. 성공 응답과 Vision은 재호출하지 않음.
py scripts/recover_saved_extractions.py ".\output\기준실행.xlsx" `
  --output-dir "$repairDir" --recover-failed --max-calls 1 --timeout 300 `
  --codex-command "$env:APPDATA\npm\codex.cmd"
```

기준 실행의 매니페스트·배치 원장과 원본 PDF가 필요합니다. 모델은 기준 매니페스트에서 읽고 추론 강도를 덮어쓰지 않습니다. 같은 폴더에서 저장 응답을 다시 재평가해도 기존 행이 누적 추가되지 않습니다. 충돌·근거 부족·빈 계획은 보류하며, 일부 숫자만 미확인인 목표 행은 해당 필드를 비우고 원래 응답과 사유를 남깁니다. [입력 조건·출력·반복 실행](docs/saved_extraction_recovery.md)을 참고하세요.

## 평가 기준

| 구분 | 확인하는 내용 | 해석 |
|---|---|---|
| 연결 검증 | 판독 결과가 정리·병합·저장까지 전달되는지 | 모델이 정답을 읽었다는 검증과 구분 |
| 규칙 검사 | 필수 공란·타입·단위·기간·중복·충돌·저장 일치 | 확인된 규칙 위반·의심·미평가를 분리 |
| 원문 대조 | 지원 범위의 명시 항목·숫자·단위가 저장 결과에 있는지 | 원문 표현의 존재만으로 사실 정확도를 승인하지 않음 |
| 골든 대조 | 고정 범위에서 셀 정확도·행 재현율·매칭 정밀도 | 불완전한 골든의 미매칭을 실제 오답으로 확정하지 않음 |
| 최종 LLM 의견 | 확인된 문제와 검토 순서에 대한 보조 설명 | `우수/보통/미흡` 종합 등급을 사실 정확도 점수로 사용하지 않음 |

골든이 없는 지자체도 저장 후 규칙 검사와 원문 대조를 수행할 수 있습니다. 이때 셀 정확도·행 재현율은 미평가 사유와 함께 표시하며 임의 점수를 만들지 않습니다.

기본 `auto`는 원문·골든 해시, 승인 상태, 평가 범위가 맞아야 채점합니다. 서울의 검토 전 개발 골든은 `--allow-draft-evaluation`을 명시해야 사용합니다. 강원·경기 보고서에 서울 골든을 적용하지 않습니다. `off`는 골든 대조만 끄고, `required`도 평가 불가 시 이미 저장한 Excel을 보존합니다.

과거 고정 계약의 v1 점수와 순서·모호성·단위 대응을 보강한 v2 점수는 구분합니다. 채점 계약이 다르면 동일 수치로 직접 비교하지 않습니다. 자세한 기준은 [저장 후 품질 검사와 골든 평가](docs/saved_quality_evaluation.md)에 정리했습니다.

- **제한적 보완:** 실제 누락으로 확인한 예산 정보만 호출·시간 상한 내에서 추가 판독하고 기존 값과 함께 검증했습니다.
- **평가 정리:** 저장 성공·규칙 검사·원문 확인·골든 정확도를 분리해 내부 점수만으로 품질을 판단하지 않도록 했습니다.
- **응답 고정 복구:** 모델 응답 변동과 정리·병합 문제를 나누어 점검하고, 성공 기록을 유지하며 실패 범위만 복구하도록 보완했습니다.

### 축소하거나 별도 실험으로 남긴 사항

- 객체마다 모델을 호출하는 방식은 긴 문서에서 호출 수·처리 시간이 늘어 별도 선택 기능으로 유지했습니다.
- 모델 변경만으로 정확도가 개선된다고 가정하지 않고 현재 프로젝트의 실제 반환 범위·저장 보존을 비교했습니다.
- 타깃 보조검수·폐루프·참조 자료 보강·이전 Reading/텍스트 최적화는 현재 코드에 모두 통합됐다고 설명하지 않습니다.
- 문헌에서 검토한 방법론은 적용 후보이며, 논문의 모델·학습 방식을 그대로 도입했거나 동일 효과를 검증한 것으로 기록하지 않습니다.

## 검증 방법

외부 모델 경계만 fixture/mock으로 바꾸고 실제 파싱·정리·병합·원문 대조·Excel 저장을 통과하는 테스트를 우선합니다. Python 의존성과 `pytest`를 설치한 뒤 실행합니다.

```powershell
$testTag = Get-Date -Format "yyyyMMdd_HHmmss_ffffff"
py -B -m pytest `
  tests/test_saved_extraction_recovery.py `
  tests/test_extraction_foundation.py `
  tests/test_main_v9_end_to_end.py `
  tests/test_main_v9_forecast_contract.py `
  tests/test_v9_ocr_loader_contract.py `
  tests/test_source_coverage.py tests/test_source_coverage_v2.py tests/test_source_coverage_v3.py `
  tests/test_second_pass.py tests/test_second_pass_context.py `
  tests/test_saved_quality.py tests/test_saved_quality_pipeline.py tests/test_final_review.py `
  -q --basetemp ".\.cache\pytest_public_$testTag"
```

개인 실행 설정이 테스트에 섞이지 않도록 별도 터미널에서 `$env:PYTHON_DOTENV_DISABLED = "1"`을 설정할 수 있습니다. 일반 실행에서 `.env`를 다시 읽으려면 `Remove-Item Env:PYTHON_DOTENV_DISABLED -ErrorAction SilentlyContinue`로 해제합니다.

개발본에서는 관련 테스트를 나누어 실행해 신규 복구 테스트 10개를 포함한 중복 제외 333개 통과를 확인했습니다. 공개용으로 선별한 사본에서 모든 테스트가 통과했다는 의미는 아닙니다.

이번 README 정리 시 공개용 사본에서 복구 테스트 10개와 아래 합성 데이터 데모의 저장 연결을 별도로 확인했습니다. 실제 모델 호출이나 새로운 전체 문서 정확도 실측은 수행하지 않았습니다.

전체 테스트에는 다음 기존 문제가 남아 있습니다.

- `test_llm_client.py`의 3건: Windows의 공백을 포함한 가짜 CLI 경로 처리로 실패.
- `test_image_agent_fallback.py`의 1건: 구형 시트명 `energy`를 기대해 현재의 `regional_conditions`와 불일치.
- `test_supervisor_summary_context.py`: 현재 코드에 없는 구형 요약 함수의 import로 테스트 수집 오류.

앞의 4건 실패는 수정 전 코드에서도 재현했습니다. 전체 테스트 통과를 선언하지 않고, 확인한 범위와 남은 과제를 구분해 기록합니다.

추가 모델 호출 없이 저장까지 확인하는 합성 데이터 데모도 제공합니다.

```powershell
$demoTag = Get-Date -Format "yyyyMMdd_HHmmss_ffffff"
py scripts/offline_connection_demo.py --output-dir ".\output\offline_demo_$demoTag"
```

`run_ocr_fixture_demo.py`처럼 별도 실험 패키지가 필요한 스크립트는 해당 의존 자료가 없으면 단독 실행할 수 없습니다. 도구 코드의 존재와 과거 실험 전체의 즉시 재현 가능성을 구분합니다.

## 공개 자료와 재현 범위

공개 대상은 코드·설정 예시·가이드라인 Markdown·구현 설명·테스트입니다. 기존 `data/`에 평가·참조 자산이 있어도 현재의 등록·승인·해시 조건을 만족하는지 확인해야 합니다.

다음 자료는 이번 코드 스냅샷에 새로 포함하지 않습니다.

- 실제 `.env`, API 키, CLI 로그인 정보, 개발 저장소의 `.git` 이력.
- 원본 지자체 PDF·발췌 PDF, 전체 실행 Excel, 마킹 PDF, 로그, 원시 모델 응답, 체크포인트.
- `output/`, `tmp/`, 가상환경, 캐시와 개인 분석 파일.
- 비공개 원문 검토·확정 대상 목록 등 개별 실험의 전체 입력.

개발 문서의 출력 폴더·실행명·개인 PC 경로는 실험 기록을 식별하기 위한 정보이며 공개 다운로드 링크가 아닐 수 있습니다. 원본·검토 목록·응답 파일이 없으면 해당 과거 실험을 그대로 재현할 수 없습니다.

## 향후 보완 계획

- **평가 기준 정리:** 규칙 검사·원문 확인·추출 정확도를 구분하고 셀 정확도와 행 재현율의 범위·기준을 명확히 합니다.
- **기능 간소화:** 정확도 개선 효과가 작거나 호출 부담이 큰 기능을 삭제·축소하고 실행 구조를 정리합니다.
- **추출·연결 방식 개선:** 현재까지의 검증 결과를 바탕으로 목표범위·연도·단위에 따른 정보 구분과 원문 근거 연결, 여러 줄 머리글과 행·열 관계 전달을 개선합니다.
- **추가 검증:** 다른 지자체 문서에도 적용하고, 독립 원문 표본에서 누락·단위·배율·오배치와 실행시간을 확인합니다.
