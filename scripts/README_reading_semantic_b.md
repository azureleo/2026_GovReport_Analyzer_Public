## 구현 범위

- 명시 대상시트는 지역여건 키워드 분기보다 우선한다. 대상시트가 없는 행만 A 경로를 유지한다.
- `utils/reading_semantic_binding.py`의 ROLES는 허용된 역할→필드 쌍이다. 값역할 이름을 측정 숫자로 복사하지 않는다.
- 메타데이터 ID, 관계 ID, 관계 양끝, 객체, 근거·적용범위를 점검한다. 문자열 근거는 추론 없이 보존한다. 문서상 근거가 실제로 맞는지는 별도 원문 평가 대상이다.
- 같은 객체의 명시 관계만 빈 필드를 보완한다. 다른 객체의 관계는 이미 있는 필드와 값이 정확히 같은 경우에만 확인 근거로 사용한다. 다른 객체에서 빈 필드를 채우지는 않는다.
- 기존 `부문`, `세부부문`을 ` > `로 이은 값이 메타데이터 전체 경로와 정확히 같으면 두 필드를 확인한다. 자유 텍스트를 분리하거나 새 계층을 추론하지 않는다.
- 승인된 연결끼리 또는 기존 업무필드와 값이 다르면 덮어쓰지 않고 행을 보류한다. 미지원 역할은 별도 보존한다. `집계역할=합계`를 `계획구분`에 대입하지 않는다.
- 원시 숫자와 실제 측정 필드의 숫자·단위를 비교한다. 연도 숫자가 우연히 같다는 이유로 측정값 보존으로 인정하지 않는다. CO2/CO2eq 변경, 단위 환산, 누락 숫자 생성은 금지한다.
- 명시 정량 계약은 지역여건·배출현황 2종·배출전망·재정·연차이행·정량감축 7종에 한정한다. 다른 명시 계약은 보류한다. 따라서 일부 A 통과 행도 B에서는 보류될 수 있다.
- 동일 업무 식별정보를 가진 여러 후보는 후단에서 임의 선택되지 않도록 보류한다. 전체 후단 중복 규칙과의 동등성을 보장하지 않으므로 저장 검증도 필요하다.

```powershell
$bDir = ".\output\reading_semantic_b_$runTag"

py scripts/run_reading_semantic_b.py "$readingDir\raw_reading.json" --metadata "$readingDir\metadata_links.json" --schema "$readingDir\backend_schema.json" --record-ids data/reading_compatibility_smoke_ids.json --output-dir "$bDir"

py scripts/verify_reading_excel_a.py --stage-a-dir "$bDir" --output-dir "$excelDir" --offline-dotenv-shim
```

두 번째 명령의 이름과 `--stage-a-dir`, 파일명 `mapped_reading_a.xlsx`는 A의 기존 검증기를 변경하지 않고 재사용하기 때문에 그대로다. 입력은 B 후보다.
`--offline-dotenv-shim`은 환경파일을 읽지 않는 격리 테스트용 옵션이다.
첫 명령이 실패하면 두 번째 명령을 실행하지 않는다. Excel 검증 종료 코드 2는 저장되었지만 차이/경고가 있다는 뜻이며 0만 완전 무차이 통과다.
전체 후보 비교는 첫 명령의 `--record-ids data/reading_compatibility_smoke_ids.json`을 빼고 새 출력 폴더로 실행한다.

## 산출물

- `candidate_validation.json`: 후보, 필드별 원본 ID, 연결 로그, 보류 사유. binding_log의 confirmed/filled는 후보 단계 판정이며 candidate_accepted와 저장 검증까지 함께 확인한다.
- `compatible_reading_b.json`, `metadata_links.json`: 별도 호환 입력·전체 관계 보존본.
- `compatibility_report.json`: A 변환 내역, 입력·코드 SHA-256.
- `comparison_a_b.json`: 동일 입력 A/B 획득·탈락 ID, 재실행 일치 여부.
- Excel 검증 폴더의 `backend_output.json`, `cell_validation.json`, `execution_manifest.json`: 실제 후단 결과·셀 좌표·변경 기록.
